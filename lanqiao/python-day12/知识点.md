# Day 12 知识点：递归与分治（递归三要素 / 斐波那契 / 汉诺塔 / 快速幂）

> 一句话：**递归 = 把"大问题"说成"同一个小一号的问题"，再加一个不再往下问的出口。**
> 分治 = 递归的"正经用法"：**把问题对半切开，两边各自解决，再把结果合起来。**
>
> 今天的题：6 题基础 + 1 题复习 + 3 道蓝桥风格真题，全部带**真跑出来的样例**。

## 0. 先看一个"循环写不出来"的场景

汉诺塔：3 根柱子 A B C，A 上有 5 个盘子（大的在下），要全部搬到 C，规则：

1. 一次只能搬**一个**盘子
2. 大盘**永远不能**压在小盘上面
3. 只能从柱子**顶上**拿

用循环写？你会卡住——因为你**根本不知道该先搬哪一个**。
但用递归，三句话就完了：

```
要把 5 个盘子从 A 搬到 C：
  ① 先把上面 4 个从 A 搬到 B（借 C 当中转）
  ② 把最大的那个从 A 搬到 C
  ③ 再把 4 个从 B 搬到 C（借 A 当中转）
```

"把 4 个从 A 搬到 B"和原问题是**同一种问题**，只是规模小了一号 → 这就是递归。

## 1. 递归三要素（缺一个就写不出来）

| 要素 | 叫什么 | 一句话 | 写错会怎样 |
|---|---|---|---|
| ① | **出口**（终止条件） | 规模小到什么程度**直接给答案**，不再往下问 | 没有出口 → `RecursionError`（栈溢出） |
| ② | **缩小**（递推关系） | 每次调用自己时，问题必须**真的变小** | 没变小 → 无限递归，同样栈溢出 |
| ③ | **回归**（接住返回值） | 小一号的答案拿到手后，**怎么拼成**大问题的答案 | 忘 `return` → 函数返回 `None`，后面全崩 |

### 1.1 模板：递归求和 `1+2+...+n`

```python
def f(n):
    if n == 1:          # ① 出口：n=1 时答案是 1，不用再问
        return 1
    return n + f(n - 1) # ② 缩小（n → n-1）  ③ 回归（把 n 加上去）

print(f(100))  # 5050
```

把 `f(3)` 展开看，就是**先一路往下问，再一路往上还**：

```
f(3) = 3 + f(2)
           f(2) = 2 + f(1)
                      f(1) = 1        ← 出口，开始往回归
           f(2) = 2 + 1 = 3
f(3) = 3 + 3 = 6
```

> ⚠️ 新手最常写的两个错：
> ```python
> def f(n):
>     if n == 1:
>         return 1
>     n + f(n - 1)      # ❌ 忘记 return → f(3) 返回 None
> ```
> ```python
> def f(n):
>     return n + f(n - 1)   # ❌ 没有出口 → RecursionError
> ```

### 1.2 生活类比

- **查字典**：查"递归"→ 解释里写着"参见『递归』"→ 你会一直查下去（没出口）。
- **剥洋葱**：剥一层（缩小），剥到没皮了（出口），再把每层皮摆回去（回归）。
- **问路**："到火车站怎么走？"→"往前走 100 米再问一个人"（缩小）→ 直到有人说"就在这"（出口）。

## 2. 递归在内存里长什么样（为什么会有"深度限制"）

每次调用自己，Python 都会在**调用栈**上压一帧（栈帧 = 这次调用的局部变量 + 返回到哪一行）。`f(3)` 运行时栈是这样的：

```
┌─────────────┐
│ f(1)  n=1   │ ← 最后进去，最先出来
├─────────────┤
│ f(2)  n=2   │
├─────────────┤
│ f(3)  n=3   │ ← 最先进去，最后出来
├─────────────┤
│ 主程序       │
└─────────────┘
```

- **后进先出**（LIFO）→ 所以递归天然是"先往下问到底，再一路往上还"。
- 栈是有上限的：**Python 默认约 1000 层**，超过就报错：

```python
f(5000)   # RecursionError: maximum recursion depth exceeded
```

```python
import sys
print(sys.getrecursionlimit())   # 1000（默认值）
sys.setrecursionlimit(10000)     # 手动放宽（蓝桥机考里可以这么干，但别设太大，会真的把内存吃光）
```

> ⭐ **蓝桥机考建议**：递归深度一般不会超过几千；如果 n 会到 1e5 级别，**别硬递归**，改成循环/递推。
> 今天的题 1 深度最多 500，题 3 最多 10，都安全。

### 2.1 递归 vs 循环

| | 递归 | 循环 |
|---|---|---|
| 代码像不像"人的思路" | ✅ 像（尤其树、分治、回溯） | ❌ 要自己维护下标/状态 |
| 速度 | 慢一点（每层要建栈帧） | 快 |
| 内存 | 占栈（深度大就爆） | 只占几个变量 |
| 什么时候用 | **结构本身是递归的**（树、分治、汉诺塔、排列组合） | 简单累加、遍历 |

## 3. 斐波那契：递归的"反面教材"

$F(1)=1,\ F(2)=1,\ F(n)=F(n-1)+F(n-2)$

照着公式写递归，一行就完事：

```python
def fib(n):
    if n <= 2:
        return 1
    return fib(n - 1) + fib(n - 2)
```

**但它在 n=40 时就要跑十几秒，n=100 时你孙子都等不到。** 为什么？看 `fib(5)` 的调用树：

```
                fib(5)
          ┌───────┴───────┐
        fib(4)          fib(3)
      ┌───┴───┐       ┌───┴───┐
   fib(3)   fib(2)  fib(2)  fib(1)
   ┌──┴──┐
fib(2) fib(1)
```

`fib(3)` 被算了 **2 次**、`fib(2)` 被算了 **3 次**……越往下重复越多，总次数 ≈ **2ⁿ/√5**（指数级）。
这叫**重叠子问题**——**同一个问题被反复求解**。

### 3.1 记忆化（memo）：算过的记在小本本上

```python
memo = {}           # 小本本：n → fib(n)

def fib(n):
    if n <= 2:
        return 1
    if n in memo:           # 查过就直接抄答案
        return memo[n]
    memo[n] = fib(n - 1) + fib(n - 2)   # 算完先记本子，再返回
    return memo[n]
```

或者用标准库自带的"自动记忆化"：

```python
from functools import lru_cache   # 标准库的装饰器：自动帮你做"记小本本"这件事

@lru_cache(maxsize=None)          # 加在函数上一行，函数返回过的参数组合会被缓存下来
def fib(n):
    if n <= 2:
        return 1
    return fib(n - 1) + fib(n - 2)
```

| 写法 | 时间复杂度 | n=90 能不能跑完 |
|---|---|---|
| 朴素递归 | **O(2ⁿ)** | ❌ 跑不完 |
| 递归 + 记忆化 | O(n) | ✅ 瞬间 |
| 递推（自底向上 for） | O(n) | ✅ 瞬间 |

> 📌 **递推版**（以后 DP 的基础，先混个眼熟）：
> ```python
> a, b = 1, 1
> for _ in range(n - 1):
>     a, b = b, a + b
> print(a)
> ```
> ⭐ 判断标准：**"同一个子问题会不会被问很多次"**——会，就上记忆化。

## 4. 汉诺塔：递归的"标准答案"

设 `hanoi(n, src, tmp, dst)` = 把 n 个盘子从 `src` 搬到 `dst`，`tmp` 当中转。

```python
def hanoi(n, src, tmp, dst, moves):
    if n == 1:                      # ① 出口：只剩一个，直接搬
        moves.append(src + '->' + dst)
        return
    hanoi(n - 1, src, dst, tmp, moves)   # ② 先把上面 n-1 个搬到中转柱（借目标柱）
    moves.append(src + '->' + dst)       # ③ 把最大的那个搬到目标柱
    hanoi(n - 1, tmp, src, dst, moves)   # ④ 再把 n-1 个从中转柱搬到目标柱（借源柱）
```

**参数顺序最容易错的地方**：第 ② 步里 `tmp` 和 `dst` 换了位置（因为此时"目标"是 `tmp`），
第 ④ 步里 `src` 和 `tmp` 换了位置。**写之前先把三个柱子的"角色"说清楚**。

### 4.1 为什么是 2ⁿ − 1 步

设 `T(n)` = 搬 n 个需要的步数：

```
T(1) = 1
T(n) = T(n-1) + 1 + T(n-1) = 2·T(n-1) + 1
```

展开：`T(n) = 2ⁿ - 1`。n=3 → 7 步，n=10 → 1023 步，n=64 → 1.8×10¹⁹ 步（传说中的世界末日）。

> 顺带一句：**"最小盘永远在 A→C、A→B、C→B… 之间循环"** 这个规律也能做，但别背，
> 用递归写 3 行就完事了，考试时少一个记错的机会。

## 5. 分治：递归的"正经用法"

### 5.1 分治三步（背下来）

| 步骤 | 干什么 | 归并排序里对应 |
|---|---|---|
| **分**（Divide） | 把大问题切成**几个规模更小的同类问题** | 数组对半切 |
| **治**（Conquer） | 递归解决这些小问题（小到可以直接答） | 只剩 1 个元素 → 天然有序 |
| **合**（Combine） | 把小答案**合并**成大答案 | 两个有序数组合并成一个 |

> 关键前提：**合并的代价不能太高**。归并排序能到 O(n log n)，就是因为"合"只要 O(n)。

### 5.2 归并排序全过程

数组 `[5, 2, 9, 1]`：

```
分：  [5, 2, 9, 1]
      /          \
   [5, 2]       [9, 1]
   /    \       /    \
 [5]   [2]    [9]   [1]     ← 只剩 1 个 = 天然有序（出口）
   \    /       \    /
  [2, 5]        [1, 9]      ← 合并
      \          /
     [1, 2, 5, 9]           ← 再合并
```

合并两个**已有序**的数组，只要两个指针从头往后比，谁小拿谁：

```python
def merge(left, right):
    out = []
    i = j = 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:     # <= 而不是 < ：相等时先拿左边，排序才"稳定"
            out.append(left[i]); i += 1
        else:
            out.append(right[j]); j += 1
    out.extend(left[i:])            # 谁先走完，另一个剩下的直接接上（剩下的本来就有序）
    out.extend(right[j:])
    return out


def merge_sort(a):
    if len(a) <= 1:                 # ① 出口
        return a
    mid = len(a) // 2
    left = merge_sort(a[:mid])      # ② 分 + 治
    right = merge_sort(a[mid:])
    return merge(left, right)       # ③ 合
```

### 5.3 为什么是 O(n log n)

- **切了多少层**：每次对半 → `log₂n` 层（n=1e5 时约 17 层）
- **每层总共干多少活**：所有小块加起来还是 n 个元素 → O(n)
- 相乘：**O(n log n)**

对比：冒泡/选择/插入排序是 O(n²)，n=1e5 时是 1e10 次操作（超时），归并约 1.7e6 次（0.3 秒）。

> ⚠️ 归并排序的代价：**要多开 O(n) 的空间**（临时数组）。冒泡是原地排序但慢。
> 蓝桥题 n ≤ 2e5 时，归并排序完全够用。

## 6. 快速幂（分治的最短模板，必须背）

**问题**：求 $a^b \bmod p$，其中 b 可能到 10¹⁸。

循环乘 b 次？b=10¹⁸ 天荒地老。注意到：

$$a^{b} = \begin{cases} (a^{b/2})^2 & b \text{ 是偶数}\\ (a^{\lfloor b/2 \rfloor})^2 \cdot a & b \text{ 是奇数}\end{cases}$$

每算一次 b 就减半 → **O(log b)**，b=10¹⁸ 只要约 60 次。

### 6.1 递归版

```python
def qpow(a, b, p):
    if b == 0:              # ① 出口：任何数的 0 次方都是 1
        return 1 % p        # 注意 p=1 时答案必须是 0（1 % 1 = 0）
    half = qpow(a, b // 2, p)     # ② 先算一半（这就是"分"）
    if b % 2 == 0:
        return half * half % p            # ③ 合
    return half * half % p * a % p
```

### 6.2 迭代版（更快一点点，蓝桥常用）

```python
def qpow(a, b, p):
    res = 1 % p
    a %= p
    while b:
        if b & 1:            # b 的二进制末位是 1 → 这一位要乘进去
            res = res * a % p
        a = a * a % p        # a 变成 a²、a⁴、a⁸……
        b >>= 1              # b 右移一位 = b // 2
    return res
```

### 6.3 取模三条规则（题里到处用）

| 规则 | 说明 |
|---|---|
| `(x + y) % p == (x % p + y % p) % p` | 加法可以随时取模 |
| `(x * y) % p == (x % p * y % p) % p` | **乘法可以随时取模**（快速幂靠这条） |
| `(x - y) % p` | Python 里负数取模结果是正的，放心用 |

> ⚠️ 两条纪律：
> 1. **每一步乘完就 `% p`**，别等最后——不然中间数会大到几万位。
> 2. `b = 0` 时答案是 `1 % p`，不是 `1`（p=1 时 1%1=0）。这种边界蓝桥爱考。

## 7. 递归枚举（回溯）：全排列

求 `1..n` 的所有排列。思路：一位一位地"试"，试完要**退回去**：

```python
n = 3
used = [False] * (n + 1)   # used[i] = 数字 i 是不是已经在当前排列里了
path = []                  # 当前正在拼的排列
res = []

def dfs():
    if len(path) == n:                 # ① 出口：拼满了
        res.append(' '.join(map(str, path)))
        return
    for i in range(1, n + 1):          # 从小到大试，天然就是字典序
        if used[i]:
            continue
        used[i] = True                 # 选 i
        path.append(i)
        dfs()                          # ② 往下一层
        path.pop()                     # ③ 撤销：把 i 拿回来
        used[i] = False

dfs()
```

`n=3` 的搜索树（第一层 3 个分支，每个分支再 2 个……）：

```
            ()
       ┌─────┼─────┐
       1     2     3
      / \   / \   / \
     2   3 1   3 1   2
     |   | |   | |   |
     3   2 3   1 1   2
```

**回溯的命门就是"撤销"**：`path.pop()` 和 `used[i] = False` 少写一个，
后面所有分支都会带着脏状态跑，输出会少很多行（而且很难查）。

## 8. 递归的六种"死法"（错题本重点）

| # | 症状 | 原因 | 修法 |
|---|---|---|---|
| 1 | `RecursionError` | 没有出口，或出口条件永远不满足 | 先写 `if 最小规模: return 答案` |
| 2 | 返回 `None`，后面 `TypeError` | 忘写 `return` | 每个分支都要 return |
| 3 | 跑得极慢（n=40 就卡） | 重复计算（斐波那契式） | 记忆化 `lru_cache` / 递推 |
| 4 | 结果比正确答案大很多 | 全局变量在每层都被累加 | 用返回值，别用全局累加 |
| 5 | 全排列/组合少了行 | 回溯忘记撤销 | `pop()` + 复位 `used` |
| 6 | n=1e5 时内存爆/超时 | 递归深度太大，或每层做了 O(n) 的切片和 `in` | 改迭代、传下标 `(l, r)` 不传切片 |

> 第 6 条特别说明：`a[:mid]` 切片会**复制**一份数组，总代价 O(n log n) 还能接受；
> 但如果写成 `if x in left`（O(n) 查找）塞进循环里，立马退化成 O(n²)。

## 9. 蓝桥实战：看到关键词就选武器

| 题目长什么样 | 用什么 |
|---|---|
| "把 n 个盘子/圆盘搬来搬去" | 汉诺塔递归（三步拆解） |
| "求第 n 项 / 走楼梯方案数 / 分割方案数" | 递归 + 记忆化（或递推） |
| "求 a 的 b 次方 / 大指数取模" | 快速幂 |
| "把数组排序 / 数逆序对 / 求最大子段和" | 分治（归并排序那一套） |
| "输出所有方案 / 所有排列组合" | 回溯（选 → 递归 → 撤销） |
| "树/二叉树" | 递归（左子树 + 右子树 + 自己） |
| 递归深度 > 5000 | 先想**能不能改递推**，不行再 `setrecursionlimit` |

**考场纪律三条**：

1. **先写出口，再写递归体**（顺序反了十有八九忘出口）
2. **递归函数只通过参数和返回值交流**，别乱用全局变量（除非是 `res` 这种"收集答案"的容器）
3. 写完立刻手推 **n=1、n=2** 两个最小用例，比对着样例调快得多

## 11. 自测习惯（每道题都做一遍）

1. **先手推 n=1**：出口对不对？
2. **再手推 n=2**：缩小和回归对不对？
3. **跑题目给的样例**：格式对不对（多行/空格/换行）？
4. **跑大数据**：n=2e5 时 1~2 秒能不能过？
5. **故意造边界**：全负数、全相同、b=0、n=1

> 记不住就记一句话：**递归 = 出口 + 变小 + 拼回去；分治 = 切开 + 各自做 + 合并；回溯 = 选 + 递归 + 撤销。**
