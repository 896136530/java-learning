# Day 11 知识点：双指针（左右指针 / 快慢指针 / 滑动窗口入门）

> 前提：Day10 前缀和与差分过关了。
> **今天换一把更"活"的武器**——前缀和是"先算好一张表"，双指针是"**两个下标一起走**"。
> 前者的表是死的，后者的两个下标是**动态**的：一个负责探路，一个负责收尾。
>
> 一句话：**双指针把"枚举所有区间"的 O(n²)，压成"每个元素只被走过常数次"的 O(n)。**
> 这是蓝桥性价比最高的一招——**90% 的"最长/最短子数组""两数之和""去重"题，都是它。**

---

## 0. 先看一个"暴力会超时"的场景

题目：给一个长度为 10 万的数组，求"**和不超过 S 的最长连续子数组**"（数组全是正数）。

**暴力写法**（你目前会这么写）：

```python
best = 0
for i in range(n):              # 枚举左端点
    s = 0
    for j in range(i, n):       # 枚举右端点
        s += a[j]
        if s <= S:
            best = max(best, j - i + 1)
```

**复杂度**：两层循环 → **O(n²)** → 10 万 × 10 万 = **10^10 次** → **100 秒以上** → 超时。

**有人会说：我用 Day10 的前缀和啊！**

```python
for i in range(n):
    for j in range(i, n):       # ⚠️ 还是要枚举两个端点
        if pre[j+1] - pre[i] <= S:
            best = max(best, j - i + 1)
```

> ⭐ **前缀和只把"求一个区间和"降到 O(1)，它没法帮你"少枚举几个区间"。**
> 区间有 n² 个，前缀和让每个区间算得快，但**数量还是 n² 个**。
> **要靠双指针把"枚举的区间个数"本身降下来。**

**双指针的写法**（右指针一直往右走，左指针只在必要时往右走）：

```python
l = 0
cur = 0
best = 0
for r in range(n):
    cur += a[r]                 # 右指针进一个
    while cur > S:              # 超了就收缩
        cur -= a[l]
        l += 1
    best = max(best, r - l + 1)
```

**复杂度**：`r` 走 n 步，`l` 也一共只走 n 步 → **O(n)** → 10 万次运算 → **0.02 秒**。

> ⭐ **关键洞察**：`l` 从来不回退。虽然看起来是两层循环，但 `l` 一生只增加 n 次，
> 所以总的移动次数是 `2n`，不是 `n²`。**"看似两层循环，实际还是 O(n)"** —— 双指针的精髓。

## 1. 双指针的三个"形态"（今天的目录）

| 形态 | 两个指针怎么动 | 典型场景 |
|---|---|---|
| **左右指针**（对撞） | 一个在头往右，一个在尾往左，**相遇就结束** | 两数之和、回文、反转、盛水容器 |
| **快慢指针**（同向） | 都从左往右，一个走得快一个走得慢 | 数组去重、找中点、判环、找重复数 |
| **滑动窗口** | 右指针扩张、左指针收缩，**维护一个区间** | 最长/最短子数组、定长窗口最大和 |

> 💡 共同点：**两个指针都只往一个方向走，从不回头** —— 这是 O(n) 的来源。
> 一旦你的指针需要回退（比如 r 每次都要重置 l），那就退化回 O(n²) 了。

## 2. 左右指针（对撞双指针）

### 2.1 模板代码（背下来）

```python
l, r = 0, n - 1
while l < r:                    # ⚠️ 是 l < r，不是 l <= r
    # 根据 a[l] 和 a[r] 的关系决定谁动
    if 满足条件:
        ...
        l += 1                  # 找到了通常两边都收
        r -= 1
    elif 偏小了:
        l += 1                  # 左边增大
    else:
        r -= 1                  # 右边减小
```

> ⚠️ **`while l < r` vs `while l <= r`**：
> `l < r` 表示"两个不同的位置"，`l <= r` 会取到同一个位置（单个元素自己配自己）。
> 两数之和、盛水容器必须用 `l < r`；判断回文奇数长度时中间那个元素不用比，也是 `l < r`。

### 2.2 为什么可以放心移动？（以"有序数组两数之和"为例）

题目：升序数组 `a`，找两个**不同位置**的数，和为 `target`。

```
a = [1, 2, 4, 7, 11],  target = 9
     ↑              ↑
     l              r

a[l] + a[r] = 1 + 11 = 12 > 9
```

**现在该动谁？答案是 `r -= 1`（右边往左走）。为什么？**

```
如果保留 r = 11：a[l] + a[r] = 1 + 11 = 12 已经 > 9
那么 a[l] 换成任何"更靠左的数"（本例子，l 只能动，但）
关键推理：既然 a[l] 已经是最小的了（答案只能在 [l, r] 里找），
         1 和 11 都超了，那 1 和"比 11 小"的才有希望 → 所以让 r 变小。
         反过来：11 和"比 1 大"的只会更大 → 所以 11 可以永久淘汰 ✅
```

**一句话记法**：

```
a[l] + a[r] > target  →  r -= 1   （和太大了，把大的那边减小）
a[l] + a[r] < target  →  l += 1   （和太小了，把小的那边增大）
```

> ⭐ **每次比较都能"永久淘汰"掉一个元素** —— 这就是 O(n) 的来源。
> 因为数组**有序**，"a[r] 没人要"这个结论才能立刻下；**乱序数组请先排序**。

**验证**（`a = [1,2,4,7,11]`, `target = 9`，下标 0 起）：

```
l=0,r=4: 1+11=12>9 → r=3
l=0,r=3: 1+7=8<9   → l=1
l=1,r=3: 2+7=9 ✅  → 答案是下标 1 和 3（题目按 1 开始数就是 2 和 4）
```

### 2.3 回文判断：左右指针的"对称"版本

```python
i, j = 0, len(s) - 1
while i < j:
    if s[i] != s[j]:
        print("NO")             # 一发现不一样就可以结束了
        break
    i += 1
    j -= 1
else:
    print("YES")
```

> ⚠️ **不要写 `s == s[::-1]`**。它虽然也是 O(n)，但**多开了 n 个字符的内存**，
> 而且**遇到第一个不同不会提前停**（回文题常常故意给一个超长串，只在前几个字符就不匹配）。
> 双指针遇到不同**立刻停**，这是它的优势。

## 3. 盛水容器：左右指针 + 贪心

题目：给一排线的高度 `h[i]`，选两条线 `i < j`，装水量 = `min(h[i], h[j]) * (j - i)`，求最大值。

**为什么从最宽的开始，然后移动"短的那边"？**

```
     h[l]                                   h[r]
      │                                      │
      │          水                          │
      │▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓│
      └──────────────────────────────────────┘
      l                                      r
            宽度 = r - l （最大）
```

**推理**：

```
当前的宽度 (r - l) 已经是最宽的了。
如果移动"长的那边"（假设 h[r] 更高）：
   新的宽度一定变小 （因为 l 或 r 收了一步）
   新的高度 = min(h[l], h[新]) ≤ h[l]  （短的还是 h[l]，或者更短）
   → 宽变小 且 高不变大 → 面积一定不会变大 → 白算了 ❌

如果移动"短的那边"（h[l] 更短）：
   新的宽度一定变小，但新的高度 = min(h[新], h[r]) 有可能变大 ✅
   → 只有移动短板才可能得到更大的面积
```

> ⭐ **口诀：每次移动较短的那根**。（相等时移动哪边都行，不影响答案）

**复杂度**：`l`、`r` 各走 n 步 → **O(n)**。（暴力枚举所有 `(i,j)` 是 O(n²)）

## 4. 快慢指针

### 4.1 有序数组去重（快慢指针模板题）

题目：**原地**删除升序数组里的重复元素，只保留一个。

```
a = [1, 1, 2, 2, 3, 5, 5, 5]

slow = 0 ← 写指针：指向"已经处理好的最后一个有效位置"
fast = 1 ← 读指针：负责扫过整个数组

fast 读到 1：和 a[slow]=1 相同 → 跳过（重复）
fast 读到 2：和 a[slow]=1 不同 → slow+=1（=1），把 2 写到 a[1]
                                  a = [1, 2, 2, 2, 3, 5, 5, 5]
fast 读到 2：和 a[slow]=2 相同 → 跳过
fast 读到 3：不同 → slow=2，写入 3   a = [1, 2, 3, 2, 3, 5, 5, 5]
fast 读到 5：不同 → slow=3，写入 5   a = [1, 2, 3, 5, 3, 5, 5, 5]
fast 读到 5：相同 → 跳过
fast 读到 5：相同 → 跳过

最后 slow = 3 → 有效长度 = slow + 1 = 4，前 4 个是 [1, 2, 3, 5] ✅
```

**模板**：

```python
slow = 0
for fast in range(1, n):
    if a[fast] != a[slow]:      # 发现"新的"元素
        slow += 1
        a[slow] = a[fast]       # 写到前面
k = slow + 1                    # 有效长度
```

> ⭐ **一句话理解**：`fast` 是"**读**"，`slow` 是"**写**"。
> `fast` 每个元素都摸一遍，`slow` 只在发现有效元素时才往前挪。
> **两个指针都只往右走 → O(n)，而且一个额外的数组都不用开。**

### 4.2 快慢指针在数组里"找中点"

链表里的经典操作，**在数组里也能用下标模拟**：

```python
slow = fast = 0
while fast + 1 < n:             # 让 fast 走两步，slow 走一步
    slow += 1
    fast += 2
# 结束时 slow 就是中点（fast 到不了终点时 slow 停在偏左的中点）
```

> 💡 **用途**：判断"中点两侧是否对称"（今天的真题训练里会出现类似思想）、
> 归并排序的分治切分（Day12 会用），以及"快指针先跑 k 步"来求**倒数第 k 个**。

### 4.3 ⭐ Floyd 判圈：把数组下标当"链表指针"来找重复数字

题目：`n+1` 个数，每个都在 `[1, n]`，**有且只有一个数字重复**（其余都恰好出现一次），
要求 **O(n) 时间、O(1) 额外空间** 找出它（不许排序、不许开计数数组、不许用 set）。

**怎么变形成"链表"？** 把**下标**当节点，把 `a[i]` 当 `i` 的"next 指针"：

```
下标：  0   1   2   3   4
a   ：  1   3   4   2   2

0 --a[0]=1--> 1 --a[1]=3--> 3 --a[3]=2--> 2 --a[2]=4--> 4 --a[4]=2--> 回到 2 ♻️
                                                                       ↑
                                                              2 就是"环入口"
```

> ⭐ **为什么一定会成环？** 有 `n+1` 个点、每个点出度为 1，而值域只有 `n` 个数
> → 必然有一个值（下标）被指向两次 → 追着走必然**撞回同一个点** → 成环。
> 而**环的入口，正是那个重复的数字**。

**Floyd 判圈三步（背下来）**：

```python
# 第 1 步：龟兔赛跑，找相遇点
slow = a[0]
fast = a[a[0]]
while slow != fast:             # 速度 1 vs 速度 2
    slow = a[slow]
    fast = a[a[fast]]

# 第 2 步：一个人回到起点
p = 0

# 第 3 步：两人同速前进，相遇处就是环入口 = 重复的数字
while p != slow:
    p = a[p]
    slow = a[slow]
print(p)
```

> ⚠️ **三个最容易错的地方**：
> 1. 起点是 `a[0]` 和 `a[a[0]]`（**不是** 0 和 0，那样第一步就相遇了）
> 2. `fast = a[a[fast]]` 要写**两次取值**（走两步）
> 3. 第 3 步是 `p = 0` 开始（**回到起点 0**，不是回到数组开头元素）

> 💡 这题的思想价值 > 代码价值：**"数组也能当成链表"** 是很多题的关键一步。

## 5. 滑动窗口入门

### 5.1 定长窗口（窗口大小固定 = k）

题目：长度 `k` 的连续子数组的最大和。

**暴力**：每个起点算一次和 → O(n·k)。

**滑动窗口**：窗口向右移一格时，**加进右边一个、减掉左边一个**：

```
a = [2, 1, 5, 1, 3, 2], k = 3

[2 1 5] 1 3 2     和 = 8
 2 [1 5 1] 3 2    和 = 8 - 2 + 1 = 7      ⭐ 只改了两个数
 2 1 [5 1 3] 2    和 = 7 - 1 + 3 = 9
 2 1 5 [1 3 2]    和 = 9 - 5 + 2 = 6
```

```python
cur = sum(a[:k])                # 第一个窗口
best = cur
for i in range(k, n):
    cur += a[i] - a[i - k]      # ⭐ 进一个、出一个
    if cur > best:
        best = cur
```

**复杂度**：**O(n)**。（每个元素进窗口一次、出窗口一次）

### 5.2 变长窗口（⭐ 最常用，模板背下来）

```python
l = 0
cur = 0                          # 窗口 [l, r] 的"状态"（和 / 计数 / …）
best = 0
for r in range(n):
    cur += a[r]                  # ① 右指针扩张：新元素进窗口
    while 窗口不合法:             # ② 左指针收缩：一直退到合法为止
        cur -= a[l]
        l += 1
    best = max(best, r - l + 1)  # ③ 此时窗口合法，更新答案
```

**三段式记法**：**扩张 → 收缩 → 更新**。90% 的滑动窗口题都是这三步。

> ⚠️ **收缩必须用 `while`，不能用 `if`**。
> 因为**进一个元素可能一次要退好几个**才够（比如 `S` 很小、`a[r]` 很大）。
> 用 `if` 只退一格，窗口会一直"不合法"，后面全错。

### 5.3 ⭐⭐ 变长窗口的"单调性前提"（今天最重要的坑）

**能不能用滑动窗口，取决于一个问题：`r` 往右扩张时，"不合法"这件事是不是单调的？**

| 数组元素 | 窗口和随 r 扩张 | 能用滑动窗口吗 |
|---|---|---|
| **全是正数** | 只增不减 | ✅ **能用**（超了就退 l，退了就一定合法） |
| **有负数** | 可能"先超后掉回来" | ❌ **不能用**！退 l 之后可能又不超了，逻辑崩掉 |

> ⭐ **例子**：`a = [5, -4, 5]`，`S = 5`。
> 窗口 `[5, -4]` 的和是 1（合法），扩到 `[5,-4,5]` 和是 6（超了）→ 退 l → `[-4,5]` 和是 1（又合法了）。
> 这时"退一格"就显得莫名其妙，而且**已经漏掉的长区间补不回来**。
>
> **结论**：`a[i] > 0` 才用滑动窗口；**有负数**就得换 Day10 的前缀和 + 别的技巧（如单调队列，以后学）。

> 💡 所以题目里写"**第二行 n 个正整数**"这四个字，就是在**明示你用滑动窗口**。
> 看到"正整数 / 非负 / 全是 1 和 0"就要警觉：**命题人在给你单调性**。

## 6. 三种双指针对照表（做题前先对号入座）

| | 左右指针 | 快慢指针 | 滑动窗口 |
|---|---|---|---|
| 指针方向 | 一头一尾对撞 | 都往右，速度不同 | 都往右，一个扩一个缩 |
| 数组要求 | **有序**（或对称） | 有序 / 下标可当指针 | **正数**（单调性） |
| 结束条件 | `l >= r` | `fast` 到头 / 相遇 | `r` 到头 |
| 维护的东西 | 两个端点 | 写位置 / 相遇点 | **一个区间 `[l, r]` 的统计量** |
| 答案形态 | 一对下标 / 是否 | 长度 / 重复值 / 中点 | 最长 / 最短 / 最大子数组 |
| 复杂度 | O(n) | O(n) | **O(n)**（l、r 各只走 n 步） |

## 7. 复杂度对比表（背下来）

| 问题 | 暴力 | 双指针 | 前缀和能不能救 |
|---|---|---|---|
| 有序数组两数之和 | O(n²) 枚举所有对 | **O(n)** | ❌ 前缀和管不了"找一对" |
| 盛水容器最大面积 | O(n²) 枚举所有对 | **O(n)** | ❌ |
| 有序数组去重 | O(n) 但**要开 set** | **O(n) + O(1) 空间** | ❌ |
| 找重复数字（n+1 个数） | O(n) 但**要开计数数组** | **O(n) + O(1) 空间** | ❌ |
| 定长窗口最大和 | O(n·k) | **O(n)** | ⚠️ 前缀和 O(n) 也行，但要多开 n 的空间 |
| 和不超过 S 的最长子数组（正数） | **O(n²)** | **O(n)** | ❌ 前缀和降不到 O(n) |
| 最长无重复子串 | O(n²) 枚举所有子串 | **O(n)** | ❌ |
| 最小覆盖子串 | O(n²) 枚举所有子串 | **O(n)** | ❌ |

> ⭐ **看出规律了吗**：凡是"**要在一堆区间里挑最好的一个**"，前缀和**救不了**——
> 因为前缀和只优化"算一个区间"，不减少"区间的个数"。**减少区间个数靠双指针。**

## 8. 蓝桥实战套路（看到关键词就选武器）

| 题目里的关键词 | 用什么 |
|---|---|
| "有序数组 / 已排序，找出两个数…" | **左右指针** |
| "回文 / 反转 / 对称" | **左右指针** |
| "最多能装 / 最大面积 / 两端" | **左右指针 + 移动短板** |
| "原地删除重复 / 只保留一个" | **快慢指针**（读指针 + 写指针）|
| "只出现一次/重复的数字，要求 O(1) 空间" | **快慢指针（判圈）** |
| "长度恰好为 k 的子数组" | **定长滑动窗口** |
| "最长/最短的连续子数组，且…（正数）" | **变长滑动窗口** |
| "不含重复字符 / 覆盖所有字符" | **滑动窗口 + 计数** |
| "子数组和等于 k（**有负数**）" | ❌ 不是滑动窗口 → **前缀和 + 哈希**（以后学） |

## 9. Python 写法的省事技巧

### 9.1 字符 → 下标：用长度 26 的数组代替 set/dict

题目里的字符串大多是"只含小写字母"。这时候**别用 `set`，用数组**：

```python
idx = ord(c) - ord('a')         # 'a'→0, 'b'→1, ..., 'z'→25
cnt = [0] * 26                  # 比 dict 快，而且能 O(1) 随机访问
```

> ⭐ 为什么快？`set`/`dict` 每次操作要做哈希、要分配对象；
> **数组只是"读一下第 idx 格"**。数据量大（10 万）时差距很明显。
> 而且数组可以写 `last[c] = r` 这种"我上次出现在哪"的直接记录。

### 9.2 `last[]` 数组代替"往前找"（最长无重复子串的关键优化）

笨办法：窗口不合法时 `while` 一个个退。聪明办法：**记住每个字符上次出现的位置**。

```python
last = [-1] * 26                # 每个字符上一次出现的位置，-1 表示没见过
if last[c] >= l:                # 上次出现的位置还在窗口里 → 有重复
    l = last[c] + 1             # ⭐ 直接把 l 跳到"重复字符的下一位"，一步到位
last[c] = r
```

> ⚠️ 这是"**用空间换时间**"，但空间很小（26 个格子），**不会破坏 O(1) 额外空间**的说法。

### 9.3 窗口状态要"增量维护"，别在循环里重算

```python
# ❌ 错：每次 sum() 重算 → O(n²)
for r in range(n):
    s = sum(a[l:r+1])

# ✅ 对：进出各改一次 → O(n)
cur += a[r]        # 进
cur -= a[l]        # 出
```

> ⭐ **判断你的滑动窗口是不是 O(n)，只看一件事**：
> `while` 里面**有没有 `sum()`、有没有 `in`、有没有切片**。有 → 你已经退化回 O(n²) 了。

### 9.4 输入读得快一点（Day10 学过，今天更要用）

```python
import sys
data = sys.stdin.read().split()     # 一次性读完，配合下标取值
```

> 双指针题经常要读 10 万个数，`input()` 逐行读会慢好几倍。

## 10. 常见坑速查

| 坑 | 现象 | 正确写法 |
|---|---|---|
| 收缩用 `if` 而不是 `while` | 大元素进来后窗口一直不合法，答案偏小 | `while 不合法: 退 l` |
| 乱序数组直接用左右指针 | 答案错，而且不报错（最难查） | **先 `a.sort()`** 或确认题目说"有序" |
| 数组里有负数还用滑动窗口 | 结果时对时错 | 看 5.3 节：**只有正数才能用** |
| 每次循环 `sum(a[l:r+1])` | 超时（O(n²)） | 用 `cur += / -=` 增量维护 |
| 两数之和用 `while l <= r` | 同一个元素被自己配了两次 | `while l < r` |
| 移动"长的那边" | 盛水容器答案偏小 | **移动短的那边** |
| 去重时忘了 `slow += 1` 再写 | 元素被覆盖丢失 | 先 `slow += 1`，再 `a[slow] = a[fast]` |
| 去重输出 `slow` 当长度 | 少 1（slow 是**下标**） | 长度是 `slow + 1` |
| Floyd 从 `0` 和 `0` 起步 | 第一步就"相遇"，答案错 | `slow = a[0]`、`fast = a[a[0]]` |
| Floyd 第 3 步忘了回起点 | 找不到环入口 | `p = 0` 再同速前进 |
| 窗口长度算成 `r - l` | 恒少 1（`[l,r]` 有 `r-l+1` 个） | 长度 = `r - l + 1` |
| 忘了处理"无解" | 输出 0 或者最后一次的答案 | 用 `best = 0` / `None` 起手，最后单独判 |
| 输出里混进提示文字 | 判题直接 0 分 | **只输出答案本身** |

## 11. 自测习惯

今天必测的四类（比 Day10 更多，因为双指针的坑是"静默"的）：

1. **数组只有一个元素 / 两个元素**（`while l < r` 一次都不进循环的那种）
2. **答案是 0 / 不存在**（比如没有满足条件的区间、找不到两个数）
3. **有并列答案**（多个等长最长区间 → 题目要求"最靠左"的那个，你的输出对不对？）
4. **对拍**：写个暴力版（两层循环枚举所有区间）和双指针版，**同一组数据比结果**；
   再专门造一组**大量重复值**的数据（考去重和窗口收缩）。
5. **大数据测时间**：`n = 100000` 跑一遍，**超过 1 秒就是复杂度写错了**
   （最常见的原因：`while` 里出现了 `sum()` 或切片）。

> ⭐ 双指针题最大的风险不是"报错"，而是"**算错但不报错**"。
> 所以**造数据对拍**比看样例更重要。
