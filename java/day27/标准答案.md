## Ex1：一行数据 → 一个对象

```java
class Student {
    private String name;
    private int score;
    private String className;

    public Student(String name, int score, String className) {
        this.name = name;
        this.score = score;
        this.className = className;
    }

    public String getName() { return name; }
    public int getScore() { return score; }
    public String getClassName() { return className; }

    @Override
    public String toString() {
        return name + " " + score + " " + className;
    }
}

class RowMapper {
    static Student mapRow(ResultSet rs) throws SQLException {
        return new Student(rs.getString("name"), rs.getInt("score"), rs.getString("class_name"));
    }

    static Student one(Connection conn, String name) throws SQLException {
        String sql = "SELECT name, score, class_name FROM student WHERE name = ?";
        try (PreparedStatement ps = conn.prepareStatement(sql)) {
            ps.setString(1, name);
            try (ResultSet rs = ps.executeQuery()) {
                if (rs.next()) {
                    return mapRow(rs);
                }
                return null;
            }
        }
    }
}
```

**实测输出**：`张三 88 一班` / `分数：88` / `班级：一班` / `查不到的人：null`

- 易错：不写 `toString()` → `Student@1b6d3586`，调试时完全没法看
- 加分理解：`mapRow` 是"结果集 → 对象"的**唯一出口**。今天 Ex3 和 Review 都用它，
  以后加一列只改这一个方法——这就是"转换逻辑只写一次"

## Ex2：批量插入（BatchDao）

```java
class BatchDao {
    static int insertAll(Connection conn, List<Student> list) throws SQLException {
        String sql = "INSERT INTO student (name, score, class_name) VALUES (?, ?, ?)";
        try (PreparedStatement ps = conn.prepareStatement(sql)) {
            for (Student s : list) {
                ps.setString(1, s.getName());
                ps.setInt(2, s.getScore());
                ps.setString(3, s.getClassName());
                ps.addBatch();
            }
            int[] res = ps.executeBatch();
            int rows = 0;
            for (int r : res) {
                rows += r;
            }
            return rows;
        }
    }
}
```

**实测输出**：`插入前人数：7` / `插入行数：3` / `插入后人数：10` + 10 行学生

- 易错：`executeBatch()` 返回 `int[]` 却当成 `int` 用 → 编译错；或 `return res.length`（虽然本题也是 3，但语义是"几条结果"不是"插了几行"）
- 加分理解：**空 List 也安全** → `executeBatch()` 返回空数组，累加得 0（实测 T5 通过）
- 加分理解：批量 vs 逐条。1000 行逐条 `executeUpdate` = 1000 次网络往返；批量是**打包一趟**，
  实测项目里差几十倍。代价是"某一行坏掉影响整批"，所以真实项目常按 500~1000 行一批

## Ex3：多行 → `List<Student>`（StudentDao）

```java
class StudentDao {
    static List<Student> findByMinScore(Connection conn, int min) throws SQLException {
        List<Student> list = new ArrayList<>();
        String sql = "SELECT name, score, class_name FROM student "
                + "WHERE score >= ? ORDER BY score DESC, name ASC";
        try (PreparedStatement ps = conn.prepareStatement(sql)) {
            ps.setInt(1, min);
            try (ResultSet rs = ps.executeQuery()) {
                while (rs.next()) {
                    list.add(RowMapper.mapRow(rs));
                }
            }
        }
        return list;
    }
}
```

**实测输出**：`80 分以上：4 人` / 钱七 100 二班 / 李四 95 一班 / 张三 88 一班 / 周九 82 三班 / `200 分以上：0 人（不报错）`

- 易错：`String sql = "..." + "...";` 换行拼接时**漏空格** → `score >= ?ORDER BY` 语法错
- 加分理解：返回**空 List** 而不是 null。这是"空对象模式"的朴素版——
  调用方永远可以放心 `for` 和 `.size()`，不用到处判 null

## Ex4：⭐ 事务转账（TransferService）

```java
class TransferService {
    static boolean transfer(Connection conn, String from, String to, int amount) throws SQLException {
        int fromBalance = Setup.balanceOf(conn, from);
        if (fromBalance == -1) {
            throw new SQLException("账户不存在");
        }
        if (Setup.balanceOf(conn, to) == -1) {
            throw new SQLException("账户不存在");
        }
        if (fromBalance < amount) {
            throw new SQLException("余额不足");
        }

        conn.setAutoCommit(false);
        try {
            updateBalance(conn, from, -amount);
            updateBalance(conn, to, amount);
            conn.commit();
            return true;
        } catch (SQLException e) {
            conn.rollback();
            throw e;
        } finally {
            conn.setAutoCommit(true);
        }
    }

    private static void updateBalance(Connection conn, String owner, int delta) throws SQLException {
        String sql = "UPDATE bank_account SET balance = balance + ? WHERE owner = ?";
        try (PreparedStatement ps = conn.prepareStatement(sql)) {
            ps.setInt(1, delta);
            ps.setString(2, owner);
            ps.executeUpdate();
        }
    }
}
```

**实测输出**：
```
初始：钱七 1000 赵六 1000 对账：5000
--- 钱七 → 赵六 转 400 ---
返回：true
钱七：600 赵六：1400
对账：5000
--- 赵六 → 钱七 转 99999（余额不够）---
转账失败：余额不足
钱七：600 赵六：1400
对账：5000
```

- 易错 ①：只写 `setAutoCommit(false)` 忘 `commit()` → **数据一点没变**（看着像"没执行"）
- 易错 ②：`catch` 里不 `rollback()` → 出错的连接挂着未提交事务，下一个用这连接的人会看到脏数据
- 易错 ③：`finally` 忘 `setAutoCommit(true)` → `conn` 还给 main 时状态被改坏
- **刁钻用例实测（T3）**：故意在"扣钱成功、加钱之前"抛异常 → 扣的钱**被回滚回来**，
  张三仍是 1000，对账仍是 3000 ✅（这就是事务的价值，没事务这里就丢了 100）
- 加分理解：**余额校验要放在 `setAutoCommit(false)` 之前**——注定失败的事，不用开事务

## Ex5：事务三道防线（SafeTransferService）

```java
class SafeTransferService {
    static String tryTransfer(Connection conn, String from, String to, int amount) throws SQLException {
        if (amount <= 0) {
            return "金额必须大于 0";
        }
        if (from.equals(to)) {
            return "不能给自己转账";
        }
        int fromBalance = Setup.balanceOf(conn, from);
        if (fromBalance == -1) {
            return "账户不存在";
        }
        if (Setup.balanceOf(conn, to) == -1) {
            return "账户不存在";
        }
        if (fromBalance < amount) {
            return "余额不足";
        }

        conn.setAutoCommit(false);
        try {
            update(conn, from, -amount);
            update(conn, to, amount);
            conn.commit();
            return "true";
        } catch (SQLException e) {
            conn.rollback();
            throw e;
        } finally {
            conn.setAutoCommit(true);
        }
    }

    private static void update(Connection conn, String owner, int delta) throws SQLException {
        String sql = "UPDATE bank_account SET balance = balance + ? WHERE owner = ?";
        try (PreparedStatement ps = conn.prepareStatement(sql)) {
            ps.setInt(1, delta);
            ps.setString(2, owner);
            ps.executeUpdate();
        }
    }
}
```

**实测输出**：
```
--- 转给不存在的人 ---
失败：账户不存在
张三余额：1000
对账：3000
--- 自己转给自己 ---
失败：不能给自己转账
对账：3000
--- 负数金额 ---
失败：金额必须大于 0
对账：3000
--- 正常转账 200 ---
成功：true
张三余额：800
李四余额：1200
对账：3000
```

- 易错 ①：在方法里 `System.out.println("失败：...")` 又 `return` → 输出变成两行 / 或 `失败：false`
- 易错 ②：**负数金额不校验** → `balance - (-50)` 变成加钱，凭空造钱（对账变 3050）⚠️ 真实事故级 bug
- 易错 ③：不校验"自己转自己" → 扣完再加，对账虽然平，但语义上应当拒绝
- **刁钻用例实测（T4）**：连续转 600 两次 → 第一次成功（张三 1000→400），
  第二次"余额不足"（400 < 600）→ 张三 400、对账 3000 ✅ 校验和事务都生效

## 🎯 复习：成绩管理 v2（ScoreService）

```java
class ScoreService {
    static void ensureAccount(Connection conn, String owner, int balance) throws SQLException {
        try (PreparedStatement ps = conn.prepareStatement("SELECT id FROM bank_account WHERE owner = ?")) {
            ps.setString(1, owner);
            try (ResultSet rs = ps.executeQuery()) {
                if (rs.next()) {
                    return;
                }
            }
        }
        try (PreparedStatement ps = conn.prepareStatement(
                "INSERT INTO bank_account (owner, balance) VALUES (?, ?)")) {
            ps.setString(1, owner);
            ps.setInt(2, balance);
            ps.executeUpdate();
        }
    }

    static int addStudent(Connection conn, String name, int score, String cls) throws SQLException {
        String sql = "INSERT INTO student (name, score, class_name) VALUES (?, ?, ?)";
        try (PreparedStatement ps = conn.prepareStatement(sql)) {
            ps.setString(1, name);
            ps.setInt(2, score);
            ps.setString(3, cls);
            ps.executeUpdate();
        }
        return Setup.count(conn);
    }

    static List<Student> ranking(Connection conn) throws SQLException {
        List<Student> list = new ArrayList<>();
        String sql = "SELECT name, score, class_name FROM student ORDER BY score DESC, name ASC";
        try (Statement st = conn.createStatement();
             ResultSet rs = st.executeQuery(sql)) {
            while (rs.next()) {
                list.add(RowMapper.mapRow(rs));
            }
        }
        return list;
    }

    static Map<String, Integer> countByClass(Connection conn) throws SQLException {
        Map<String, Integer> map = new LinkedHashMap<>();
        String sql = "SELECT class_name, COUNT(*) FROM student GROUP BY class_name "
                + "ORDER BY COUNT(*) DESC, class_name";
        try (Statement st = conn.createStatement();
             ResultSet rs = st.executeQuery(sql)) {
            while (rs.next()) {
                map.put(rs.getString(1), rs.getInt(2));
            }
        }
        return map;
    }

    static boolean transfer(Connection conn, String from, String to, int amount) throws SQLException {
        int fromBalance = Setup.balanceOf(conn, from);
        if (fromBalance == -1 || Setup.balanceOf(conn, to) == -1) {
            return false;
        }
        if (fromBalance < amount) {
            return false;
        }

        conn.setAutoCommit(false);
        try {
            update(conn, from, -amount);
            update(conn, to, amount);
            conn.commit();
            return true;
        } catch (SQLException e) {
            conn.rollback();
            return false;
        } finally {
            conn.setAutoCommit(true);
        }
    }

    private static void update(Connection conn, String owner, int delta) throws SQLException {
        String sql = "UPDATE bank_account SET balance = balance + ? WHERE owner = ?";
        try (PreparedStatement ps = conn.prepareStatement(sql)) {
            ps.setInt(1, delta);
            ps.setString(2, owner);
            ps.executeUpdate();
        }
    }
}
```

**实测输出**：
```
插入成功，当前人数：8
--- 排行榜前 3 ---
第1名：钱七 100 二班
第2名：李四 95 一班
第3名：吴十 90 二班
--- 每班人数 ---
一班 3 人
二班 3 人
三班 2 人
--- 钱七 → 赵六 转 400 ---
转账结果：true
钱七：600 赵六：1400
对账：5000
--- 钱七 → 赵六 转 99999（余额不足，必须不生效）---
转账结果：false
钱七：600 赵六：1400
对账：5000
```

- 易错 ①：`countByClass` 用 `HashMap` → 顺序乱（SQL 白排了）→ 用 **`LinkedHashMap`**
- 易错 ②：`transfer` 里余额不足**抛异常**（Ex4 的风格）→ main 只打印 `false`，但你得用 boolean 风格
- 易错 ③：`ensureAccount` 不先查就插 → 重复插入，同一个人两个账户（对账翻倍）
- **刁钻用例实测（T6）**：`ensureAccount` 连调两次 → 钱七账户仍是 **1** 条 ✅（幂等）
- 加分理解：对账 5000 = 学生账户 3000 + 新开两个账户 2000。**转账是搬家不是印钱**，
  所以两次转账（一次成功、一次失败）之后对账必须还是 5000 —— 这就是"事务守恒"

## 六题一句话总复习

| 题 | 武器 | 一句话 |
|---|---|---|
| Ex1 | 实体 + `mapRow` | 一行数据 → 一个对象，转换只写一次 |
| Ex2 | `addBatch/executeBatch` | 打包送一趟，别一行一行挤牙膏 |
| Ex3 | `List<Student>` | 多行 → 对象列表，查不到返空 List 不返 null |
| Ex4 | **事务** | `setAutoCommit(false)` → 两条 UPDATE → `commit()`，出错 `rollback()` |
| Ex5 | 三道防线 | 先校验（别浪费事务）→ 事务 → 对账（钱守恒） |
| Review | 全拼装 | 实体 + DAO + 事务，一个完整小系统 |

## 附：面试可背

1. **什么是事务**：一组**要么全成功、要么全失败**的数据库操作。
   四个特性 ACID：原子性（全或无）、一致性（对账平）、隔离性（互相看不见中间态）、持久性（提交就落盘）。
2. **JDBC 里怎么写事务**：`conn.setAutoCommit(false)` → 业务 SQL → `conn.commit()`；
   出错 `conn.rollback()`；最后 `setAutoCommit(true)` 恢复。
3. **DAO 分层解决什么**：SQL 集中在一个层，业务代码不认识 SQL；
   换数据库/改表结构时只动 DAO，不动业务逻辑。
