## 二、核心心法：**数据有三种"装法"，先想清楚再动手**

```
① 一个对象      Student s = new Student("张三", 88);      → 管"一个"人
② 一排对象      List<Student> list = new ArrayList<>();   → 管"一队"人（要遍历/排序）
③ 一张表        Map<String,Integer> map = new HashMap<>(); → 管"查得快"（按名字找成绩）
```

**选型口诀（今天每道题都先问自己）**：

- 要**一个个遍历**（打印全班）→ `List`
- 要**按某个键快速查**（名字查成绩）→ `Map`
- 要**自动排好序**（学号顺序）→ `TreeMap`
- 要**按别的规则重排**（分数降序）→ 取出来放 `List`，再 `Collections.sort` 或 `list.sort`

> 一句话：**Map 是"通讯录"，List 是"排队的队伍"**——查人用通讯录，排队用队伍。

## 三、排行榜为什么不能用 TreeMap 直接排？

很多人的第一反应：`TreeMap<Integer, Student>` 用**成绩**当 key 不就自动排好了？——**不行，两个原因**：

1. **成绩会重复**：同分两个人，key 撞了 → 后一个**覆盖**前一个，人直接消失！
2. 排行榜要按分数排，但学号才是唯一标识——**分数的身份不唯一**

**正确姿势（今天 Review 就考这个）**：

```
TreeMap/HashMap（学号→学生）
      ↓ entrySet 取出所有键值对
List<Map.Entry<...>>（可以随便重排的列表）
      ↓ list.sort(按 value 的成绩降序)
前 3 名就是 list.get(0..2)
```

## 四、常见坑（今天必踩预警）

| 坑 | 现象 | 正确做法 |
|---|---|---|
| `Integer` 拆箱 NPE | `int s = map.get("查不到的");` → 抛异常 | 返回类型用 `Integer`，再判 `== null` |
| 比较器方向反了 | 明明要降序，跑出来升序 | `Integer.compare(o.score, this.score)`（**倒着比**）|
| 同分顺序乱 | 两个 88 分，每次跑顺序不一样 | 比较器里**同分再比姓名**兜底（确定性强，判题才过）|
| 平均值变成整数 | 419/5 输出 `83` 不是 `83.80` | 先转 `double`：`(double) sum / size`，再 `String.format("%.2f", ...)` |
| 用 Map 当排行榜 | 同分的人被覆盖 | 分数不能当 key，要取出来放 List 排 |

**口诀**：*查得快用 Map，排队用 List，同分兜底加姓名，平均先转 double。*
