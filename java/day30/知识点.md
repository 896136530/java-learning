# Day 30：SpringBoot 上手 —— 从"我写服务器"到"框架给我服务器"

> 前提：昨天（Day29）你搞懂了 Maven（依赖自动下载、`mvn` 三个命令、可执行 jar）。
> 今天你会看到 —— **SpringBoot 项目就是一个 Maven 项目**，你昨天学的东西今天全用得上。

---

## 0. 先用一句话说清 SpringBoot 是什么

**SpringBoot = Spring 框架 + 一堆"约定好的默认配置" + 内嵌的服务器。**

| 你以为要做的 | SpringBoot 替你做的 |
|---|---|
| 装 Tomcat、配 web.xml、打 war 包部署 | **内嵌 Tomcat**，`main` 一跑服务就起来了 |
| 手写一堆 XML 配置文件 | **约定优于配置**：默认值全给你了，要改才写一行 |
| 手动管理几十个依赖的版本 | **starter**：写一个依赖，版本全对好 |
| 自己写 JDBC 连库、发 SQL、关资源 | **JPA**：贴 `@Entity`，建表和增删改查全自动 |
| 自己解析 HTTP 请求、拼 JSON 响应 | **SpringMVC**：贴 `@GetMapping`，参数和 JSON 自动转换 |

**一句话**：以前你是"自己砌墙盖房"，SpringBoot 是"精装房——结构给你了，你只管往里搬家具"。

### 那 "Spring" 和 "SpringBoot" 到底啥区别？（必问）

| | Spring（框架本体）| SpringBoot（脚手架）|
|---|---|---|
| 核心能力 | **IoC 容器** + **依赖注入**（对象由它创建和管理）| 就是 Spring + 一堆默认配置 |
| 配置方式 | 大量 XML / 手写 `@Configuration` 类 | **约定优于配置**：默认值全给好了 |
| 起一个 web 项目 | 装 Tomcat、配 web.xml、打 war、部署 | **内嵌 Tomcat**，`main` 一跑就有了 |
| 管依赖版本 | 自己保证几十个包版本互相兼容 | `parent` + `starter` 帮你对齐 |
| 一句话 | 「能力」| 「怎么爽快地用这个能力」|

> **记住这个关系**：SpringBoot **不是** Spring 的替代品，它是 Spring 的**启动器 + 默认配置套餐**。
> 你在今天代码里写的 `@Autowired`、`@Component`，全是 **Spring 本体**的能力；
> `SpringApplication.run()`、`starter`、`application.properties` 才是 **SpringBoot** 加的。

## 1. 第一件事：认结构（和 Day29 对比着看）

```
java/day30/
├── pom.xml                         ← ⭐ 和 Day29 一样！只是内容变"高级"了
└── src/
    └── main/
        ├── java/
        │   └── com/xiaoming/day30/             ← ⭐ 有【包名】了！（Day29 是 ex1、ex2 这种）
        │       ├── Day30Application.java        ← 启动类（main 只有一行）
        │       ├── controller/TaskController.java  ← 接口层（接收请求、返回数据）
        │       ├── repository/TaskRepository.java  ← 仓库层（一行代码 = 一个 DAO）
        │       ├── entity/Task.java                ← 实体类（贴 @Entity 就自动建表）
        │       └── config/DataInitializer.java     ← 启动时灌测试数据
        └── resources/
            └── application.properties           ← ⭐ 就是 Day29 的 db.properties 升级版
```

### 「包名」为什么必须有？

Day29 你的类是 `ex1.HelloMaven`（包名只有一个词）。真实项目全是**反向域名**：

```
com.xiaoming.day30.controller.TaskController
└────┬────┘ └──┬──┘ └────┬───┘ └──────┬──────┘
   公司域名倒写   项目名    分层名        类名
```

**为什么倒着写**：全世界只有一个 `com.baidu`，所以不会和别人重名 —— 你发的 jar 别人拿去用，不会撞车。

#### ⭐ `package` 声明铁律（今天每个文件首行都有，别漏）

```java
package com.xiaoming.day30.controller;    // ← 文件第一行，决定"这个类属于哪个包"
```

**规则：包名 = 文件夹路径，一个字母都不能差。**

```
src/main/java/com/xiaoming/day30/controller/TaskController.java
                └──────── package com.xiaoming.day30.controller; ─────────┘
                              这两者必须严格对应
```

| 情况 | 结果 |
|---|---|
| 路径和 `package` 一致 | ✅ 正常编译 |
| `package` 写了、文件却放错文件夹 | ❌ **编译直接报错**（Maven 强制检查）|
| **完全没写 `package`**（默认包）| ⚠️ 能编译，但**别的类 import 不到你**，SpringBoot 也扫不到 → **等于白写** |

> 📌 **和 Day29 的关系**：Day29 的 `ex1/HelloMaven.java` 首行就是 `package ex1;` —— 只是当时没给你点出这条规则。
> **今天起，每新建一个类，第一行永远是 `package 对应路径;`。**

### 「分层」是什么意思？

| 层 | 类 | 职责 | Day27/28 里对应什么 |
|---|---|---|---|
| **controller** | TaskController | 接收 HTTP 请求、返回 JSON | 以前 `main` 里读输入那部分 |
| **repository** | TaskRepository | 数据存取 | 你的 `BookDao` / `StudentDao` |
| **entity** | Task | 数据的形状 | 你的 `Book` / `Student` |
| **config** | DataInitializer | 启动初始化 | 你的 `Setup.java` / `initTable()` |

**看懂了吗？** 分层你没变，变的是**每层要写的代码量少了一个数量级**。

## 2. pom.xml 对比：为什么依赖都不用写版本号了

**Day29（你写的）：**
```xml
<dependency>
  <groupId>com.mysql</groupId>
  <artifactId>mysql-connector-j</artifactId>
  <version>8.4.0</version>          ← 版本号自己写，还得自己查
</dependency>
```

**Day30：**
```xml
<parent>
  <groupId>org.springframework.boot</groupId>
  <artifactId>spring-boot-starter-parent</artifactId>
  <version>3.3.5</version>          ← ⭐ 只在这里写一次版本
</parent>

<dependency>
  <groupId>org.springframework.boot</groupId>
  <artifactId>spring-boot-starter-web</artifactId>
  <!-- 没有 version！parent 已经规定好了 3.3.5 该配哪些依赖的哪些版本 -->
</dependency>
```

### 两个关键概念

| 概念 | 意思 | 好处 |
|---|---|---|
| **parent** | 继承一个"父 pom"，它管着几百个依赖的版本 | 你只写一次版本，全家对齐 |
| **starter** | 一个"能力包"，里面是一组配合好的依赖 | `starter-web` = SpringMVC + Tomcat + Jackson(JSON) |

**`starter-web` 里面到底装了什么？** 你昨天学的命令就能看：

```bash
mvn dependency:tree
```
（你会看到几十个依赖 —— 以前你要一个个手下载，现在写一行就行）

## 3. 今天最震撼的三件事（按震撼程度排序）

### 🥇 第一件：一个 `main` 就起了一个网站

```java
@SpringBootApplication
public class Day30Application {
    public static void main(String[] args) {
        SpringApplication.run(Day30Application.class, args);
    }
}
```

**就这 3 行**，跑起来后：
- 启动了一个 Tomcat（端口 8080）
- 扫描了所有 `@RestController` 并注册好路由
- 建立了数据库连接池
- 读完了 `application.properties`

⚠️ **`@SpringBootApplication` 的位置规则**：它从**这个类所在的包往下扫描**。
你的 Controller 必须放在 `com.xiaoming.day30` **或其子包**里。
放到外面 SpringBoot 就找不到 —— **新手第一个经典坑**（表现为：接口全 404，但编译一点错没有）。

### 🥈 第二件：DAO 从 60 行变成 1 行

| Day27/28 的你 | Day30 |
|---|---|
| `BookDao.java`：60+ 行（Connection、PreparedStatement、SQL 字符串、mapRow、关资源） | `TaskRepository.java`：**一行** |

```java
public interface TaskRepository extends JpaRepository<Task, Long> {
}
```

**就这一行，你白得这些方法**：`save` / `findAll` / `findById` / `deleteById` / `count`。

**更离谱的是「魔法方法名」** —— 下面这些方法**没有实现**，Spring 按方法名自己推导 SQL：

| 你写的方法名 | Spring 生成的 SQL |
|---|---|
| `findByDayNo(Integer)` | `SELECT * FROM task WHERE day_no = ?` |
| `findByDone(Boolean)` | `SELECT * FROM task WHERE done = ?` |
| `countByDone(Boolean)` | `SELECT COUNT(*) FROM task WHERE done = ?` |
| `findByTypeOrderByDayNo(String)` | `SELECT * FROM task WHERE type = ? ORDER BY day_no` |

> 📌 **规则**：`findBy` / `countBy` / `deleteBy` + 属性名（首字母大写）+ `And` / `Or` + `OrderBy...`
> ⚠️ **用的是实体里的属性名**（`dayNo`），不是数据库列名（`day_no`）—— 写错启动就报错。

**为什么能这样？** 因为 Spring Data JPA 在启动时**动态生成了这个接口的实现类**。
你不用写实现，运行时却真的有实现 —— 这就是"代理"技术，也是 Spring 的核心手段之一。

### 🥉 第三件：内嵌的"零安装"哲学（H2 和 Tomcat）

Day26 你花了很久搞 MySQL：装服务、起进程、配密码、建库建表 —— 数据库是个**外部服务**。

今天用的 **H2** 是纯 Java 写的数据库，**和你的程序跑在同一个进程里**：
- 不用安装、不用启动、不用密码
- 程序一关，数据就没了（`mem` = 内存）

**发现了吗？这和 Tomcat 是一模一样的套路**：

| | 以前（外部服务） | 现在（内嵌组件） |
|---|---|---|
| Web 服务器 | 装 Tomcat、部署 war | **内嵌 Tomcat**（starter-web 带进来的） |
| 数据库 | 装 MySQL、连 3306 | **内嵌 H2**（一个 jar 就是数据库） |

> **SpringBoot 的设计哲学**：开发阶段让"外部依赖"变成"内部组件"，**零配置、开箱能跑**；
> 上线时再通过配置切回真 MySQL、真 Tomcat。
> 你 Day29 Ex3 学的"配置外置"就是这个思想的另一半。

## 4. 关键注解速查（今天只用这几个）

| 注解 | 贴在哪 | 干什么 |
|---|---|---|
| `@SpringBootApplication` | 启动类 | 声明"这是 SpringBoot 应用"，开启自动配置 + 包扫描 |
| `@RestController` | Controller 类 | 这个类的方法返回值 → 直接作为 HTTP 响应（自动转 JSON）|
| `@RequestMapping("/tasks")` | 类或方法 | URL 前缀/路径 |
| `@GetMapping` / `@PostMapping` | 方法 | 处理 GET / POST 请求 |
| `@RequestParam("day")` | 方法参数 | 取 URL 问号后面的参数：`/tasks?day=3` |
| `@PathVariable("id")` | 方法参数 | 取路径里的变量：`/tasks/{id}` |
| `@RequestBody` | 方法参数 | 把请求体的 JSON **自动变成对象**（靠 Jackson）|
| `@Autowired` | 字段/构造器 | 依赖注入："我需要这个对象，Spring 你给我" |
| `@Entity` / `@Id` / `@Column` | 实体类 | 声明"这个类对应一张表" |
| `@Repository` / `@Component` | 类 | 声明"这个类交给 Spring 管理" |
| `@Value("${app.name:默认值}")` | 字段 | 把配置文件里的值读进来 |

## 5. 依赖注入（DI）：今天最需要"意会"的概念

**问题**：你的 `TaskController` 里用了 `taskRepository`，但**你没写 `new TaskRepositoryImpl()`**，它从哪来的？

```java
@Autowired
private TaskRepository taskRepository;    // 你没 new 过它，为什么能用？
```

**答**：Spring 启动时做了 4 件事：

1. 扫描到 `TaskRepository` 是个接口
2. 用 Spring Data JPA **生成它的实现类**
3. 创建好对象，放进"容器"（可以理解成一个巨大的 Map：类型 → 对象）
4. 看到 `@Autowired`，**把对象塞给你**

> **一句话**：你声明"我需要什么"，Spring 负责"给你什么"。

**好处**（举你熟悉的例子）：
- 今天用 H2，明天想换 MySQL：**改 `application.properties` 就行**，Controller 一行都不用动
- 想测试时用假数据：塞一个假的 Repository 进去，不用改业务代码

**两种注入写法**（今天代码里都有）：

```java
// ① 字段注入（简单，你会在很多老代码里看到）
@Autowired
private TaskRepository taskRepository;

// ② 构造器注入（⭐ 更推荐：能标 final、依赖关系一眼看清、方便测试）
private final TaskRepository taskRepository;
public DataInitializer(TaskRepository taskRepository) {
    this.taskRepository = taskRepository;
}
```

## 6. `application.properties`：昨天那课的续集

```
server.port=8080                                    ← 改一行，端口就变了
spring.datasource.url=jdbc:h2:mem:day30db...        ← 数据库地址（跟 Day29 的 db.url 一样的东西）
spring.jpa.show-sql=true                            ← 把自动生成的 SQL 打到控制台 ⭐ 强烈建议开着
spring.h2.console.enabled=true                      ← 打开网页版数据库客户端
```

**和 Day29 的关系**：

| Day29 | Day30 |
|---|---|
| `db.properties`（你自己起的名字）| `application.properties`（**名字固定**，SpringBoot 才认） |
| 你写 `Hold.readResource()` 自己读 | **框架自动读**，你用 `@Value` 取 |
| 读 `db.url`、`db.user` | 读 `server.port`、`spring.datasource.*` |

**⭐ 今天一定要做的观察**：`spring.jpa.show-sql=true` 开着，启动后看控制台 ——
你会发现 `create table task (...)`、`insert into task (...)`、`select ... from task` **全是自动生成的**。

**你一个 SQL 都没写，但 SQL 一直在跑。** 这就是 ORM。

## 7. 怎么跑

### 用脚本（推荐）
双击 `运行SpringBoot.bat`，选编号：
```
1. 启动应用（前台，Ctrl+C 停止）    ← 最常用
2. 打包（生成可执行 jar）
3. 打包后直接 java -jar 跑
4. mvn clean
5. mvn dependency:tree（看 starter 里装了多少依赖）
```

### 用手敲（终端里）

```bash
mvn spring-boot:run                    # 启动（前台，Ctrl+C 停）

# 另开一个终端窗口，测接口：
curl http://localhost:8080/ping
curl http://localhost:8080/tasks
curl http://localhost:8080/tasks/report

# 打包 + 发货（和 Day29 一样的套路）
mvn clean package
java -jar target/day30-springboot-1.0.jar
```

> ⚠️ **`mvn spring-boot:run` 是"前台"运行** —— 它会一直占着那个终端（服务器不能自己停）。
> 所以测接口要**再开一个终端**（或者直接用浏览器）。这就是"服务器程序"和以前"跑完就结束的程序"最大的体验差别。

### 浏览器直接看（最直观）

| 地址 | 看什么 |
|---|---|
| http://localhost:8080/ping | 服务器活着吗 |
| http://localhost:8080/tasks | 8 条任务的 JSON |
| http://localhost:8080/tasks?day=3 | 第 3 天的任务（2 条）|
| http://localhost:8080/tasks/1 | 第 1 条任务 |

## 8. 今天必须搞清的三个"为什么"

### Q1：为什么 `Day30Application` 的位置不能乱放？
因为它决定**包扫描的起点**。放在 `com.xiaoming.abc`，Spring 只会扫 `com.xiaoming.abc.*`，
你的 `com.xiaoming.day30.controller` 就永远扫不到 → **所有接口 404，但编译全过**。
（这是最气人的一种错：没有报错，就是不工作）

### Q2：为什么 Repository 不写实现也能用？
Spring Data JPA 在启动时**按接口生成实现类**（动态代理）。
你给的"信息"是：① 泛型 `<Task, Long>` 说明操作哪张表、主键什么类型
② 方法名 `findByDayNo` 说明查询条件。

### Q3：为什么 H2 的数据一关就没？
因为 `jdbc:h2:mem:` 的 `mem` = **内存**。数据库的所有数据在 JVM 堆里，
进程一退出，内存就没了。改成 `jdbc:h2:file:./data/day30` 就会存到磁盘（可以自己试试）。

## 9. 自测习惯

```bash
# 1. 改完代码重启（SpringBoot 没有自动重启，除非装 devtools）
# 2. 先打 /ping 确认服务器活着，再打复杂接口 ← 分层排查
# 3. 接口返回不对时，看**控制台打印的 SQL**（show-sql=true）
#    —— 90% 的"数据不对"都能在 SQL 里找到原因
# 4. 打包后一定要 java -jar 跑一次（Day29 Ex4 的教训）
```

> ⚠️ **注意端口占用**：如果 8080 被占了（比如你上次的 SpringBoot 没关干净），
> 启动会报 `Port 8080 was already in use`。
> 解决办法：① 关掉旧进程 ② 或改 `server.port` （这就是"配置外置"的实用价值）
