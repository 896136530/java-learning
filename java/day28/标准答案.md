## Ex3 期望输出

```

--- 场景1：A 把张三改成 700（先不提交）---

```

⚠️ 容易出错的点：
- `connB.setAutoCommit(true)` 是 main 里给的；B 的 SELECT 在自动提交模式下也会开一个"隐式事务/快照"，但因为每次 SELECT 都是独立快照，所以**B 每次读到的都是当下已提交的值** → 场景1 打印 1000 正确、提交后打印 700 正确
- 若用户把 `B 看张三` 写成 700：说明他理解反了隔离级别，要讲清"未提交的改动别人看不见"

⚠️ **`c5 == c2` 是 `false` 才是正确行为**（代理壳每次现做；`equals` 也 false）。判断复用看"池子还剩几个"。
**这是本页我一开始写反的地方（原写"true"），真机验证后已修正模板与知识点。用户若输出 true，反而要问他"你是不是把真连接直接借出去了"。**

参考实现：

```java
class MiniPool {
    private final List<Connection> idle = new ArrayList<>();
    private final int size;

    MiniPool(int size) throws SQLException {
        this.size = size;
        for (int i = 0; i < size; i++) {
            idle.add(Db.newConnection());
        }
    }

    Connection getConnection() {
        if (idle.isEmpty()) {
            return null;
        }
        Connection real = idle.remove(idle.size() - 1);
        return (Connection) Proxy.newProxyInstance(
                Connection.class.getClassLoader(),
                new Class<?>[]{Connection.class},
                (proxy, method, methodArgs) -> {
                    if (method.getName().equals("close")) {
                        this.close(real);
                        return null;
                    }
                    return method.invoke(real, methodArgs);
                });
    }

    int size() {
        return idle.size();
    }

    void close(Connection real) {
        idle.add(real);
    }
}
```

⚠️ 关键判据：**必须包 Proxy**。若用户直接 `return real;`，实测后果是：
- `c2.close()` 真把连接关了、**池子数量不增加**（`池子还剩` 不变）
- 后面拿它执行 SQL 报 **`No operations allowed after connection closed.`**
这就是"壳"的意义。

## 常见错误清单（批改时逐个查）

| 症状 | 原因 |
|---|---|
| 编译"未报告的异常错误 SQLException" | 方法签名漏 `throws SQLException`（**用户在 Day27 连栽两次**）|
| 运行 "Unknown column 'xxx' in 'field list'" | 列名写错（`class` 是关键字，列名是 `class_name`）|
| 运行 "Table 'day28.xxx' doesn't exist" | 表名写错（Day27 出现过 `Account`、`back_account`）|
| 改不存在的人报异常 | 错在把 `executeUpdate()` 当成"必须有 1 行"；它返回 0 是正常的 |
| `countByClass` 打印顺序乱 | 用了 `HashMap`（必须 `LinkedHashMap`）；或 ORDER BY 用了 `class_name`（中文排序，"三班"会跑到"二班"前）|
| 分页出现重复/漏行 | 没有 `ORDER BY` |
| 批量插入一半成功 | 没套事务 / `finally` 里忘了 `setAutoCommit(true)` |
| 借第 4 个不是 null | `getConnection()` 忘了判空（或池子建多了）|
| 连接池借出后程序报 "No operations allowed after connection closed" | `close()` 被真执行了 → 没包 `Proxy` 壳 |
| 转账后对账变了 | 事务没生效（漏 commit / 或把两条 UPDATE 放到事务外）|
