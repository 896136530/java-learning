## 题 1：DAO 写操作三件套（`Day28_Ex1.java`）

**要写的**：`Student`（public 字段 + 构造器 + toString）、`StudentUtils`（`mapRow` / `findOne` / `findId` / `insert` / `updateScore` / `deleteById`）

**核心考点**：
- 三条写操作**全部 `return executeUpdate()`**——返回影响行数
- 改一个不存在的人 → 返回 **0**，不是异常
- `findOne` / `findId` 查不到 → 返回 `null` / `-1`

**自测**：连续跑两次（`Setup.init` 会重置数据，所以跑几次结果都一样）；再自己加一个"插同名的人"看看会怎样（表里没有唯一约束，所以能插进去两个）。

## 题 2：聚合下推（`Day28_Ex2.java`）

**要写的**：`Student`、`StudentUtils`（`countStudents` / `avgScore` / `maxScore` / `topN` / `countByClass`）

**核心考点**：
- `COUNT(*)` / `AVG(score)` / `MAX(score)` 直接让数据库算，`rs.getInt(1)` / `getDouble(1)` 拿结果
- `topN` 里 **`LIMIT ?` 用占位符**（不是字符串拼接！）
- `countByClass` 必须用 **`LinkedHashMap`** 保住 SQL 的排序

**自测**：`topN(conn, 10)` 比人数多 → 拿到全部 7 个而不是报错；`countByClass` 打印出来是不是 `{一班=3, 二班=2, 三班=2}`（用 `HashMap` 会乱序；ORDER BY 里用 `class_name` 会变成"三班在二班前面"——中文别当排序键）。

## 题 3：事务隔离级别实况（`Day28_Ex3.java`）⭐

**要写的**：`BalanceDao`（`balanceOf` / `updateBalance` / `openTx` / `commit` / `rollback` / `levelName`）

**这题的重点不是写代码，是"看懂你打出来的数字"**：
- 场景 1：A 开了事务把张三改成 700 **但没提交** → `A 自己看张三=700`，**`B 看张三=1000`**（隔离生效！）
- 场景 1 后半：A 提交后，B 再看 → **700**（提交之后才"放出来"）
- 场景 2：A 改成 500 然后 rollback → A 再看 → **回到 700**
- 场景 3：`connB.setTransactionIsolation(READ_COMMITTED)` 后打印名字

**答完这题你应该能回答**：什么是脏读？什么是不可重复读？MySQL 默认哪一档？

**自测**：把场景 1 里 `commit` 那行注释掉（改成 `rollback`）跑一次，想清楚 B 为什么始终看不到 A 的改动。

## 题 4：手写迷你连接池（`Day28_Ex4.java`）⭐

**要写的**：`MiniPool`（构造器预热 N 个连接、`getConnection` 借出、`size` 剩余、`close` 还回、**代理包装**）

**核心考点**：
- 构造时就 `Db.newConnection()` 建好 N 个（预热）
- `getConnection()`：空了返回 `null`；否则 `remove` 并返回（**不是 get！借出去池子里就没它了**）
- **`Proxy` 包装**：让 `close()` 变成"还回池子"而不是"真关闭"
- 难点在 `Proxy`，但**理解"借出去的是壳"比会写 Proxy 更重要**

**自测**：把 `getConnection()` 里改回直接 `return real;`（不包壳）跑一次——`c2.close()` 会**真的关掉连接**、池子数量不增加，后面拿它查数据库直接报 `No operations allowed after connection closed.`。就懂为什么要包壳了。
> ⚠️ 别被这一行骗了：包壳之后 `c5 == c2` 是 **`false`（正常）**——壳每次现做，真连接才被复用。判断复用看"池子还剩几个"。

## 题 5：为什么要连接池（`Day28_Ex5.java`）

**要写的**：把 Ex4 的 `MiniPool` **整块复制过来**（这题不用新写代码）

**核心考点**：对比两个数字
- 30 次"每次新建连接"：包含 30 次 TCP + 认证
- 30 次"池子借还"：连接早就连好了，只是搬对象
- 再看"连接复用"三行输出

> 💡 数字因机器而异，**看的是差距**（通常新建连接慢十倍以上）。这也是"真实项目必须用连接池"的硬理由。

## 🎯 复习：业务 DAO 合体（`Day28_Review.java`）

**要写的**：`Student` + `StudentDao` 九个方法（写操作 ×3 + 批量事务 + 分页 + 转账 + 两个辅助）

**三个"项目经验"考点**：
1. **`addAll` 必须套事务**：三个人里有一个失败就全部回滚（不然半截数据进了库）
2. **`page` 必须 `ORDER BY`**：不排序的 `LIMIT/OFFSET` 会出现翻页重复/漏行
3. **转账后对账必须不变**：`SUM(balance)` 是"钱搬家"的铁证（这题期望 **4000**，自己加一遍验证）

**自测**：把 `addAll` 里故意塞一个"name 为 null"的数据（表里 `name NOT NULL` → 会抛异常）→ 看是不是三个人一个都没进去（事务回滚成功）。
