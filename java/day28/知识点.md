## 1. DAO 到底该长什么样（把方法收口）

Day27 你在每个练习里手写了 `RowMapper.one` / `BatchDao.insertAll`，今天把它们收进**一个类**：

```java
public class StudentDao {
    // 查
    public static Student findOne(Connection conn, String name) throws SQLException { ... }
    public static List<Student> findAll(Connection conn) throws SQLException { ... }
    // 写（返回影响行数）
    public static int insert(Connection conn, String name, int score, String cls) throws SQLException { ... }
    public static int updateScore(Connection conn, String name, int score) throws SQLException { ... }
    public static int deleteById(Connection conn, int id) throws SQLException { ... }
}
```

**三条规矩**（今天开始守着写）：

| 规矩 | 为什么 |
|---|---|
| **方法都返回"数据"或"影响行数"**，不 `println` | 打印是 main 的事；DAO 一打印，别的地方就没法复用了 |
| **查不到返回 `null` / 空 `List`，不抛异常** | "没有"是正常情况，不是错误 |
| **`throws SQLException` 一律往外扔** | 让上层决定"是重试、还是提示用户"；DAO 自己吞掉异常 = bug 被埋葬 |

## 2. ⭐ 影响行数：`executeUpdate()` 的返回值才是"结果"

```java
int rows = dao.updateScore(conn, "陈七", 100);   // 陈七不存在
System.out.println(rows);                        // → 0   不是报错！
```

| 返回值 | 含义 |
|---|---|
| `1` | 真的改到了 1 行 |
| `0` | **没改到任何一行**（人不存在 / 条件不匹配）—— 关键判断依据 |
| `>1` | 一条 UPDATE 改了多行（比如 `WHERE class_name = '一班'` 改了一班 3 个人）|

> 💡 项目里"删除失败"的提示，**就是靠这个 0 判断的**：`if (dao.deleteById(conn, id) == 0) 提示"记录不存在"`。

**自增主键怎么拿回来？** 插入后想知道新 id：

```sql
SELECT LAST_INSERT_ID()      -- 同一个连接里，刚插入那行的自增 id（标准做法）
```

## 3. 聚合下推：能在数据库算的，别搬回 Java

```java
// ❌ 慢写法：把 7 万行都捞回来，Java 里循环统计
// SELECT * FROM student → for 循环算人数/平均分/最高分

// ✅ 快写法：数据库算完只给你一个数
// SELECT COUNT(*) FROM student
// SELECT AVG(score) FROM student
// SELECT MAX(score) FROM student
// SELECT name, score, class_name FROM student ORDER BY score DESC, name ASC LIMIT 3
```

| 需求 | SQL | Java 拿法 |
|---|---|---|
| 人数 | `COUNT(*)` | `rs.getInt(1)` |
| 平均分 | `AVG(score)` | `rs.getDouble(1)` |
| 最高分 | `MAX(score)` / `MIN(score)` | `rs.getInt(1)` |
| 前 N 名 | `ORDER BY ... LIMIT ?` | `rs.getInt(...)` + 逐行 mapRow |

> ⚠️ `rs.getInt(1)` / `getString(1)` 里的 **1 是"第几列"（从 1 开始）**，不是下标 0。用列名更清楚：`rs.getInt("score")`。
> ⚠️ `AVG` 返回的是 **DOUBLE**（78.0），不是 int。想打两位小数在 Java 里格式化。

## 4. 结果集顺序：为什么 countByClass 必须用 `LinkedHashMap`

```java
Map<String, Integer> map = new HashMap<>();       // ❌ 打乱顺序
Map<String, Integer> map = new LinkedHashMap<>(); // ✅ 保持放入顺序
```

SQL 里排好的顺序，**`HashMap` 会给你打乱**（它按哈希值存键，遍历顺序和放入顺序无关）→ 打印出来像乱序。
**要"有序字典"就用 `LinkedHashMap`**（Day13 讲过 Map，今天第一次真正需要它）。

> 一句话：**SQL 排好的顺序，只在 `List` 和 `LinkedHashMap` 里能保住。**

### ⚠️ 顺带一个中文坑：中文别当排序键

```sql
-- 一班 3 人，二班 2 人，三班 2 人
ORDER BY COUNT(*) DESC, class_name   -- ❌ 实测得到：一班=3, 三班=2, 二班=2
ORDER BY COUNT(*) DESC, MIN(id)      -- ✅ 实测得到：一班=3, 二班=2, 三班=2
```

人数打平（2 对 2）时靠 `class_name` 分胜负，而**中文的排序规则既不看拼音也不看笔画，是按字符编码值排的**——"三"的编码比"二"小，所以"三班"跑到"二班"前面去了。
**想按"班级第一次出现的顺序"排，就用 `MIN(id)`（该班第一个人的 id）；中文一律不当排序键。**

## 5. ⭐ 事务隔离级别（今天的新知识）

事务有 ACID，其中的 **I（Isolation 隔离性）** 说的是"**多个事务同时跑，互相看到什么**"。SQL 标准定义了 4 档：

| 级别 | 值 | 能防住 | 防不住 | 直白解释 |
|---|---|---|---|---|
| `READ UNCOMMITTED` 读未提交 | 1 | 啥也防不住 | 脏读、不可重复读、幻读 | 别人没提交的改动你也能看到（"脏"）|
| `READ COMMITTED` 读已提交 | 2 | 脏读 | 不可重复读、幻读 | 只读"已提交"的（Oracle/PostgreSQL 的默认档）|
| **`REPEATABLE READ` 可重复读** | 4 | 脏读、不可重复读 | 幻读（MySQL 基本也防住了）| **MySQL 默认档**：同一个事务里两次查同一个东西，结果一样 |
| `SERIALIZABLE` 串行化 | 8 | 全部 | — | 事务排队一个个来，最安全也最慢 |

**三个"读"的名词**（面试必问）：

| 名词 | 现象 | 例子 |
|---|---|---|
| **脏读** | 读到了别人**没提交**的改动 | A 把余额改成 700 还没提交，B 就看到了 700；A 一反悔 rollback，B 手上那个 700 是"脏"的 |
| **不可重复读** | 同一事务里两次读同一条，值变了 | A 第一次读余额 1000，B 转走 300 并提交，A 再读变 700（**同一行**变了）|
| **幻读** | 同一事务里两次查"一批"行，**行数**变了 | A 查"一班有 3 人"，B 插进 1 人并提交，A 再查变 4 人（**多出来了**）|

**怎么写代码**：

```java
// 看当前级别：MySQL 默认是 4（REPEATABLE READ）
System.out.println(conn.getTransactionIsolation());

// 改级别
conn.setTransactionIsolation(Connection.TRANSACTION_READ_COMMITTED);

// 翻译成人话（值就是 1/2/4/8，别背数字，用常量比）
static String levelName(int level) {
    if (level == Connection.TRANSACTION_READ_UNCOMMITTED) return "READ UNCOMMITTED";
    if (level == Connection.TRANSACTION_READ_COMMITTED)   return "READ COMMITTED";
    if (level == Connection.TRANSACTION_REPEATABLE_READ)  return "REPEATABLE READ";
    if (level == Connection.TRANSACTION_SERIALIZABLE)     return "SERIALIZABLE";
    return "未知";
}
```

> 💡 **"自己能看到自己没提交的改动，别人看不到"** —— 这就是隔离性最直观的样子。今天 Ex3 你会亲眼看到：A 改了张三的余额还没提交时，A 自己读到新值，B 读到的还是旧值（MySQL 的可重复读快照）。

### 顺带：乐观锁 vs 悲观锁（了解，面试常聊）

- **悲观锁**：改之前先锁住这行 → `SELECT ... FOR UPDATE`（别人要改就得等）
- **乐观锁**：不锁，改的时候带上版本号 → `UPDATE ... SET balance = ?, version = version + 1 WHERE id = ? AND version = ?`，返回 0 就是"被人抢先改了，重来"
- 转账这种"必须串行"的场景，MySQL 的 UPDATE 本身就会加行锁；`FOR UPDATE` 是提前锁

## 6. ⭐ 连接池：为什么不用 `DriverManager` 每次新建

```java
// 每次都这样 —— 每次都要走"TCP 连接 + 握手 + 认证"
Connection conn = DriverManager.getConnection(URL, USER, PWD);
```

| | `DriverManager` 每次新建 | 连接池 |
|---|---|---|
| 成本 | 每个请求几十毫秒都在**建连接** | 拿一个**已经连好**的（微秒级） |
| 连接数 | 1000 个请求 = 1000 个连接，MySQL 直接被打爆 | 固定 10 个连接循环用 |
| 项目里 | 只在学习/脚本里用 | **一律用池**（HikariCP / Druid）|

**池子的工作方式**（就是 Ex4 你要手写的东西）：

```
启动时：先建好 N 个连接存起来（预热）
借：  getConnection()  → 从空闲列表里拿一个
还：  close()          → 不是真关闭，是"放回空闲列表"
```

**最妙的一手在"还"**：真连接如果被你 `close()` 了就废了，所以池子借给你的其实是**一层壳（代理对象）**：

```java
// 池子返回的"壳"：长得像 Connection，但 close() 被换成了"还回池子"
return (Connection) Proxy.newProxyInstance(
        Connection.class.getClassLoader(),
        new Class<?>[]{Connection.class},
        (proxy, method, methodArgs) -> {
            if (method.getName().equals("close")) {
                idle.add(real);                 // 只拦截 close
                return null;
            }
            return method.invoke(real, methodArgs);   // 其余方法原样转发给真连接
        });
```

> 这就是 HikariCP / Druid 的核心把戏（叫**动态代理包装**）。你不用会写 `Proxy`，但要理解**"借出去的是壳，真连接留在池里"**。
> 等你上 SpringBoot：`dataSource.getConnection()` 拿到的就是这种壳，**业务代码一行都不用改**——这就是"面向接口编程"的价值。

**⚠️ 一个反直觉的实测结果**（你会亲眼看到）：包了壳之后，`c5 == c2`、`a == b` **全是 `false`**，连 `equals` 也是 `false`——
因为**壳是每次借的时候现做的**（真连接被复用了，但壳每次都是新对象）。
所以想证明"连接被复用了"，要看的是**池子剩下几个**（借 3 个 → 剩 0；还 1 个 → 剩 1；再借 → 剩 0），而不是拿对象比。
**对象相等 ≠ 资源复用**——这一点想通了，动态代理就懂了。

**真实项目里的配置项**（认识一下就行）：`maximumPoolSize`（最多几个）、`minimumIdle`（最少留几个）、`connectionTimeout`（借不到等多久报错）。

## 7. 分页：`LIMIT ? OFFSET ?`

```sql
SELECT name, score, class_name FROM student ORDER BY id LIMIT ? OFFSET ?
--  每页 3 条：
--  第 1 页 → LIMIT 3 OFFSET 0
--  第 2 页 → LIMIT 3 OFFSET 3
--  第 3 页 → LIMIT 3 OFFSET 6
```

```java
int offset = (pageNo - 1) * pageSize;   // ← 公式记住
```

- ⚠️ **必须带 `ORDER BY`**：不排序时数据库返回的行序**没有保证**，翻页会出现"同一条出现在两页/漏掉"
- 超出范围（比如 10 个人看第 9 页）→ 返回**空 List**，不是报错
