# Day 10 知识点：Object 类 + 常用方法（toString / equals / hashCode）

> 前提：Day 7~9 的继承、多态、接口都过关了。今天是"所有类的老祖宗"专场——Object 类，和后端天天打的三个方法。

## 1. 万物皆 Object

类图上所有类的顶端站着一位"老祖宗"：**Object 类**。
- 你写的每个类，就算没写 `extends`，也**自动继承 Object**（编译器偷偷加的）
- 所以 `class Student { ... }` 其实等于 `class Student extends Object`
- 结论：**Object 里的方法，任何类都有**——因为继承！我们随便拿几个开刀

## 2. toString()：对象变字符串（天天用）

**作用**：把一个对象转成能看的字符串。
**默认行为**：输出 `类名@一堆乱码`（其实是内存地址的哈希）——人类看不懂。
**正确用法**：**重写 toString()**，让它返回有用的信息。

```java
class Student {
    String name;
    int studentId;
    // ...构造方法省略

    @Override
    public String toString() {
        return "姓名：" + name + "，学号：" + studentId;
    }
}

Student s = new Student("小明", 2025001);
System.out.println(s);        // 姓名：小明，学号：2025001（自动调 toString！）
System.out.println(s.toString()); // 跟上面一模一样
```

> ⚠️ **`System.out.println(对象)` 就是在偷偷调 `toString()`**——所以后端打印日志、调试，全靠它。

## 3. equals() vs ==：对象怎么"比相等"（面试高频坑）

| | `==` | `equals()` |
|---|---|---|
| 比什么 | **地址**（是不是同一个对象）| 默认**也是地址**；重写后比**内容** |
| 什么时候用 | 比基本类型（int/double）| 比对象内容 |
| String 特例 | `"a" == "a"` 可能是 true（常量池）| String 重写了 equals → 比内容 |

```java
String a = "hello";
String b = "hello";
String c = new String("hello");
System.out.println(a == b);   // true（两个字面量，共用一个常量池对象）
System.out.println(a == c);   // false（c 是 new 出来的新对象，地址不同！）
System.out.println(a.equals(c)); // true（String 重写了 equals，比内容）
```

> **铁律：比字符串内容永远用 `equals`，别用 `==`！**

**重写 equals 的正确姿势**（参数必须是 `Object`，写成别的就是重载不是重写）：

```java
@Override
public boolean equals(Object o) {
    if (o instanceof Student) {        // 先判断类型对不对
        Student s = (Student) o;       // 再向下转型
        return name.equals(s.name) && studentId == s.studentId;  // 逐项比内容
    }
    return false;
}
```

## 4. hashCode()：对象的"数字指纹"

**作用**：把对象算成一个**整数**。这个数字后面 HashMap（Day 13）用它来"秒找"对象。
**规则（必须背）**：**equals 相等的两个对象，hashCode 必须相等**（反之不要求）。
**简单实现版**：

```java
@Override
public int hashCode() {
    return name.hashCode() + studentId;   // 简单但符合规则
}
```

> 实际项目不用手写，用 `Objects.hash(name, studentId)`（JDK7+），一行搞定——你现在先用简单版理解原理。

## 5. getClass()：运行时拿"真实类型"

**作用**：返回对象**运行时真正的类**——多态"运行看右边"的实锤：

```java
Animal a = new Dog("旺财");
System.out.println(a.getClass().getName()); // Dog（不是 Animal！）
System.out.println(a instanceof Dog);       // true（沿着继承链找）
System.out.println(a instanceof Animal);    // true（父类也算）
```

> `getClass()` 拿到的是"右边"真实类型；`instanceof` 问的是"是不是这个类型或它的子孙"。

## 6. 常见坑清单（记住）

1. `System.out.println(obj)` 打出一堆 `类名@16进制` 乱码 → **没重写 toString**
2. 比字符串内容**必须 `equals`**，`==` 比的是地址，`new String("a") == "a"` 是 false
3. 重写 equals 时**参数必须写 `Object`**——写成 `equals(Student o)` 是重载，Java 不认！
4. 重写 equals 的**类型判断**：`o instanceof Student` 不能少，否则 `equals(别的东西)` 会崩
5. **重写了 equals 就必须重写 hashCode**——违反"相等对象哈希必相等"规则，HashMap 会出诡异 bug
6. 基本类型比较用 `==`（int/double），别用 equals
