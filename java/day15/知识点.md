# Day 15 知识点：异常处理（try / catch / finally）

> 前提：集合家族已通关。今天学程序"防翻车"的本事——出错了不崩溃、还能优雅收场。**这是简历面试必问题**。

## 1. 为什么需要异常

程序运行时的错误（除零、数组越界、数字格式错、文件不存在）如果不处理，程序会直接崩溃退出（红字堆栈一大堆）。
**异常处理 = 把错误"接住"，让程序继续跑**，或者给出友好提示。

## 2. 基本结构

```java
try {
    int r = 10 / 0;          // 可能"翻车"的代码放这里
    System.out.println(r);   // 出错了，这行不会执行！
} catch (ArithmeticException e) {
    System.out.println("除零了，我接住了");   // 翻车后走这里
} finally {
    System.out.println("清理工作");            // 无论翻不翻车都执行
}
```4
- **try**：可能出错的代码
- **catch**：接住指定类型的异常（可以有多个 catch）
- **finally**：**不管出没出错都执行**（关文件、断连接放这里）

## 3. 常见异常类型（背下来）

| 异常 | 什么时候抛出 | 例子 |
|---|---|---|
| `ArithmeticException` | 数学错误 | 除以 0 |
| `ArrayIndexOutOfBoundsException` | 数组越界 | `arr[10]` 而数组只有 3 个 |
| `NumberFormatException` | 字符串转数字失败 | `Integer.parseInt("abc")` |
| `NullPointerException` | 调了 null 对象的方法 | `s.length()` 而 s 是 null |

## 4. 一个 try 多个 catch

```java
try {
    int x = arr[i];
} catch (ArrayIndexOutOfBoundsException e) {
    System.out.println("越界");
} catch (NullPointerException e) {
    System.out.println("数组是空的");
}
```

> catch 从上往下匹配——**范围小的异常写前面**（父子关系时尤其注意）。

## 5. 异常会"向上抛"

方法里没接住，就抛给调用者；调用者也没接住，一路抛到 main → 崩。
所以"在哪一层接住"是设计问题——今天的练习统一练**在本方法内接住**。

## 6. 面试加分点

- 多 catch 的匹配顺序、finally 的用途
- 别用异常当"正常流程控制"（性能差、代码难看）
- 进阶：try-with-resources（`try(资源){...}` 自动关资源，以后 IO 流会遇到）
