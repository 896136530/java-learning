## 0. 名词速查

| 词 | 人话 | 比喻 |
|---|---|---|
| MyBatis | 一个"SQL 映射框架"：SQL 写在 XML 里，结果自动变成 Java 对象 | 点菜员：你写菜单（SQL），它把菜端到桌上摆好（对象）|
| `SqlSessionFactory` | 读配置、建连接池的"总工厂"，**全项目一个** | 一家餐厅的总店，只开一次 |
| `SqlSession` | 一次会话（≈ 一个数据库连接 + 一次事务），**用完必须关** | 一次点餐服务 |
| Mapper 接口 | 只有方法签名、没有实现的接口 | 菜单上的菜名 |
| `namespace` | XML 开头那个全限定名，**必须等于接口全名** | 菜名和菜单必须对得上号 |
| `#{}` | 占位符，变成 SQL 里的 `?`，值走 `setString` | 填空：答案是"内容"，不会被当命令 |
| `${}` | **字符串直接拼进 SQL**，危险 | 把客人说的话直接当成命令念出来 |
| `resultMap` | 手动写"列名 → 属性名"的对照表 | 翻译表 |
| `association` | 一对一关联（一个学生 → 一个班级）| 学生档案里夹一张班级名片 |
| `typeAlias` | 给实体类起短名，XML 里不用写全限定名 | 外号 |
| 动态代理 | MyBatis 在运行时给 Mapper 接口"变"出一个实现类 | 你只报菜名，后厨自动接单 |

## 1. 为什么要有 MyBatis：先看 JDBC 有多烦

Day21 你写过：`DriverManager → Connection → PreparedStatement → setXxx → ResultSet → rs.next() → 拼对象 → 关三个资源`。
一条查询 30 行，**一半在干杂活**（关资源、取值、拼对象），换个表就再抄一遍。

MyBatis 把杂活接走了，只留三件事给你：**SQL、参数、返回值**。

| | 纯 JDBC | MyBatis |
|---|---|---|
| SQL 放哪 | 散落在 Java 代码里 | 集中在 XML（或注解）|
| 参数 | 手动 `setInt/setString` | `#{name}` 自动对应 |
| 结果 | 手动 `rs.getString` 拼对象 | 自动映射成对象 |
| 关资源 | 自己 try-with-resources | 框架管 |
| 换表 | 再抄一遍 | 加一个 `<select>` |

## 2. 三件套：配置 + XML + 接口

```
mybatis-config.xml        全局：连哪个库、日志、mapper 在哪
mapper/StudentMapper.xml  一条 SQL 一个 <select>/<insert>
mapper/StudentMapper.java 方法签名（方法名 = XML 里的 id）
```

### ① 全局配置（只写一次）

```xml
<environments default="dev">
  <environment id="dev">
    <transactionManager type="JDBC"/>       <!-- 不 commit 就回滚 -->
    <dataSource type="POOLED">              <!-- 自带连接池 -->
      <property name="url" value="jdbc:mysql://127.0.0.1:3306/day38?..."/>
      <property name="username" value="day38"/>
      <property name="password" value="day38"/>
    </dataSource>
  </environment>
</environments>
<mappers>
  <mapper resource="mapper/StudentMapper.xml"/>
</mappers>
```

### ② XML 里写 SQL

```xml
<mapper namespace="com.xiaoming.day38.mapper.StudentMapper">
    <select id="findById" resultMap="studentMap">
        SELECT id, name, score, cls_id, create_time FROM student WHERE id = #{id}
    </select>
</mapper>
```

### ③ 接口里写方法名

```java
public interface StudentMapper {
    Student findById(@Param("id") int id);
}
```

⭐ **对号规则**：`namespace` = 接口全名；`<select id="x">` 的方法名 = `x`；参数名靠 `@Param`。

### ④ 用起来

```java
try (SqlSession session = MyBatis.openSession()) {
    StudentMapper mapper = session.getMapper(StudentMapper.class);
    Student s = mapper.findById(3);     // 你以为在调接口，其实是 MyBatis 造的代理在执行 SQL
}
```

真机输出：

```
Student{id=3, name='王五', score=76, clsId=2, 班级=-}
查不到时返回：null
```

## 3. `#{}` vs `${}`：今天最该记住的一条

| | `#{}` | `${}` |
|---|---|---|
| 变成什么 | SQL 里的 `?`（占位符）| **直接拼成字符串** |
| 参数怎么传 | `setString` 等，值只是数据 | 值会成为 SQL 的一部分 |
| 注入 | 安全 | **危险** |
| 用途 | 所有**值** | 表名/列名/排序字段（且必须白名单校验）|

### 真机演示（项目里第 4 个示例）

传进去 `' OR '1'='1`：

```
${} 版本 → 实际执行 SQL：... WHERE name LIKE '%' OR '1'='1%'
           返回 8 行（整表都出来了）
#{} 版本 → 实际执行 SQL：... WHERE name LIKE CONCAT('%', ?, '%')
           参数：' OR '1'='1
           返回 0 行 ✅
```

⭐ 记住：**值一律用 `#{}`；只有"结构性"的东西（表名、列名、`ORDER BY` 的字段名）才可能用 `${}`，并且必须拿白名单卡死**。

## 4. 映射：列名和属性名对不上怎么办

两套办法，今天都用了：

| 办法 | 怎么写 | 什么时候用 |
|---|---|---|
| 全局驼峰 | 配置 `<setting name="mapUnderscoreToCamelCase" value="true"/>` | `cls_id → clsId`、`create_time → createTime` |
| `resultMap` | 一个个写 `<result column="cls_id" property="clsId"/>` | 名字完全对不上、要复用、联表时 |

```xml
<resultMap id="studentMap" type="Student">
    <id     column="id"          property="id"/>
    <result column="cls_id"      property="clsId"/>
    ...
</resultMap>
```

⚠️ 注意：`SELECT` 的**列必须出现在结果里**，否则那个属性是 `null`（不报错，最容易静默出错）。

## 5. 联表：`association`（一对一）

需求：查学生时**一起把班级名和老师带出来**。

```xml
<resultMap id="studentWithClass" type="Student" extends="studentMap">
    <association property="classInfo" javaType="ClassInfo">
        <id     column="c_id"      property="id"/>
        <result column="c_name"    property="name"/>
        <result column="c_teacher" property="teacher"/>
    </association>
</resultMap>

<select id="findAllWithClass" resultMap="studentWithClass">
    SELECT s.id, s.name, s.score, s.cls_id, s.create_time,
           c.id AS c_id, c.name AS c_name, c.teacher AS c_teacher
    FROM student s LEFT JOIN class_info c ON s.cls_id = c.id
</select>
```

真机输出：

```
Student{id=5, name='钱七', score=100, clsId=3, 班级=三班/赵老师}
Student{id=2, name='李四', score=95, clsId=1, 班级=一班/王老师}
```

⭐ 要点：联表时**右表的列要起别名**（`c_id`/`c_name`），否则和左表同名列打架（`id`、`name` 两张表都有）。

## 6. MyBatis vs JPA vs 纯 JDBC（面试会问）

| | 纯 JDBC | MyBatis | JPA / Hibernate |
|---|---|---|---|
| SQL 谁写 | 你 | **你** | 框架生成（也可写）|
| 映射 | 手工 | XML/注解配置 | 注解自动 |
| 灵活度 | 最高、最啰嗦 | 高、可控 | 低（复杂查询要写 JPQL/原生 SQL）|
| 学习成本 | 低但杂活多 | 中 | 高（缓存、延迟加载、脏检查）|
| 国内招聘 | 基础 | **主流**（尤其 MyBatis-Plus）| 外企/部分公司 |

⭐ 一句话：**JDBC 是手动挡，MyBatis 是半自动，JPA 是全自动**。国内后端面试问 MyBatis 远多于 JPA。

## 7. 常见坑（今天会遇到的）

| # | 坑 | 现象 / 修法 |
|---|---|---|
| 1 | `namespace` 写错或 id 和方法名不一致 | `Invalid bound statement (not found): ...findByScore` |
| 2 | mappers 里漏配 XML | 同上，启动时不报、调用时才炸 |
| 3 | 参数没加 `@Param`，XML 里用 `#{min}` | `Parameter 'min' not found. Available parameters are [...]` |
| 4 | 用 `${}` 传值 | 注入（今天演示：8 行全出来）|
| 5 | `SELECT` 少查一列 | 属性是 `null`，不报错 |
| 6 | 忘了 `session.commit()` | 数据没进去（今天故意不提交，跑多少遍库都不变）|
| 7 | `SqlSession` 当成员变量共用 | 它不是线程安全的，用完就关 |
| 8 | 列名和属性名对不上又没配驼峰/resultMap | 属性 `null` |
