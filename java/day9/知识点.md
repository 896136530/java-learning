# Day 9 知识点：抽象类 + 接口（多态的"进阶形态"）

> 前提：Day 8 多态过关。今天学的是"多态的两件武器"：抽象类和接口，也是 Spring 框架的地基。

## 1. 为什么需要抽象方法

多态有个解决不了的尴尬：父类有些方法，**没法写具体实现**。
- "动物都会吃东西" —— 但"怎么吃"？狗啃、猫舔、鸟啄，父类根本写不出来
- 方案：父类只**声明**"有这个功能"，具体怎么干交给子类 —— 这就是**抽象方法**

```java
abstract void eat();   // 只有"声明"，没有大括号实现
```

## 2. 抽象方法 vs 普通方法

| | 普通方法 | 抽象方法 |
|---|---|---|
| 写法 | `void eat() { ... }` | `abstract void eat();` |
| 有没有实现 | ✅ 有 | ❌ 没有（光喊不做）|
| 谁来完成 | 自己 | 子类必须实现 |

## 3. 抽象类（abstract class）

- **含有抽象方法的类 = 抽象类**（`abstract class`）
- **不能 new**：抽象类没有实物，new 出来没意义（"动物"是概念，现实中只有狗猫鸟）
- 可以同时有普通方法、属性、构造方法（给子类用）+ 抽象方法
- 子类**必须实现所有抽象方法**（否则编译报错，除非子类自己也是抽象类）
- 类比：**半成品图纸**——墙已经砌好了（普通方法），"装门的地方"留空（抽象方法），施工队（子类）按自己风格补上

```java
abstract class Animal {
    String name;
    Animal(String name) { this.name = name; }
    void sleep() { System.out.println(name + "在睡觉"); }  // 普通方法：已经写好
    abstract void eat();  // 抽象方法：留空，子类实现
}

class Dog extends Animal {
    Dog(String name) { super(name); }
    @Override
    void eat() { System.out.println(name + "啃骨头"); }   // 补上抽象方法
}
```

## 4. 接口（interface）

- 接口 = **纯合同 / 纯说明书**：只规定"必须会什么"，**不能有任何实现**
- 用法：`class 类名 implements 接口名`
- 接口里的方法**自动是** `public abstract`（不写也默认）
- **一个类可以实现多个接口** —— 弥补 Java 单继承的不足！
- 类比：**USB 接口**——手机、相机、键盘、鼠标，只要符合 USB 标准就能插；接口只关心"能不能充电/传数据"，不关心你是什么东西

```java
interface Flyable {
    void fly();   // 自动是 public abstract，可省略不写
}

class Bird implements Flyable {
    // ⚠️ 注意：实现接口方法必须写 public！
    public void fly() { System.out.println("扇翅膀飞了"); }
}
```

## 5. 抽象类 vs 接口（面试高频！背下来）

| | 抽象类 | 接口 |
|---|---|---|
| 关键字 | `extends` | `implements` |
| 能来几个 | 只能继承**一个** | 可以实现**多个** |
| 方法 | 可以有实现 | 全是抽象（JDK8 前规则）|
| 属性 | 普通变量 | 只能是常量（默认 public static final）|
| 构造方法 | 有 | 没有 |
| 语义 | **"是什么"**（is-a）| **"能干什么"**（can-do）|
| 例子 | 学生是"人" | 学生能"跑"、能"说话" |

**选哪个？口诀：抽象类管身份，接口管能力。**
- 是"你的一部分"（猫是动物）→ 继承抽象类
- 是"你的一项技能"（猫会叫、会抓老鼠）→ 实现接口
- 实际开发：**优先用接口**——一个类可以灵活"叠加能力"，不占继承名额

## 6. 接口多态（Day 8 知识直接复用）

接口引用可以指向实现类对象，照样是"编译看左边，运行看右边"：

```java
Flyable f = new Bird("麻雀");   // 接口引用 → 实现类对象
f.fly();                        // 麻雀扇翅膀飞了（运行看右边）
```

接口当方法参数 → 一个方法通吃所有实现类（练习题 5 会用到）。

## 7. 常见坑清单（记住）

1. **抽象类不能 new**：`new Animal(...)` 编译报错
2. 子类没实现全部抽象方法 → 编译报错（除非子类自己也 abstract）
3. **实现接口的方法必须写 `public`**：写 `void fly()` 不写 public → 编译报错（attempting to assign weaker access privileges）
4. 接口没有构造方法，`new 接口名()` 也是编译报错
5. 一个类只能 extends 一个父类，但可以 implements 好几个接口
6. 抽象方法没有方法体：写 `abstract void eat() {}`（带大括号）也是错的
7. 类里只要有 1 个抽象方法，这个类必须是 abstract

## 8. 一句话总结 + 明天预告

> **抽象类 = "半成品图纸"（是什么），接口 = "合同 / USB 标准"（能干什么）。**
> Spring 的世界就是接口的世界——控制器、Service、DAO 全用接口定义，实现类随便换。
