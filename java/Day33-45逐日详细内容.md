# Day 33 ｜ 拦截器 / 过滤器 ⭐

**一句话**：请求进 Controller **之前**和**之后**，插入你自己的逻辑（记日志、查登录）。

### 要学的知识点

1. **Filter（属于 Servlet 规范，跟 Spring 无关）**
   - 接口 `Filter`，核心方法 `doFilter(ServletRequest, ServletResponse, FilterChain)`
   - `chain.doFilter(req, res)` = 放行；**不调用它 = 直接拦死**（后面谁都不执行）
   - 还有 `init()` 初始化、`destroy()` 销毁
   - 两种注册方式：`@WebFilter("/*")` + 启动类 `@ServletComponentScan`；或 `FilterRegistrationBean`（能设 `setOrder` 控制顺序）
   - **执行时机：在 `DispatcherServlet` 之前**，所以它连"要访问哪个 Controller"都不知道

2. **Interceptor（属于 Spring MVC）**
   - 接口 `HandlerInterceptor`，三个方法：
     - `preHandle`：Controller **执行前**。返回 `true` 放行、`false` **中断**（直接返回，后面的都不走）
     - `postHandle`：Controller 执行完、**视图渲染之前**。⚠️ 你写的是 `@RestController`（`@ResponseBody`），**基本用不上这个方法**
     - `afterCompletion`：**请求全部结束、无论成功还是抛异常都会执行** ← **清理 ThreadLocal 必须写这里**
   - 注册：`WebMvcConfigurer#addInterceptors` → `registry.addInterceptor(x).addPathPatterns("/**").excludePathPatterns("/login")`

3. **执行顺序（面试必问，背下来）**
   ```
   Filter → DispatcherServlet → Interceptor.preHandle
     → Controller → Interceptor.postHandle（视图渲染前）
     → 视图渲染 → Interceptor.afterCompletion → Filter 返回
   ```
   - 多个 Interceptor 时：`preHandle` **正序**执行，`postHandle` / `afterCompletion` **倒序**执行

4. **Filter vs Interceptor 的区别（面试高频，至少答 3 条）**
   | | Filter | Interceptor |
   |---|---|---|
   | 归属 | Servlet 容器（Tomcat） | Spring 容器 |
   | 能注入 Bean 吗 | 能（但用 `@WebFilter` 注册时容易拿不到） | 能，天然是 Spring Bean |
   | 能拿到 Controller 方法吗 | **不能** | **能**（`preHandle` 的 `HandlerMethod` 参数 → 能读方法上的注解） |
   | 触发范围 | 所有请求（含静态资源） | 只拦 DispatcherServlet 处理的请求 |

5. **典型应用**
   - 日志：记录 URI、耗时、参数（`preHandle` 记开始时间，`afterCompletion` 算耗时）
   - 登录校验：从 Header 取 token → 校验 → 不通就 `response.setStatus(401)` 并 return false
   - 跨域 CORS：`CorsFilter` 或 `addCorsMappings`

### 易错点 / 面试点
- 拦截器里 `@Autowired` 的 Bean 是 **null** → 因为拦截器是你 `new` 出来的，没交给 Spring；要用 `@Bean` 注册或让它成为 Spring Bean
- `excludePathPatterns("/login")` 写错 → 实际路径是 `/api/login`，白名单没生效，登录接口自己被拦
- `postHandle` 里改 `ModelAndView` 对 REST 接口**完全无效**
- `afterCompletion` 里能拿到异常（第 4 个参数 `Exception ex`），但**捕获不到 `preHandle` 自己抛的异常**

### ✅ 过关标准
1. 能写一个**记录请求耗时**的 Filter
2. 能写一个**做登录校验**的 Interceptor（含白名单）
3. 能**口述那 5 步执行顺序**，不看书
4. 能答出 Filter vs Interceptor 的区别（≥3 条）

# Day 34 ｜ Spring 事务管理 `@Transactional` ✅ 已生成（2026-10-17）⭐⭐

> ✅ **这个空位已于 2026-10-17 用掉**（`java/day34/` 已生成、待练习）。选事务的理由：Day27 你手写过 JDBC 事务（`setAutoCommit` / `commit` / `rollback`），
> 现在正好学框架版；而且**面试必问"事务失效场景"**。

### 要学的知识点

1. **加在哪一层**：**Service 的方法上**（不是 Controller、不是 Mapper）
   - SpringBoot 自动开了 `@EnableTransactionManagement`，不用你手动加

2. **它底层是怎么工作的**（接 Day42 AOP 的预告）
   - AOP 动态代理包住你的方法 → 方法开始前 `setAutoCommit(false)`
   - 正常结束 → `commit()`；抛异常 → `rollback()`
   - 所以：**"事务生效"的本质是"你调用的是代理对象，不是原始对象"**

3. **7 种传播行为**（`Propagation`）—— 至少掌握前 4 个
   | 传播行为 | 含义 | 用在哪 |
   |---|---|---|
   | `REQUIRED`（**默认**） | 有事务就加入，没有就新建 | 绝大多数场景 |
   | `REQUIRES_NEW` | **挂起**外层事务，自己开一个新事务 | 记日志：主业务失败也想保留日志 |
   | `NESTED` | 嵌套事务（用保存点 `savepoint`） | 内层失败可单独回滚，外层仍可提交 |
   | `SUPPORTS` | 有就用，没有就**非事务**执行 | 查询方法 |
   | `MANDATORY` | 必须在事务里，否则报错 | 强制约束 |
   | `NOT_SUPPORTED` | 挂起外层，自己非事务执行 | 不想占用事务的操作 |
   | `NEVER` | 不能在事务里，否则报错 | 极少数 |

4. **回滚规则（超高频考点）**
   - 默认 **只对 `RuntimeException` 和 `Error` 回滚**
   - **受检异常（`Exception` 的子类但不是 `RuntimeException`）默认不回滚！**
   - 要回滚受检异常 → 必须写 `@Transactional(rollbackFor = Exception.class)`

5. **事务失效的 6 个场景（面试必背）**
   1. **同类内部方法直接调用**（`this.method()`）→ 不走代理 ← 最经典
   2. 方法**不是 `public`**（`private` / `protected` / 包级）
   3. 异常被你自己 **try-catch 吃掉了**（没往外抛，Spring 不知道出事了）
   4. 数据库引擎**不支持事务**（MySQL 的 MyISAM）
   5. **多线程**里调用（事务信息绑在 `ThreadLocal` 上，子线程拿不到）
   6. 这个类**没被 Spring 管理**（你自己 `new` 出来的）

6. **和 Day27 手写版对比**
   ```java
   // Day27 手动版
   conn.setAutoCommit(false);
   try { ...; conn.commit(); } catch (Exception e) { conn.rollback(); }
   ```
   ```java
   // 现在声明式版
   @Transactional(rollbackFor = Exception.class)
   public void transfer(...) { ... }
   ```

### ✅ 过关标准
1. 能默写 7 种传播行为里的**前 4 个**并说出区别
2. 能**背出 6 个失效场景**
3. 能故意写一个"**自己调用自己导致事务失效**"的 demo，并解释为什么失效
4. 能说出 `rollbackFor` 不写会踩什么坑

# Day 35 ｜ 换真 MySQL（H2 → MySQL）+ 还"数据库约束"的债 ⭐

**一句话**：把 Day30 那个用 H2 内存库的项目，跑在真的 MySQL 上；同时把 Day32 欠下的"约束/唯一索引"补上。

### 要学的知识点

1. **装 MySQL 8 / 或用 Docker 起一个**；建库、建表、建用户
2. **改配置** `application.yml`
   ```yaml
   spring:
     datasource:
       url: jdbc:mysql://localhost:3306/你的库?useSSL=false&serverTimezone=Asia/Shanghai&characterEncoding=utf8mb4
       username: root
       password: 你的密码
       driver-class-name: com.mysql.cj.jdbc.Driver
   ```
   - 常见坑：`serverTimezone` 不写会报时区错；`useSSL` 不写有警告
3. **连接池（SpringBoot 默认 HikariCP）**—— 面试常问
   - 为什么不能"每次请求新建连接"：TCP 三次握手 + MySQL 鉴权开销太大
   - 关键参数：`maximum-pool-size`（默认 10）、`minimum-idle`、`connection-timeout`、`max-lifetime`
   - 池子耗尽的典型报错：`Connection is not available, request timed out`
4. **数据库约束**（⭐ 这是 Day32 记下的债，今天还）
   - `NOT NULL` / `DEFAULT` / `PRIMARY KEY` / `UNIQUE` / `FOREIGN KEY` / `CHECK`
   - **唯一约束 vs 唯一索引**：在 MySQL 里建 `UNIQUE` 约束就是建唯一索引，本质一回事
   - **联合唯一索引**：`UNIQUE KEY uk_user_date (user_id, day)` → 同一个用户同一天只能有一条
5. **逻辑删除 vs 物理删除**（项目里几乎必用）
   - `is_deleted TINYINT DEFAULT 0`；查询都带 `and is_deleted = 0`；`DELETE` 改成 `UPDATE`
6. **字段类型怎么选**
   - 金额：**`DECIMAL(10,2)`，绝对不要用 `float` / `double`**（精度丢失）
   - `VARCHAR(n)`：n 是**字符数**不是字节数；按实际最长 + 余量定
   - `DATETIME` vs `TIMESTAMP`：`TIMESTAMP` 有时区转换 + 2038 问题
   - 主键：`BIGINT AUTO_INCREMENT` 或雪花 ID
7. **字符集坑**：`utf8` 在 MySQL 里是**假的 UTF-8（最多 3 字节，存不了 emoji）** → **一律用 `utf8mb4`**
8. **H2 → MySQL 的差异**：自增写法、大小写敏感（Linux 上 MySQL 表名大小写敏感）、`LIMIT` 语法、保留字

### ✅ 过关标准
1. 能把 Day30 的项目**跑在真 MySQL 上**，接口全部照常工作
2. 能写出一份含**主键 / 唯一 / 非空 / 默认值 / 外键 / 联合唯一索引**的建表 SQL
3. 能说清 `utf8` 与 `utf8mb4`、`DECIMAL` 与 `DOUBLE` 的区别
4. 能说出连接池解决什么问题、池子耗尽的报错长什么样

# Day 36 ｜ MySQL 索引（一）：B+ 树 / 聚簇索引 / 最左前缀 ⭐⭐⭐

**一句话**：MySQL 为什么快？全靠索引。**这章是面试问得比 JVM 还勤的东西。**

### 要学的知识点

1. **索引是什么**：一种**排好序**的数据结构（InnoDB 用 **B+ 树**）
2. **为什么是 B+ 树**（面试必问，要能对比）
   - vs **二叉树 / 红黑树**：数据量大时树太高 → 磁盘 IO 次数多
   - vs **B 树**：B 树每个节点都存数据 → 同样高度装得少；B+ 树**只有叶子存数据**，非叶子只存索引 → **一层能放几百上千个 key → 树更"矮胖"**
   - vs **哈希**：哈希只能等值查询，**不支持范围查询和排序**
   - B+ 树**叶子节点用双向链表串起来** → 范围查询（`between` / `>`）只需顺着链表扫
3. **三层 B+ 树能存多少**：一层约 1170 个 key，三层约 **2000 万行** → 查任意一行最多 **3 次磁盘 IO**（这个推算要会）
4. **聚簇索引 vs 二级索引（核心！）**
   - **聚簇索引（主键索引）**：叶子节点直接存**整行数据**。所以"按主键查"最快，**不用回表**
   - **二级索引（普通/唯一索引）**：叶子节点存的是**主键值**，不是整行！
     → 所以用二级索引查别的列，得**先找到主键、再拿主键去聚簇索引查整行** = **回表**
   - 推论：**没有主键的表**，InnoDB 会隐式建一个 6 字节的 `row_id` 当聚簇索引
5. **索引类型**：主键索引 / 唯一索引 / 普通索引 / **联合索引（组合索引）** / 全文索引
6. **最左前缀原则**（面试必考）
   - 建了联合索引 `idx_a_b_c (a, b, c)`：
     - ✅ 能用：`where a=?`、`where a=? and b=?`、`where a=? and b=? and c=?`
     - ✅ 部分能用：`where a=? and c=?` → 只用到 `a`
     - ❌ 不能用：`where b=?`、`where b=? and c=?`、`where c=?`
   - **范围查询会截断后面的列**：`where a=? and b>? and c=?` → `c` 用不上索引
   - `order by` 也要满足最左前缀，否则出现 `Using filesort`
7. **索引失效的常见场景（至少背 6 个）**
   1. **`like '%xxx'`** 前置百分号（`like 'xxx%'` 可以）
   2. **对索引列做函数/运算**：`where YEAR(create_time)=2026`、`where id+1=5`
   3. **隐式类型转换**：`phone` 是 `VARCHAR`，你写 `where phone = 13800000000`（整数）→ 失效
   4. **`or` 连接的列有一个没索引** → 整个失效
   5. **联合索引不满足最左前缀**
   6. **`is null` / `is not null`**（取决于 null 的比例）
   7. `!=` / `not in` / `not exists`（**有时**失效，看优化器成本估算）
   8. 优化器**觉得全表扫更快**（表太小、区分度太低）→ 主动放弃索引

### ✅ 过关标准
1. 能**手画一棵 B+ 树**并解释"为什么三层能撑 2000 万行"
2. 能说清**聚簇索引和二级索引的叶子节点分别存什么**、什么是回表
3. 给你联合索引 `(a,b,c)` 和 8 条 SQL，能**逐条判断走不走索引**
4. 能背出 **≥6 个索引失效场景**

# Day 37 ｜ MySQL 索引（二）：EXPLAIN / 慢日志 / 覆盖索引 ⭐⭐⭐

**一句话**：昨天懂原理，今天**用工具证明**索引有没有生效，并把慢 SQL 改快。

### 要学的知识点

1. **`EXPLAIN` 每一列（重点看 4 列）**
   - `id`：执行顺序（越大越先；相同则从上到下）
   - `select_type`：`SIMPLE` / `PRIMARY` / `SUBQUERY` / `DERIVED`
   - **`type`（最重要）**：性能从好到坏
     `system > const > eq_ref > ref > range > index > ALL`
     - `const`：主键/唯一索引等值 → 最快
     - `ref`：普通索引等值
     - `range`：范围查询（`between` / `>` / `in`）
     - `index`：扫整个索引树（比 ALL 好一点，但**仍然是全扫**）
     - **`ALL`：全表扫 → 必须优化**
   - `possible_keys`（可能用的）vs **`key`（实际用的）** ← `key` 是 `NULL` 就说明**没用上索引**
   - `key_len`：**用来判断联合索引实际用了几个列**（`VARCHAR(10)` utf8mb4 非空 = 40 字节；可空 +1）
   - `rows`：预估扫描行数（越小越好）
   - `filtered`：过滤后剩余百分比
   - **`Extra`**：
     - **`Using index`** ✅ = **覆盖索引**，不用回表
     - `Using where` = 用上了 where 过滤（正常）
     - **`Using filesort`** ❌ = 排序没走索引，需要优化
     - **`Using temporary`** ❌ = 用了临时表（常见于 `group by` / `distinct`）
2. **覆盖索引（Covering Index）**
   - 定义：**要查的列全都在索引里** → 不用回表
   - 例：`select id, name from user where name='x'`（`name` 上有索引，`id` 是主键本来就在二级索引叶子里）→ 覆盖索引
   - 例：`select id, name, age from user where name='x'` → 要回表取 `age`
   - 怎么优化：把要查的列**加进联合索引**，比如 `idx_name_age (name, age)`
3. **慢查询日志**
   - 开启：`slow_query_log = ON`、`long_query_time = 1`（超过 1 秒记录）
   - 查看：`mysqldumpslow -s t 慢日志文件`（按耗时排序）
   - 更进一步：`pt-query-digest`（Percona 工具）
4. **区分度（选择性）**
   - `区分度 = count(distinct 列) / count(*)`
   - 越接近 1 越好；**区分度低（性别、状态标志位）不适合单独建索引**
   - 联合索引**把区分度高的列放前面**
5. **什么时候不该建索引**
   - 表数据太少（几百行，全扫更快）
   - **写多读少**的表（每次写都要维护索引）
   - 区分度太低的列
   - 频繁更新的列
   - `TEXT` / `BLOB` 大字段（要用**前缀索引** `index(col(10))`）
6. **联合索引顺序怎么定**：**等值查询的列在前，范围查询的列在后**

### ✅ 过关标准
1. 能读懂一条真实的 `EXPLAIN` 输出，**指出问题 + 说出优化方向**
2. 能解释"**覆盖索引为什么不用回表**"
3. 拿到一条慢 SQL，能说出**至少 2 种优化方案**
4. 能说出 `Using filesort` / `Using temporary` 分别意味着什么

# Day 38 ｜ MyBatis 基础（+ 和 JPA 正面对比）⭐⭐

**一句话**：国内 Java 后端**用得最多的 ORM**，SQL 你自己写，框架帮你做映射。

### 要学的知识点

1. **MyBatis 是什么**：**半自动 ORM**
   - 对比：JPA / Hibernate 是**全自动**（SQL 框架生成，你不管）；MyBatis 是**SQL 你自己写**，只帮你做"结果集 → 对象"的映射
   - 为什么国内用 MyBatis 多：**SQL 完全可控**、好优化、好排查、复杂查询好写
2. **接入**
   - 依赖 `mybatis-spring-boot-starter`
   - Mapper 接口加 `@Mapper`，或在启动类上 `@MapperScan("com.xxx.mapper")`
   - `application.yml`：
     ```yaml
     mybatis:
       mapper-locations: classpath:mapper/*.xml
       type-aliases-package: com.xxx.entity
       configuration:
         map-underscore-to-camel-case: true   # user_name → userName 自动映射
     ```
3. **Mapper 接口 ↔ XML 的对应关系**（必须刻在脑子里）
   - XML 的 `namespace` = **接口的全限定名**
   - XML 里每个 `<select id="xxx">` 的 `id` = **接口里的方法名**
   - `resultType` = 返回的元素类型（`List<User>` 写 `User`，不用写 `List`）
   - `parameterType` 可省略（MyBatis 能推断）
4. **`#{}` vs `${}`（重点 + 安全）**
   | | `#{}` | `${}` |
   |---|---|---|
   | 本质 | **预编译占位符 `?`** | **字符串直接拼接** |
   | 注入风险 | **没有** | **有！** |
   | 用在哪 | 参数值（99% 场景） | **表名 / 列名 / `order by` 字段**（且必须白名单校验） |
   - `${}` 注入例子：`order by ${sort}`，前端传 `id; drop table user--` → 灾难
5. **`resultMap`**：列名和属性名对不上时用
   ```xml
   <resultMap id="userMap" type="User">
     <id column="id" property="id"/>
     <result column="user_name" property="userName"/>
   </resultMap>
   ```
6. **参数与返回值**
   - 多参数：要么用 `@Param("name")`，要么用 `param1`/`param2`（**推荐 `@Param`**）
   - 返回单个对象 / `List` / `Map` / `int`（影响行数）
   - 拿自增主键：`useGeneratedKeys="true" keyProperty="id"`
7. **`jdbcType` 的坑**：参数为 `null` 时某些数据库要指定 `#{name, jdbcType=VARCHAR}`
8. **和 JPA 的对比表（面试可能问）**
   | 维度 | MyBatis | JPA / Hibernate |
   |---|---|---|
   | SQL 可控性 | **完全自己写**，最好优化 | 框架生成，复杂查询难控 |
   | 学习曲线 | 低（会 SQL 就会一半） | 高（要懂脏检查、缓存、延迟加载） |
   | 数据库移植性 | 差（SQL 是手写的） | 好（方言自动切换） |
   | 动态 SQL | **强**（`<if>` 等标签） | 弱（要 Criteria / Spec） |
   | 国内使用率 | **高** | 低（外企/老项目多） |

1. 能用 MyBatis 写完整的 **CRUD（XML 版）**，包括动态条件
2. 能说清 `#{}` / `${}` 区别，并**举一个 `${}` 注入的例子**
3. 能列出 **MyBatis vs JPA 至少 4 条区别**
4. 能说出 `namespace` / `id` / `resultType` 分别对应什么

# Day 39 ｜ MyBatis 动态 SQL + 关联映射 ⭐⭐

**一句话**：把"条件不固定的查询"用标签拼出来；把"表和表的关系"映射成对象。

### 要学的知识点

1. **`<if test="条件">`**：按条件拼 SQL
2. **`<where>`**：自动去掉开头多余的 `AND` / `OR`（不写它就得写 `where 1=1`）
3. **`<set>`**：更新时自动去掉**结尾多余的逗号**（不写它会 SQL 语法错）
4. **`<foreach>`**（最常用、最容易写错）
   ```xml
   <foreach collection="ids" item="id" open="(" separator="," close=")">
     #{id}
   </foreach>
   ```
   - `collection`：`List` 默认叫 `list`、数组叫 `array`、`@Param` 后叫参数名
   - 用在：`in` 查询、批量插入（`separator=","` + `values`）
5. **`<choose> / <when> / <otherwise>`**：相当于 Java 的 `switch-case-default`（只选一个分支）
6. **`<trim>`**：`<where>` / `<set>` 的底层，能自定义 `prefix` / `suffix` / `prefixOverrides`
7. **`<sql>` + `<include>`**：把重复的列名/条件抽成片段复用
8. **`test` 表达式的坑**
   - 判断字符串空：`test="name != null and name != ''"`
   - 字符串比较：`test="type == 'A'"`（**`'A'` 单引号 + 外层双引号**；写 `"A"` 会被当成数字比较）
   - `test="flag"` 对 `Boolean` 才安全；数字 `0` 可能被判成 false
9. **关联映射**
   - **一对一**：`<association property="idCard" javaType="IdCard">`（用户 → 身份证）
   - **一对多**：`<collection property="items" ofType="OrderItem">`（订单 → 订单项）
   - **多对多**：中间表 join（学生 ↔ 课程）
   - 两种写法：**嵌套查询**（`select` 属性，会触发 N+1）vs **嵌套结果**（一次 join 查完，推荐）
10. **N+1 问题**：查 1 个订单列表，每行再单独查一次明细 → 1 + N 次 SQL
    - 解法：① 用 join 一次查完（嵌套结果）② 开延迟加载 `fetchType="lazy"`（治标）

1. 能写一个"**3 个可选条件动态拼接 + `in` 批量查询 + 分页**"的 Mapper XML
2. 能说清 `<where>` 和 `<set>` **各自解决了什么问题**（不写会怎样）
3. 能解释 **N+1 问题**并说出 2 种解法
4. 能写出**一对多**的 `collection` 映射

# Day 40 ｜ MyBatis-Plus + 三层架构 + DTO/VO ⭐⭐

**一句话**：MP 让单表 CRUD 一行代码搞定；三层架构让你的项目"看起来像公司里写的"。

### 要学的知识点

1. **MyBatis-Plus（MP）是什么**：**只增强、不改变** MyBatis —— 你用 MP 也能写原生 XML
2. **`BaseMapper<T>`**：继承它就白拿 17 个方法
   - `insert` / `deleteById` / `updateById` / `selectById` / `selectList` / `selectCount` / `selectPage`
3. **`IService<T>` / `ServiceImpl<M, T>`**：Service 层也能白拿一批方法
4. **条件构造器（重点）**
   - `QueryWrapper<T>`：字段名字符串，**写错要到运行时才发现**
   - **`LambdaQueryWrapper<T>`（推荐）**：`User::getName`，编译期就能查错
   - 常用：`eq` / `ne` / `gt` / `ge` / `lt` / `le` / `like` / `likeRight` / `in` / `isNull` / `orderByDesc` / `and(w -> ...)` / `or(...)`
   - 更新：`LambdaUpdateWrapper` + `set`
5. **分页插件**
   ```java
   @Bean
   public MybatisPlusInterceptor mybatisPlusInterceptor() {
       MybatisPlusInterceptor i = new MybatisPlusInterceptor();
       i.addInnerInterceptor(new PaginationInnerInterceptor(DbType.MYSQL));
       return i;
   }
   ```
   - 用 `Page<User> page = new Page<>(1, 10);` + `selectPage(page, wrapper)` → 拿 `page.getRecords()` / `getTotal()`
   - 对比：`PageHelper`（MyBatis 的分页插件）和 MP 的分页插件是两套，别混
6. **主键策略**：`@TableId(type = IdType.AUTO)`（自增）/ `ASSIGN_ID`（雪花 ID）
7. **字段自动填充**：`@TableField(fill = FieldFill.INSERT)` + 实现 `MetaObjectHandler` → 自动填 `createTime` / `updateTime`
8. **逻辑删除**：`@TableLogic` + 全局配置 → `deleteById` 自动变成 `UPDATE ... SET deleted=1`
9. **⭐ 三层架构（这次要落地到项目里）**
   - **Controller**：只做「接参数 + 校验（`@Valid`）+ 调 Service + 返回 `Result<T>`」，**不写业务**
   - **Service**：业务逻辑 + 事务（`@Transactional`）—— 接口 + 实现类分离（`UserService` / `UserServiceImpl`）
   - **Mapper**：**只做数据访问**，不写业务
   - 为什么分层：职责单一、可测试、可复用（Day27 学的 DAO 分层是纯 JDBC 版，这次是框架版）
10. **⭐ DTO / VO / Entity 分层（面试爱问"为什么不能直接用实体接参数"）**
    - `User`（Entity）：对应数据库表
    - `UserDTO`（入参）：`UserCreateDTO`、`UserUpdateDTO` —— 前端只能传这些字段
    - `UserVO`（出参）：返回给前端，**能脱敏**（不返回密码）
    - **为什么必须分开**：如果直接用 `User` 接参数，前端可以塞 `role=admin` / `balance=999999` → **越权漏洞**（这叫"参数覆盖攻击"）
    - 转换：`BeanUtils.copyProperties(dto, entity)` —— ⚠️ 坑：**字段名不一致就静默丢掉**（不报错）

# Day 42 ｜ AOP + 自定义注解（`@RestControllerAdvice` 的底层原理）⭐⭐

**一句话**：把"和业务无关、但到处都要写"的代码（日志、事务、权限）抽出来，**不侵入业务代码**。

### 要学的知识点

1. **AOP 术语**（面试会问定义）
   - **切面 `@Aspect`**：横切逻辑的类
   - **切点 `@Pointcut`**：在哪里切（表达式）
   - **通知 `Advice`**：切了以后做什么（5 种）
   - **连接点 `JoinPoint`**：可以被切的地方（方法）
   - **织入 `Weaving`**：把切面"织"进目标对象的过程
2. **5 种通知 + 执行顺序**
   | 通知 | 时机 |
   |---|---|
   | `@Before` | 目标方法前 |
   | `@AfterReturning` | 正常返回后（能拿到返回值） |
   | `@AfterThrowing` | 抛异常后（能拿到异常） |
   | `@After` | 最终（相当于 `finally`） |
   | **`@Around`** | **包住整个方法，最强**（`ProceedingJoinPoint.proceed()` 决定放不放行、能改返回值） |
   - 顺序：`@Around` 前半 → `@Before` → 方法 → `@AfterReturning`/`@AfterThrowing` → `@After` → `@Around` 后半
3. **切点表达式**
   - `execution(* com.example.service..*.*(..))` 逐段解释：
     `*`（任意返回值）`com.example.service..`（包及子包）`*`（任意类）`.*`（任意方法）`(..)`（任意参数）
   - `@annotation(com.example.anno.Log)`：**按注解切** ← 自定义注解的关键
   - `within(...)` / `bean(...)` / `args(...)`
4. **自定义注解**
   ```java
   @Target(ElementType.METHOD)              // 加在哪
   @Retention(RetentionPolicy.RUNTIME)      // ⭐ 必须是 RUNTIME，否则反射读不到
   @Documented
   public @interface OperationLog {
       String value() default "";
   }
   ```
   - **元注解 4 个**：`@Target` / `@Retention` / `@Documented` / `@Inherited`
   - `@Retention` 三档：`SOURCE` / `CLASS` / **`RUNTIME`**
5. **实战**：写 `@OperationLog` 注解 + 切面 → 自动记录「谁 / 什么时候 / 调了哪个方法 / 参数 / 耗时 / 成功失败」写进日志表
   - 切面里怎么拿方法上的注解：`MethodSignature ms = (MethodSignature) joinPoint.getSignature(); Method m = ms.getMethod(); OperationLog anno = m.getAnnotation(OperationLog.class);`
6. **AOP 底层原理（面试必问）**
   - **JDK 动态代理**：基于**接口**（`Proxy.newProxyInstance`）→ 目标类**必须有接口**
   - **CGLIB 动态代理**：基于**继承**（生成子类）→ 不能被 `final` 修饰
   - SpringBoot 2.x 起**默认 CGLIB**（`spring.aop.proxy-target-class=true`）
   - **为什么"同类内部调用不走代理"** → 和 Day34 事务失效**同一个根因**（`this` 是原始对象，不是代理）
7. **Spring 里 AOP 的典型应用**：事务（`@Transactional`）、日志、权限、缓存（`@Cacheable`）、异步（`@Async`）

# Day 43 ｜ MySQL 锁与 MVCC ⭐⭐⭐

> **大章、面试超高频。** 接 Day28 的"乐观锁 vs 悲观锁"。

### 要学的知识点

1. **锁的粒度**
   - **表锁**：锁整张表（MyISAM 只有表锁）；开销小、并发差
   - **行锁**：InnoDB 支持；开销大、并发好
   - ⚠️ **关键坑：InnoDB 的行锁是"锁索引"的** —— **如果 where 条件没走索引，行锁会退化成锁全表！**
2. **锁的模式**
   - **共享锁 S**（读锁）：`select ... lock in share mode`；多个事务可同时持有
   - **排他锁 X**（写锁）：`select ... for update` / `update` / `delete`；独占
   - `select ... for update` 的用途：**悲观锁**（先锁住再改）；坑：**没索引会锁表、锁了忘提交会卡死**
3. **意向锁（IS / IX）**：表级锁，作用是**快速判断"表里有没有行锁"**，避免逐行检查
4. **间隙锁 Gap Lock + 临键锁 Next-Key Lock**
   - **Next-Key Lock = 记录锁 + 间隙锁**，锁住"左开右闭"的区间
   - 作用：**在 RR（可重复读）隔离级别下解决幻读**（防止别人在我锁的区间里 `insert`）
   - 举例：`where id > 5 and id < 10 for update` → 锁住 (5,10) 这个间隙，别人插 7 会被阻塞
5. **死锁**
   - 产生条件：两个事务互相等对方的锁
   - **排查**：`SHOW ENGINE INNODB STATUS` → 找 `LATEST DETECTED DEADLOCK` 段落（会告诉你是哪两条 SQL）
   - **避免**：① 按**固定顺序**访问表/行 ② 事务尽量小、快进快出 ③ 加合适的索引（避免锁范围扩大）④ 用 `innodb_lock_wait_timeout` 兜底
6. **MVCC（多版本并发控制）—— 核心**
   - 目的：**读不加锁**，读写不阻塞（提升并发）
   - 依赖两个东西：
     1. **`undo log` 版本链**：每行有隐藏列 `trx_id`（最后改它的事务 ID）+ `roll_pointer`（指向 undo log 里的旧版本）
     2. **`Read View`（读视图）**：包含 `m_ids`（活跃事务 ID 列表）、`min_trx_id`、`max_trx_id`、`creator_trx_id`
   - **可见性判断算法**（拿行的 `trx_id` 和 Read View 比）：
     - `trx_id < min_trx_id` → 已提交，**可见** ✅
     - `trx_id >= max_trx_id` → 太新了（我之后才开始的），**不可见**
     - `trx_id` 在 `m_ids` 里 → 还没提交，**不可见**
     - 不可见就顺着 `roll_pointer` 找上一个版本，直到找到可见的
   - **为什么"可重复读"能读到旧版本**：因为 **RR 只在第一次 `select` 时生成一次 Read View**，后面都复用它
   - **RC（读已提交）**：**每次 `select` 都重新生成 Read View** → 所以能读到别人新提交的数据
7. **快照读 vs 当前读（很重要）**
   - **快照读**：普通 `select` → 走 MVCC，**不加锁**，读的是历史版本
   - **当前读**：`select ... for update` / `lock in share mode` / `update` / `delete` / `insert` → **加锁 + 读最新版本**
   - `update` 的执行流程：先**当前读**拿到最新值 → 再更新（所以 `update` 会读到最新数据）
8. **乐观锁 vs 悲观锁（接 Day28）**
   - 悲观锁：`for update` / `synchronized`，先锁再改
   - 乐观锁：**版本号**（`version` 字段，`update ... set version=version+1 where version=旧值`，影响行数 0 就是被别人改过）/ CAS
   - 选型：冲突少 → 乐观锁；冲突多 → 悲观锁

### ✅ 过关标准
1. 能**画出 MVCC 的版本链 + Read View 判断流程图**
2. 能解释"**RR 下幻读到底是被什么解决的**"（Next-Key Lock + MVCC 各管什么）
3. 给一段并发 SQL，能说出**会加什么锁**
4. 能说出**行锁退化成表锁**的条件，并知道怎么避免
5. 知道怎么用 `SHOW ENGINE INNODB STATUS` 查死锁

# Day 44 ｜ 认证与授权 + JWT ⭐⭐⭐

> **⚠️ 硬约束：这天必须排在"第一个项目"动工之前。** 项目要"登录注册 + 权限"，不先学没法做。

### 要学的知识点

1. **认证（Authentication）vs 授权（Authorization）**
   - 认证 = "**你是谁**"（登录）
   - 授权 = "**你能干什么**"（有没有权限访问这个接口）
2. **Session 的问题（为什么需要 JWT）**
   - 服务器要存 Session → **单机内存，集群要共享**（要么 Redis，要么粘性会话）
   - 依赖 Cookie → **跨域麻烦、移动端（App/小程序）不友好**
   - 服务器重启 Session 就丢
3. **JWT 三段结构（必须能手写/手拆）**
   ```
   eyJhbGciOiJIUzI1NiJ9 . eyJzdWIiOiIxIiwiZXhwIjoxNzAwfQ . dBjftJeZ4CVP-mB92K27uhbUJU1p1r_wW1gFWFOEjXk
   └─ Header ─┘        └──── Payload ────┘        └──────── Signature ────────┘
   ```
   - **Header**：`{"alg":"HS256","typ":"JWT"}` → base64url
   - **Payload**：`{"sub":"1","exp":1700000000,"role":"admin"}` → base64url
   - **Signature**：`HMACSHA256(base64url(Header) + "." + base64url(Payload), 密钥)`
   - ⭐ **关键结论**：Header 和 Payload 只是 **base64url 编码，不是加密！** 任何人 base64 解码都能看到内容（**所以绝不能放密码等敏感信息**）
   - 签名的作用：**防篡改**（改一个字符，签名就对不上）
4. **验签流程**
   - 服务器收到 token → 拆三段 → **用同样的密钥和算法重算签名** → 和第三段比对 → 一致才信任
   - 顺便校验 `exp` 过期时间
5. **无状态登录完整链路（要能画出来）**
   ```
   ① POST /login（账号密码）→ Service 校验 → 生成 token → 返回
   ② 前端存起来（localStorage / Cookie）
   ③ 后续请求带 Authorization: Bearer <token>
   ④ 拦截器（Day33）：取 token → 验签 → 解析出 userId
   ⑤ 把当前用户放进 ThreadLocal（UserContext.set(userId)）
   ⑥ Controller / Service 里直接 UserContext.get() 拿当前用户，不用再传参
   ⑦ ⚠️ afterCompletion 里必须 UserContext.remove()！
   ```
   - **为什么必须 remove**：Tomcat 用**线程池**，线程会复用 → 不清理会把 A 用户的身份带给 B 用户的请求（**串数据，安全事故**）
6. **安全点（面试/真机都要注意）**
   - **`alg: none` 攻击**：攻击者把 Header 改成 `{"alg":"none"}` 并去掉签名 → **必须显式指定算法**，不能信任 token 里的 alg
   - **密钥不能硬编码**在代码里 → 放 `application.yml` 或环境变量
   - **Payload 别放敏感信息**（密码、身份证）
   - **必须设过期时间** `exp`（一般 30 分钟 ~ 2 小时 + refresh token）
   - **JWT 无法主动失效**（签出去了就有效）→ 要"退出登录/踢人"就得配 **Redis 黑名单**
7. **实现**
   - 依赖 `io.jsonwebtoken:jjwt-api / jjwt-impl / jjwt-jackson`
   - 工具类：`generateToken(userId)` / `parseToken(token)` / `validate(token)`
   - 拦截器 + 白名单（`/login`、`/register`、静态资源）

### ✅ 过关标准

# Day 45 ｜ Sa-Token 实战 + RBAC 权限模型 ⭐⭐

**一句话**：手写 JWT 太累，Sa-Token 帮你把登录态、踢人、权限注解都做好了。

### 要学的知识点

1. **Sa-Token 是什么**：国产轻量鉴权框架（上手比 Spring Security 快得多，国内项目用得很多）
2. **配置**
   ```yaml
   sa-token:
     token-name: satoken          # 请求头/参数名
     timeout: 2592000             # 有效期 30 天（秒）
     active-timeout: -1
     is-concurrent: true          # 是否允许同一账号并发登录
     is-share: false              # 多人登录是否共用一个 token
     token-style: uuid
     is-log: true
   ```
3. **核心 API**
   - `StpUtil.login(id)` 登录 / `StpUtil.logout()` 登出
   - `StpUtil.getTokenInfo()` 拿 token 信息
   - `StpUtil.checkLogin()` 校验登录（没登录抛 `NotLoginException`）
   - `StpUtil.getLoginIdAsLong()` 拿当前用户 ID
   - `StpUtil.kickout(id)` **踢人下线** / `StpUtil.renewTimeout(...)` **续期**
   - `StpUtil.hasRole("admin")` / `StpUtil.hasPermission("user:add")`
4. **注解式鉴权（重点）**
   - `@SaCheckLogin`：必须登录
   - `@SaCheckRole("admin")`：必须有某角色
   - `@SaCheckPermission("user:add")`：必须有某权限
   - `@SaCheckOr(...)`：或关系
   - 注册拦截器：`registry.addInterceptor(new SaInterceptor()).addPathPatterns("/**")`
5. **RBAC 权限模型（要能设计表）**
   - **RBAC = Role-Based Access Control（基于角色的访问控制）**
   - **5 张表**：
     - `user`（用户）
     - `role`（角色）
     - `permission`（权限，也叫菜单/资源）
     - `user_role`（用户-角色 关联表）
     - `role_permission`（角色-权限 关联表）
   - 查询链路（一条 SQL join 出来）：
     用户 → `user_role` → 角色 → `role_permission` → 权限
   - 为什么要"角色"这一层：**用户和权限解耦**，改权限只改角色，不用一个个改用户
6. **`StpInterface` 接口（要把你的数据库接进去）**
   ```java
   public class StpInterfaceImpl implements StpInterface {
       public List<String> getPermissionList(Object loginId, String loginType) { ... }
       public List<String> getRoleList(Object loginId, String loginType) { ... }
   }
   ```
7. **权限标识命名规范**：`模块:操作`（`user:add` / `user:delete` / `order:list`）
8. **全局异常处理（接 Day31）**：`NotLoginException` → 401、`NotPermissionException` / `NotRoleException` → 403，返回统一 `Result`
9. **JWT vs Sa-Token 怎么选**
   - 想学原理 / 面试能讲清楚 → 手写一遍 JWT（Day44）
   - 想快速做出项目 → Sa-Token（它底层也能切 JWT 模式）
   - **面试建议**：两个都懂，讲的时候说"我用 Sa-Token 落地，同时手写过 JWT 了解原理"

### ✅ 过关标准
1. 能跑通"**登录 → 不同角色看到不同接口**"（admin 能删、普通用户返回 403）
2. 能**设计并建好 RBAC 五张表**，并能写出一条"查某人所有权限"的 SQL
3. 能实现 `StpInterface` 把数据库权限接进 Sa-Token
4. 能说出 **Sa-Token 相比手写 JWT 省了什么**（登录态管理、踢人、续期、注解鉴权）
5. 能配置全局异常，让未登录返回 401、无权限返回 403（统一 JSON）
