## 一、先想清楚：内存 vs 硬盘

```
程序里的 List / Map     →  住在【内存】，程序一关就没了
文件里的 .txt           →  住在【硬盘】，关掉还在（= 持久化）
```

**口诀**：**内存管运算，文件管留存**。以后记账本、爬虫、日志，全是"运算在内存、留存靠文件（或数据库）"。

## 二、两条路线：字节流 vs 字符流

| 路线 | 代表类 | 存什么 | 今天用不用 |
|---|---|---|---|
| 字节流 | `InputStream` / `OutputStream` | 图片、音频、压缩包（任何二进制） | 不用 |
| 字符流 | `Reader` / `Writer` | 文本（txt / csv / 日志） | ✅ 全用这个 |

**存文本就用字符流**——字节流存中文要自己处理编码，容易乱码。

今天只碰 3 个类（够用一整年）：

| 类 | 作用 | 记忆点 |
|---|---|---|
| `BufferedReader` | 按行读，快 | `readLine()` 一次给一行 |
| `PrintWriter` | 按行写，方便 | `println()` 自动补换行 |
| `InputStreamReader` / `OutputStreamWriter` | 字节 ↔ 字符的"翻译官" | 它的括号里**指定 UTF-8** |

## 三、读文件三件套（背下来）

```java
try (BufferedReader br = new BufferedReader(
        new InputStreamReader(new FileInputStream(path), StandardCharsets.UTF_8))) {

    String line;
    while ((line = br.readLine()) != null) {   // ① 读到末尾返回 null
        // ② 处理这一行
    }
}                                              // ③ try 结束自动 close
```

三个要点：

1. **`readLine()` 读到文件末尾返回 `null`**——不是空字符串，所以判断条件是 `!= null`
2. **`try (...)` 叫 try-with-resources**——括号里创建的资源，出了 try 自动关（Day17 学过），不用手写 `close()`
3. **编码必须写 `StandardCharsets.UTF_8`**——不写就用系统默认（Windows 中文是 GBK）→ 中文乱码

## 四、写文件三件套

```java
try (PrintWriter pw = new PrintWriter(new OutputStreamWriter(
        new FileOutputStream(path), StandardCharsets.UTF_8))) {
    pw.println("张三,88");     // 自动补换行（Windows 下是 \r\n，记事本能正常显示）
}
```

**想"追加"而不是覆盖**——`FileOutputStream` 的第二个参数传 `true`：

```java
new FileOutputStream(path, true)     // true = append（在文件末尾接着写）
new FileOutputStream(path)           // 默认 = 覆盖（先把文件清空！）
```

> 这个 `true` 是今天最容易漏的一个字符：漏了，旧数据**全部消失**。

## 五、⚠️ 今天最大的坑：文件是空的 / 中文乱码

| 坑 | 现象 | 原因与正解 |
|---|---|---|
| **中文乱码** | 读出来是 `寮犱笁` 这种怪字 | 用了平台默认编码。两边都显式写 UTF-8：`new InputStreamReader(new FileInputStream(path), StandardCharsets.UTF_8)` |
| **文件是空的** | 程序"跑完了"，文件 0 字节 | 忘了 `flush()`/`close()`，数据还在缓冲区。→ 用 try-with-resources |
| **旧数据被覆盖** | 追加的进去了，前两行没了 | 忘了传 `true` |
| **FileNotFoundException** | 文件明明在却找不到 | 相对路径 = **当前工作目录**。VS Code ▶ 运行时是项目目录，文件就生成在那儿 |
| **NumberFormatException** | 读到空行就崩 | 先判空行（`line.trim().isEmpty()`），再 `split`，再确认 `parts.length == 2` |

## 六、异常：受检 vs 非受检（今天正式分清）

- **受检异常**（Compiler-checked）：`IOException` 及其子类。编译器逼你表态 → 要么 `throws`，要么 `try/catch`
- **非受检异常**（Runtime）：`NullPointerException`、`NumberFormatException`、`ArithmeticException`…编译器不管，运行时才炸

**catch 的顺序**：`FileNotFoundException` 是 `IOException` 的**子类**，所以小的写前面：

```java
} catch (FileNotFoundException e) {     // ① 先接子类（更具体）
    ...
} catch (IOException e) {               // ② 再接父类（兜底）
    ...
}
```

顺序写反 → 编译报错 *"已被捕获"*（unreachable catch）。

**兜底原则**：**出错时返回空集合，比返回 `null` 好**——调用方拿到空集合直接 `.size()` 没事；拿到 `null` 就 NPE（Day13 埋的雷）。
