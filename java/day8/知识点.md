# Day 8 知识点：多态（面向对象三大特征之三）

> 本文件只讲知识点，练习题见《练习题和代码题目.md》，做完再看《标准答案.md》。
> 前提：Day 7 的继承（extends/super/重写）已经过关，多态是站在继承肩膀上的。

## 1. 回顾：继承解决完了，还剩什么问题

Day 7 学了继承：把公共代码抽到父类，子类"白拿"。

```java
Animal a = new Dog("旺财");  // 等一下，这个写法 Day 7 没见过！
```

问题来了：**一个"Animal 类型"的引用，里面装的却是 Dog 对象**——它到底算动物还是算狗？调用方法时听谁的？这就是多态要回答的问题。

## 2. 多态是什么：同一个调用，不同表现

**多态（Polymorphism）= 同一个方法调用，对象不同，表现不同。**

生活类比：按下同一个"开始"键——
- 微波炉 → 加热
- 洗衣机 → 洗衣服
- 空调 → 吹冷风

同一个动作（按开始），不同东西（不同对象）→ 不同反应（不同实现）。这就是多态。

代码里长这样：

```java
Animal a1 = new Dog("旺财");   // 父类引用 → 狗
Animal a2 = new Cat("咪咪");   // 父类引用 → 猫
a1.sound();   // 输出：旺财汪汪叫
a2.sound();   // 输出：咪咪喵喵叫
```

**同一个 `sound()` 调用，装狗就汪汪，装猫就喵喵** —— 这就是多态。

## 3. 多态成立的三个要素（背下来！）

| 要素 | 要求 | 例子 |
|---|---|---|
| ① 有继承 | 子类 extends 父类 | `class Dog extends Animal` |
| ② 有重写 | 子类 @Override 父类方法 | `void sound()` 被 Dog 重写 |
| ③ 父类引用指向子类对象 | `Animal a = new Dog();` | 也叫**向上转型** |

**三个缺一个，多态就不成立。** 面试问"多态的条件"，就答这三条。

## 4. 向上转型：父类引用指向子类对象

`Animal a = new Dog("旺财");` —— 把"子类对象"交给"父类引用"拿着，叫**向上转型**（upcasting）。

类比：**遥控器（父类）操控电视（子类）**
- 遥控器上有的按键才能按 → 父类里有的方法才能调
- 按下"电源"键，干的是电视的活 → 调的是子类重写后的实现

> 为什么叫"向上"？类的继承图里父类画在上面，子类在下面，把子类对象"往上"交给父类引用，所以叫向上转型。

## 5. 动态绑定（核心口诀：编译看左边，运行看右边）

这是多态最重要的一句口诀，必须刻进脑子：

> **编译看左边，运行看右边。**

```java
Animal a = new Dog("旺财");
a.sound();   // 编译：左边是 Animal，Animal 有 sound → 编译通过
             // 运行：右边是 Dog，执行的是 Dog 重写后的 sound → 汪汪叫
a.bark();    // 编译错误！左边是 Animal，Animal 没有 bark → 编译直接报错
```

- **编译看左边**：`a` 的"类型"是 Animal，所以只能调用 Animal 里有的方法（`bark()` 是 Dog 独有的 → 编译报错）
- **运行看右边**：`a` 里面"实际装"的是 Dog 对象，所以执行的是 Dog 重写后的实现（输出汪汪叫，不是动物发声音）

## 6. 两个"不参与多态"的坑（面试爱挖）

1. **属性不参与多态**：`a.name` 编译、运行**都看左边**（父类的 name）
2. **静态方法不参与多态**：`a.staticMethod()` 看左边类型，跟对象无关

```java
class Animal { String name = "动物"; }
class Dog extends Animal { String name = "狗"; }

Animal a = new Dog();
System.out.println(a.name);  // 输出：动物（不是"狗"！属性看左边）
```

## 7. 向下转型 + instanceof：想用子类独有的方法

向上转型后，`a.bark()` 编译报错（左边是 Animal）。但狗明明会叫，怎么调？

**方案：先把引用"还原"成子类类型再调** —— 叫**向下转型**（强制类型转换）：

```java
Animal a = new Dog("旺财");
Dog d = (Dog) a;    // 向下转型：把父类引用强制还原成子类引用
d.bark();           // ✅ 旺财汪汪叫
```

⚠️ **危险**：如果 `a` 里面实际装的不是 Dog，强转直接崩溃（ClassCastException）：

```java
Animal a = new Cat("咪咪");
Dog d = (Dog) a;    // 💥 运行时报错：Cat cannot be cast to Dog
```

**安全写法：先 instanceof 判断，再转**：

```java
if (a instanceof Dog) {       // a 实际是不是 Dog？
    Dog d = (Dog) a;          // 是才转，安全
    d.bark();
}
```

`instanceof` = "是不是这个类型"，判断结果是 boolean。

## 8. 多态的好处（面试能说出三条就赢）

1. **写一次，处处用**：方法参数用父类类型，一个方法通吃所有子类（练习题 2、5 就是干这个）
2. **扩展容易**：以后加新子类（比如加个"孔雀"），**不用改现有代码**——这就是传说中的"开闭原则"（对扩展开放，对修改关闭）的雏形
3. **框架基础**：Spring、集合框架（List 可以装 ArrayList 也可以装 LinkedList）全是多态思想——**现在看 Spring 源码就不会一脸懵**

## 9. 重写 vs 重载（Day 7 复习，多态依赖的是"重写"）

| | 重写 Override | 重载 Overload |
|---|---|---|
| 发生位置 | 父类子类之间 | 同一个类里 |
| 方法名 | 相同 | 相同 |
| 参数列表 | **相同** | **不同** |
| 作用 | 改变父类行为 | 同一方法处理不同类型 |
| 和多态的关系 | ✅ 多态依赖它 | ❌ 和多态没关系 |

## 10. 常见坑清单（记住）

1. 向上转型后调子类独有方法 → **编译报错**（要向下转型）
2. 不判断直接向下转型 → **ClassCastException** 运行时崩溃
3. 属性不参与多态：`a.name` 输出的是**父类**的属性
4. 静态方法不参与多态：看左边类型
5. 忘了三要素（继承+重写+父类引用指向子类）→ 谈不上多态
6. `instanceof` 右边写错类型（比如 `a instanceof Dog` 而 Dog 跟 Animal 没关系）→ 编译报错

## 11. 一句话总结

> **继承给代码"复用"，多态给代码"弹性"：把父类引用当容器，装谁就是谁，同一个调用不同表现。**
