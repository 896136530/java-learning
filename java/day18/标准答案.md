## 题 1 答案（问候线程）

```java
class HelloThread extends Thread {
    @Override
    public void run() {
        for (int i = 1; i <= 3; i++) {
            System.out.println("线程1：第" + i + "次");
        }
    }
}
```

（main 输出：线程1：第1/2/3次 + 主线程结束）

**考点**：`extends Thread` + `@Override run()`；`start()` 开线程、`join()` 让主线程等待。
**刁钻用例**：把 `t.start()` 改成 `t.run()` → 不并发（run 当普通方法顺序执行），这个题因为 join 看不出区别，但换成无 join 的题立刻失效——**start 才是开线程**。

## 题 2 答案（双线程任务）

```java
class Runner implements Runnable {
    @Override
    public void run() {
        System.out.println("跑起来了");
    }
}
```

（main 输出：两行"跑起来了"（顺序可能交换）+ 完成）

**考点**：**implements Runnable（推荐）**；同一个 Runnable 对象可以包进多个 Thread。
**刁钻用例**：直接调 `r.run()` 两次 → 也是两行，但全在主线程顺序跑，没有并发。面试追问"为什么不用继承 Thread" → 单继承限制。

## 题 3 答案（同步计数器）

```java
class Adder implements Runnable {
    static int value = 0;

    static synchronized void add() {
        value++;
    }

    @Override
    public void run() {
        for (int i = 0; i < 500; i++) {
            add();
        }
    }
}
```

（main 输出：**计数结果：1000**）

**考点**：**synchronized 保证原子性**——value++ 的"读-算-写"三步不被插队。
**刁钻用例**：删掉 synchronized 只跑几次可能还是 1000（快机器上概率低），**多跑几次**就会看到 999/998——竞态是概率问题；synchronized 是把它变成必然正确。

## 题 4 答案（睡眠闹钟）

```java
class Alarm extends Thread {
    @Override
    public void run() {
        for (int i = 1; i <= 3; i++) {
            System.out.println("叮咚 " + i);
            try {
                Thread.sleep(200);
            } catch (InterruptedException e) {
                e.printStackTrace();
            }
        }
    }
}
```

（main 输出：叮咚 1/2/3 + 闹钟结束，每声间隔 200ms）

**考点**：**sleep 抛受检异常 InterruptedException，而 run() 签名不能 throws** → 只能在 run 内部 try-catch（重温 Day15）。
**刁钻用例**：`Thread.sleep(0)` → 不睡，但会给其他线程让出 CPU 的机会（yield 效果）；sleep 期间线程是"阻塞"状态，被 interrupt 会立刻抛异常。

## 题 5 答案（卖票战）

```java
class TicketBox {
    static int tickets = 5;

    static synchronized boolean sell() {
        if (tickets > 0) {
            tickets--;
            return true;
        }
        return false;
    }
}

class Seller implements Runnable {
    @Override
    public void run() {
        while (TicketBox.sell()) {
            System.out.println("卖出一张，剩余 " + TicketBox.tickets);
        }
    }
}
```

（main 输出：5 行"卖出一张，剩余 N"（顺序可能交换）+ **剩余票数：0**）

**考点**：**经典卖票场景**——"先判后减"必须整体加锁，否则两个线程可能同时判 `tickets>0` 都通过，卖出 6 张甚至负票。
**刁钻用例**：去掉 synchronized 多跑几次 → 可能出现 `剩余票数：-1`（卖超）——这就是"超卖事故"，电商秒杀同款 bug。
