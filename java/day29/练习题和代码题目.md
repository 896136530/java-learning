## 题 1：第一个 Maven 项目跑起来（`ex1/HelloMaven.java`）

**要做的事**：
1. 在 `java/day29` 目录下跑一次（`运行Maven.bat` 选 1）
2. 补 `getUrl(Connection)` 方法（TODO 写在文件末尾），并把 main 里那行改成调用它
3. **再跑一次**，确认输出没变——这说明 Maven 编译的确实是你刚改的代码

**你会看到**：Java 版本 / 供应商 / 工作目录 / 连接字符串 / 数据库产品版本 / 驱动版本 / `SELECT 1 = 1 ✅`

**要回答自己**：项目里**没有** `lib/` 目录、命令里**没有** `-cp`，驱动是从哪来的？

## 题 3：配置文件从哪来（`ex3/ConfigLoader.java`）⭐

**要做的事**：
1. 补 `loadFromClasspath(name)`（一行，转发给 `tool.Hold.readResource`）
2. 补 `countLines(content)`（数有效行，跳过 `#` 注释和空行），并让 main 用它
3. 在 `src/main/resources/db.properties` 里**加一行** `db.timeout=3000`，重跑，看行数变不变

**这道题的核心是最后一行输出**：

```
当前工作目录：...\java\day29
src/main/resources/db.properties 存在吗：true（IDE 里侥幸能读到）
⚠️ 打包成 jar 之后，这条路径就不存在了 —— 这就是"能跑不能发货"的典型病。
```

**要回答自己**：为什么"磁盘路径"在 IDE 里能读到、打成 jar 就读不到？

## 题 4：瘦 jar vs 胖 jar（`ex4/FatJar.java`）⭐ 不用写代码

**要做的 5 步**（做完在 `FatJar.java` 的 TODO 里记下你的观察）：
1. `mvn package` → 看 `target/` 里有什么、jar 多大
2. `java -jar target/day29-maven-1.0.jar` → **记下报错原文**
3. 把 pom.xml 里 shade 插件那段**注释掉** → `mvn package` → 看 jar 又变回多大
4. **放开注释** → `mvn package` → 这次 `target/` 里出现**两个** jar，各自多大？
5. `java -jar` 跑通 ✅

**要回答自己**：为什么胖 jar 比瘦 jar 大了 4 MB 左右？`java -jar` 是靠 jar 里哪个文件找到入口类的？

## 题 5：命令行小书店（`ex5/BookDao.java`）

**要做的事**：补 5 个方法（`insert` / `count` / `findByAuthor` / `totalValue` / `findAll`），
`mapRow` 已经给你了，直接复用。

**跑法**：
1. `运行Maven.bat` 选 5 → 看到书目快照（5 本，库存总价值 **580.5** 元）
2. 按提示输入一本新书（比如 `新书 张三 20.5 3`），看它插进去、快照变 6 本
3. **最后一步（今天的成果验收）**：把 pom.xml 里 shade 的 `<mainClass>` 改成 **`ex5.BookApp`**，
   然后 `mvn clean package` → `java -jar target/day29-maven-1.0.jar`
   → **命令行小书店"发货"成功**：换台电脑、只给这一个 jar 文件，它也能跑（前提是那台机器有 MySQL）

**要回答自己**：为什么打成 jar 之后还能让用户输入？（提示：`System.in` 和 jar 没关系）
