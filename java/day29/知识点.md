# Day 29 知识点：Maven 与项目结构（告别 javac 和 lib/）

> 前提：Day21~28 你一直在用 `javac -cp "lib/mysql-connector-j.jar"` 手动编译、手动跑。
> 今天换掉这套"手工坊"，用**真实 Java 项目**的方式：Maven。
> 一句话：**Maven = 项目的"包管理 + 标准布局 + 一键构建"三合一。**

## 1. 为什么要 Maven（我们踩过的坑，一条条对上）

| 你之前手工做的事 | 现在 Maven 怎么做 |
|---|---|
| 手动下载 `mysql-connector-j.jar` 丢进 `java/day21/lib/` | pom.xml 写三行，Maven **自动下载**到本地仓库 |
| `javac -encoding UTF-8 -cp "...jar" A.java B.java` | `mvn compile`（不用敲任何 jar 路径） |
| `java -cp ".;...jar" Main` | `mvn exec:java -Dexec.mainClass=xxx.Yyy` |
| 每台电脑都要重新下 jar、配路径 | `~/.m2/repository` 全机器共用，一次下载到处可用 |
| 想"给别人一个能跑的文件"要拷一堆类 + jar | `mvn package` → 一个 jar 走天下 |

> 一句话：**手工坊 → 流水线**。你以前每天做的那堆事，都是 Maven 一个命令的事。

## 2. 标准目录结构（背下来，SpringBoot 也是这套）

```
day29/                       ← 项目根目录（有 pom.xml 的地方就是项目根）
├── pom.xml                  ← ⭐ 项目身份证 + 依赖清单
├── src/
│   ├── main/
│   │   ├── java/            ← 所有 .java 源码（包名对应子目录）
│   │   │   └── ex1/HelloMaven.java
│   │   └── resources/       ← ⭐ 配置文件（会被打进 jar）
│   │       └── db.properties
│   └── test/
│       └── java/            ← 测试代码（Day31 学 JUnit 用）
└── target/                  ← Maven 生成的产物（编译结果、jar、报告）
                               ⚠️ 这个目录**不要提交到 git**（每次 build 都能重新生成）
```

| 目录 | 放什么 | 谁来读 |
|---|---|---|
| `src/main/java` | 源代码 | `mvn compile` |
| `src/main/resources` | 配置/模板/静态文件 | 用**类路径**读（下面第 6 节） |
| `target` | 编译产物、jar | 只有你自己看 |
| `~/.m2/repository` | **下载来的所有 jar**（不在项目里！） | Maven 自己 |

> ⚠️ 最容易搞混：**依赖 jar 不在项目目录里**，而在用户目录的 `.m2\repository` 里。
> 项目只是"声明我要什么"，jar 是"公用的"。

## 3. pom.xml：三件事

```xml
<modelVersion>4.0.0</modelVersion>          <!-- 固定写法 -->

<!-- ① 项目坐标 GAV：全球唯一标识这个项目 -->
<groupId>com.xiaoming</groupId>             <!-- 组织：域名倒写 -->
<artifactId>day29-maven</artifactId>        <!-- 项目名 -->
<version>1.0</version>                      <!-- 版本 -->

<!-- ② 依赖：以前手动下 jar，现在只写坐标 -->
<dependencies>
  <dependency>
    <groupId>com.mysql</groupId>            <!-- 谁的 -->
    <artifactId>mysql-connector-j</artifactId> <!-- 什么包 -->
    <version>8.4.0</version>                <!-- 哪个版本 -->
  </dependency>
</dependencies>

<!-- ③ 插件：打包/运行等"构建动作" -->
<build><plugins> ... </plugins></build>
```

```xml

  <mirrorOf>central</mirrorOf>
  <url>https://maven.aliyun.com/repository/public</url>
</mirror>
```

## 4. 生命周期：一条命令管一整套

`mvn 目标` —— 常用的就这几个（按顺序执行，后面的会自动带上前面的）：

| 命令 | 干什么 | 产物 |
|---|---|---|
| `mvn clean` | 删掉 `target/`（从干净状态开始）| 干净 |
| `mvn compile` | 编译 `src/main/java` | `target/classes/*.class` |
| `mvn test` | 跑单元测试 | 测试报告 |
| `mvn package` | 编译 + 打包 | `target/xxx-1.0.jar` |
| `mvn install` | 打包 + 装进本地仓库（给别的项目当依赖用）| `.m2` 里多一份 |

**为什么必须先 `clean`？** 因为 `target/` 会有旧产物：你改了代码却看到旧结果、你删了类却还报错——**九成是没 clean**。
> 老手习惯：**出怪错先 `mvn clean package`**。

## 5. ⭐ 瘦 jar 与胖 jar（今天最重要的实操结论）

`mvn package` 出来的默认是**瘦 jar**：只装了你自己写的类。

```
day29-maven-1.0.jar          ← 瘦 jar（约 17.7 KB）→ java -jar 会报"找不到主类/驱动"
original-day29-maven-1.0.jar ← 原始瘦 jar 的备份（shade 插件会把它挪到这里）
```

想让它"自己带着行李箱出门"，要加 **maven-shade-plugin**：

```xml
<plugin>
  <artifactId>maven-shade-plugin</artifactId>
  <version>3.5.1</version>
  <executions><execution>
    <phase>package</phase>                       <!-- 绑到 package 阶段，自动执行 -->
    <goals><goal>shade</goal></goals>
    <configuration>
      <transformers>
        <transformer implementation="...ManifestResourceTransformer">
          <mainClass>ex1.HelloMaven</mainClass>  <!-- ⭐ 入口类：jar 的"启动按钮" -->
        </transformer>
      </transformers>
    </configuration>
  </execution></executions>
</plugin>
```

加完之后：

| | 瘦 jar | 胖 jar（fat / uber jar）|
|---|---|---|
| 大小 | **17.7 KB**（实测）| **4.45 MB**（实测）|
| 内含 | 只有你的类 | 你的类 + MySQL 驱动 + 其他依赖 |
| 能不能 `java -jar` | ❌ 报错 | ✅ 能跑 |
| 换台电脑 | 跑不了 | **能跑**（自带依赖）|

> 💡 `java -jar` 靠的是 jar 里的 `META-INF/MANIFEST.MF` 文件中那行 `Main-Class`——
> shade 插件的 `<mainClass>` 就是在写这行。**没有它，JVM 不知道该从哪个类开始跑。**

## 6. ⭐ 类路径 vs 磁盘路径（配置文件到底放哪）

| | 类路径读（推荐）| 磁盘路径读 |
|---|---|---|
| 写法 | `getClassLoader().getResourceAsStream("db.properties")` | `new FileInputStream("src/main/resources/db.properties")` |
| 文件放哪 | `src/main/resources/` | 任意位置 |
| IDE 里 | ✅ 能读 | ✅ 碰巧能读（工作目录正好是项目根）|
| 打成 jar 后 | ✅ 能读（被打进 jar 内部了）| ❌ **读不到**（jar 里没有"当前目录"）|
| 适合 | 配置、模板、SQL 文件（**跟着代码走**）| 用户数据（账本.txt、导出.csv）。**用户文件放用户目录，别塞进 jar** |

> 一句话记法：**跟着代码走的文件放 resources 用类路径读；用户的数据文件用磁盘路径读。**

## 7. 常见报错速查（今天一定会遇到）

| 报错 | 原因 | 解法 |
|---|---|---|
| `Could not resolve dependencies ... not found` | GAV 写错（版本号、包名拼错）| 照着官网/中央仓库抄坐标；改成 `9.9.9` 试试就知道啥样 |
| `No compiler is provided ... JDK` | Maven 用了 JRE 而不是 JDK | 设 `JAVA_HOME` 指向 JDK |
| `Cannot access central ... Connection timed out` | 网络问题 | 换阿里云镜像 |
| `java -jar` 报 `no main manifest attribute` | 没配 shade 的 `mainClass` | 加 `<mainClass>` 并重新 package |
| `java -jar` 报 `ClassNotFoundException: com.mysql...` | 打成瘦 jar 了 | 加 shade 插件 |
| 改了代码但结果没变 | `target/` 是旧的 | `mvn clean package` |
| 中文乱码 | 编码没声明 | pom 里 `<project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>` |
