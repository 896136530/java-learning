# Day 26 知识点：用 Java 操作数据库（JDBC 实战）

> 主线：Java 就业路线 · 第 26 天（阶段二：数据库）
> 昨天（Day25）你**手敲 SQL** 给 mysql 命令行；今天让 **Java 程序自己连库、发 SQL、拿结果**。
> 一句话：**JDBC = Java 和数据库之间的翻译官**，你写的 SQL 通过它送进 MySQL，结果再被它带回来。

## 一、先回忆 Day21 的 JDBC 五步

```java
Class.forName("com.mysql.cj.jdbc.Driver");              // ① 加载驱动（新版可省略）
Connection conn = DriverManager.getConnection(url, user, pwd);   // ② 拿连接
PreparedStatement ps = conn.prepareStatement(sql);      // ③ 准备 SQL
ps.setString(1, "张三");                                 // ④ 填参数
ResultSet rs = ps.executeQuery();                       // ⑤ 执行 + 拿结果
```

今天把这五步**用熟**：封装成方法、参数化、读结果集、组装对象。**不用再写 `Class.forName`**——连接器 jar 里有 `META-INF/services` 自动注册（JDBC 4.0 起）。

## 二、一定要分清的两个"执行"方法

| 方法 | 用在 | 返回什么 |
|---|---|---|
| `executeQuery()` | `SELECT`（查） | `ResultSet`（一张虚拟结果表） |
| `executeUpdate()` | `INSERT` / `UPDATE` / `DELETE` | **int：受影响行数** |

> 记法：**Query 拿结果，Update 拿行数**。改了 0 行通常意味着 WHERE 没匹配上（不是报错！）。

## 三、ResultSet：把结果表"一行一行"走完

```java
while (rs.next()) {                       // next() 先把游标移到下一行，有行返回 true
    String name = rs.getString("name");   // 按列名取，最不容易错
    int score   = rs.getInt("score");     // 也可以按序号 rs.getInt(2)，但列名更清楚
}
```

三个要点：

1. **游标一开始在第 0 行之外**，所以必须先 `next()` 才能读
2. `next()` 返回 `false` = 没有下一行了（循环结束）
3. **只能向前**，不能回头；要倒着看就再查一次

`getInt` / `getString` / `getDouble` 遇到 **SQL NULL** 时的行为：`getInt` 返回 `0`，`getString` 返回 `null`。要区分"0 分"和"没成绩"，用 `rs.getObject(...)` 或 `rs.wasNull()`。

## 四、⭐ 今天的心脏：PreparedStatement（`?` 占位符）

```java
String sql = "SELECT score FROM student WHERE name = ?";   // ① 用 ? 留坑
try (PreparedStatement ps = conn.prepareStatement(sql)) {
    ps.setString(1, name);                                 // ② 按序号填坑（从 1 开始！）
    try (ResultSet rs = ps.executeQuery()) { ... }
}
```

**为什么必须用它？**

| 写法 | 问题 |
|---|---|
| `"WHERE name = '" + name + "'"`（字符串拼接） | **SQL 注入**：name 传 `王五' OR '1'='1` → 条件恒真，查出你没授权看的数据 |
| `"WHERE name = ?"` + `setString` | 参数**永远只当值**，不会被当成 SQL 片段 |

今天 Ex1 里就埋了一个注入尝试：拼接写法会返回 `100`（钱七的分），参数化写法老老实实返回"无成绩" ✅

**加分点：`?` 不只是给"值"用的**——`LIMIT ?`、`SET score = score + ?` 都能参数化（Ex3 / Ex5 就是）。

## 五、能交给 SQL 的，别搬回 Java

```java
// ❌ 把 100 万行学生全查回 Java，再自己 for 循环算平均
// ✅ 让数据库算，只带回 1 个数
ResultSet rs = st.executeQuery("SELECT ROUND(AVG(score), 2) FROM student");
```

原因：**数据在网络上来回搬是有成本的**（网络 IO + 内存）。数据库天生擅长算聚合，能用 `COUNT/AVG/MAX/GROUP BY/ORDER BY/LIMIT` 就别用 Java 循环。

## 六、⚠️ 今天最大的坑：环境与 URL

| 坑 | 现象 | 正解 |
|---|---|---|
| **驱动 jar 不在 classpath** | `No suitable driver found` / `ClassNotFoundException` | 编译运行都要带：`-cp "…\mysql-connector-j.jar"`（用 `运行Day26.bat` 就不用操心） |
| **URL 里编码写成 `utf8mb4`** | `Unsupported character encoding 'utf8mb4'` ⚠️ 今天真踩了 | JDBC 的 `characterEncoding` 要写 **Java 的字符集名 `UTF-8`**（连接器会自动映射到服务端的 utf8mb4） |
| 忘了 `rs.next()` 就取值 | `Before start of result set` | 取之前必须 `next()` 过一次 |
| 按序号取值从 0 开始写 | `Invalid column index` | **JDBC 的列序号和 `?` 序号都从 1 开始** |
| 连接/语句忘了关 | 连接数暴涨、程序卡死 | 一律 `try (…)` 包起来（try-with-resources） |
| `executeUpdate()` 返回 0 | 以为报错了 | 0 行 = WHERE 没匹配到，SQL 本身成功 |

## 七、今天的六个文件怎么配合（先看懂再动手）


**为什么用"共享工具类"？** 真实项目里就是这样的：连库、初始化这类事只写一次，所有业务代码复用。你写的那几个 `*Dao` 类，其实就是项目里的 **DAO（Data Access Object，数据访问对象）** 雏形——Day27 会把它讲成正式的分层。
