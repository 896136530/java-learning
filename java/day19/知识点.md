# Day 19 知识点：多线程综合实战

> 前提：Day18 的 Thread/Runnable/synchronized/join/sleep 已掌握。今天不学新玩具，**把螺丝拧紧**——实战场景里见真章。附加两个小概念：线程安全集合、volatile。

## 1. 实战套路 1：多线程分工，主线程合并

"一个任务拆成 N 段，每个线程算一段，最后拼起来"——大数据分治思想的迷你版。

```java
class SumWorker implements Runnable {
    private int start, end;
    public SumWorker(int s, int e) { start = s; end = e; }

    @Override
    public void run() {
        int s = 0;
        for (int i = start; i <= end; i++) s += i;
        merge(s);               // 把结果交回公共区
    }

    static int total = 0;
    static synchronized void merge(int v) {   // ← 合并必须同步！
        total += v;
    }
}
```

主线程：起 4 个线程 → 全部 join → 打印 total。
**坑**：`merge` 不加 synchronized → 丢和（总比别人少）。

## 2. 实战套路 2：共享对象要有"管家"

经典银行取款：同一个「账户对象」被两个人（两个线程）同时取钱。

```java
class Account {
    private int balance;
    public Account(int b) { balance = b; }

    public synchronized void withdraw(int m) {   // ← 管家的规矩：一次只进一个人
        if (balance >= m) {
            balance -= m;
        }
    }

    public int getBalance() { return balance; }
}
```

**坑**：withdraw 不加 synchronized → "余额 10000，两人各取 3 次 1000"结果不是 4000，而是 5000/6000（都读到旧余额）——银行不可能允许。

## 3. 实战套路 3：线程安全集合（面试香饽饽）

`ArrayList` **不是线程安全的**：多线程同时 add → 丢数据，甚至 `ConcurrentModificationException`。

**包装一下**：

```java
List<String> list = Collections.synchronizedList(new ArrayList<>());
```

> 记住两个名字（面试）：
> - `Collections.synchronizedList(list)` —— 给普通集合加锁（简单）
> - `CopyOnWriteArrayList` —— 读多写少超高效（写时复制）
> - HashMap 对应 `ConcurrentHashMap`（以后学）

## 4. volatile：可见性（一句话概念）

多线程各自有 CPU 缓存，可能读到**旧值**。`volatile` 保证"一个线程改了，别的线程立刻看得见"（但不保证原子性——它管"看见"，synchronized 管"不被打断"）。

```java
static volatile int progress = 0;   // 下载进度：别的线程随时要读
```

> 记忆：**volatile = 即时可见**；**synchronized = 原子不插队**。各管一摊。

## 5. 多线程调试一句话

- 程序卡住 → 看是不是 join 把自己等死了 / 死锁
- 数字不对 → 十有八九少了个 synchronized
- 打印顺序乱 → 正常，线程本来就无序，判据要用"数量/最终值"
