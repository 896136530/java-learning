## 🔥 必背代码写法总表（按主题分组）

### 一、Java 基础语法与数组
> 大→小必须强转；要小数结果至少一边写小数（Day1）。
```java
int x = (int) 3.99;      // 大→小必强转，得 3
double avg = 7.0 / 2;    // 要小数结果至少一边写小数
```
> 闰年判断：`&&` 优先级高于 `||`（Day2）。
```java
if (year % 4 == 0 && year % 100 != 0 || year % 400 == 0) { }  // 闰年：2024/2000 是，1900 不是
```
> 求平均值：不写 `(double)` 就是整数除法，平均值全错（Day3、Day23 同一条）。
```java
double avg = (double) sum / arr.length;
```
> 判质数：0、1 不是质数（Day4）。
```java
public static boolean isPrime(int n) {
    if (n < 2) return false;
    for (int i = 2; i <= n / 2; i++) if (n % i == 0) return false;
    return true;
}
```
> 有参构造方法：参数与属性同名时必须写 `this`（Day5）。
```java
class Student {
    String name; int age;
    Student(String name, int age) { this.name = name; this.age = age; }  // 同名参数必须 this
}
```
> 封装：校验只写在 setter（唯一入口）（Day6）。
```java
public int getAge() { return age; }
public void setAge(int age) {              // setter 是唯一入口，校验放这里
    if (age < 0 || age > 150) { System.out.println("年龄不合法：" + age); return; }
    this.age = age;
}
```
> 子类构造第一行必须调父类构造（Day7）。
```java
Student(String n, int id) { super(n); this.id = id; }   // 第一行必须调父类构造
```
> 向下转型：调子类独有方法前先 `instanceof`（Day8）。
```java
Dog d = (Dog) a;    // 向下转型，之前必须先 if (a instanceof Dog) 判断
```
- **口诀**：编译看左边，运行看右边（左边类型定能调什么，右边对象定执行谁的实现）。
> 身份用继承，能力用接口（Day9）。
```java
class Bird extends Animal implements Flyable { }   // 身份用继承，能力用接口
```

### 二、集合与字符串
> 重写 `equals` 必须重写 `hashCode`，否则 HashMap 查不到（Day10）。
```java
@Override public boolean equals(Object o) {          // 参数必须是 Object
    if (o instanceof Student) { Student s = (Student) o;
        return name.equals(s.name) && studentId == s.studentId; }
    return false;
}
@Override public int hashCode() { return name.hashCode() + studentId; }
```
> 字符串（Day11）：比内容永远用 `equals`；**方法返回的都是新串，不接住等于白写**；循环里大量拼接用 `StringBuilder`。
```java
if (a.equals(b)) { ... }                  // 忽略大小写 a.equalsIgnoreCase(b)；== 比的是地址
s.length();  s.charAt(0);  s.trim();      // 下标从 0 开始
s.substring(1, 3);   s.substring(3);      // 半开区间 [a,b)；只给起点 = 截到末尾
s.indexOf("ll");     s.contains("ell");   // indexOf 找不到返回 -1
s.split(",");        s.replace("-", "+"); // split → String[]
s = s.toUpperCase();                      // ⭐ 必须接住返回值，否则等于白写
StringBuilder sb = new StringBuilder();   // 循环拼接：append 返回 this，支持链式
sb.append("a").append(1);  String out = sb.toString();
```
> 边遍历边删：必须从后往前（正着删会漏元素）（Day12）。
```java
for (int i = nums.size() - 1; i >= 0; i--) {   // 边遍历边删：必须从后往前
    if (nums.get(i) == target) nums.remove(i);
}
```
> 词频统计：首次出现的键自动从 0 起算（Day13 与 Day22 是同一行）。
```java
map.put(w, map.getOrDefault(w, 0) + 1);  // 词频统计
```
> 两级排序 = `ORDER BY score DESC, name ASC`（Day23）。
```java
int c = Integer.compare(o.score, this.score);   // 负/0/正决定谁在前
return c != 0 ? c : this.name.compareTo(o.name);
```

### 三、异常与文件 IO
> 读文本最省事版：`try (资源)` 自动关流，`readLine()` 读到末尾返 null（Day17）。
```java
try (BufferedReader br = new BufferedReader(new FileReader(p))) { // 自动关流
    while ((line = br.readLine()) != null) { }  // 结尾
} catch (IOException e) { }                     // 不崩
```
> 读文本三件套：不手写 `UTF_8` 就用平台默认（Windows GBK），中文读出乱码（Day24）。
```java
try (BufferedReader br = new BufferedReader(
        new InputStreamReader(new FileInputStream(path), StandardCharsets.UTF_8))) {
    String line;
    while ((line = br.readLine()) != null) { /* 处理 */ }
}
```

### 五、JDBC（连 MySQL）
> SQL 侧：连表 + 分组聚合 + 排序取前 N（Day25）。
```sql
SELECT class_name, COUNT(*), ROUND(AVG(score),2) FROM student JOIN class_info c
ON student.class_name = c.class_name GROUP BY class_name ORDER BY AVG(score) DESC LIMIT 2;
```
> JDBC 入口：先拿到 `Connection`（Day21）。
```java
static Connection getConnection() throws SQLException {
    return DriverManager.getConnection(URL, "root", "root");
}
```
> 增删改都走参数化：`?` 序号从 1 开始，返回 0 行 = WHERE 没匹配（Day26）。
```java
String sql = "UPDATE student SET score = score + ? WHERE class_name = ?"; // 增删改都走它
ps.setInt(1, delta); ps.setString(2, cls);   // ? 序号从 1 开始
int rows = ps.executeUpdate();               // 0 行 = WHERE 没匹配
```
> 「要么全成」的操作前必写；出错全撤，借来的 conn 恢复原样（Day27）。
```java
conn.setAutoCommit(false);                // "要么全成"的操作前必写
try { update(conn, from, -amount); update(conn, to, amount); conn.commit(); }  // 才落库
catch (SQLException e) { conn.rollback(); throw e; }   // 出错全撤，钱"还"回来
finally { conn.setAutoCommit(true); }                  // 借来的 conn 恢复原样
```
> 连接池借壳：真连接留池里，`close` 被换成「还回去」（Day28）。
```java
return (Connection) Proxy.newProxyInstance(Connection.class.getClassLoader(),
        new Class<?>[]{Connection.class}, (proxy, method, args) -> {
            if (method.getName().equals("close")) { idle.add(real); return null; }
            return method.invoke(real, args);
        });
```
- **口诀**：对象相等 ≠ 资源复用（`Proxy` 壳每次借时现做，判复用看池子还剩几个）。

### 七、统一响应与全局异常
> 兜底 handler：任何意料外异常都走这里；必须 `return ResponseEntity`，否则 HTTP 状态码恒为 200（Day31）。
```java
@ExceptionHandler(Exception.class)
public ResponseEntity<Result<Void>> handleOther(Exception e) {
    log.error("系统异常", e);
    return ResponseEntity.status(500)
            .body(Result.fail(ResultCode.SYSTEM_ERROR, "服务器开小差了，请稍后重试"));
}
```
> Service 才是 throw 的地方：主干只写成功路径，状态码由异常类决定，新增错误不用改 handler（Day31）。
```java
if (count <= 0)  throw new ParamException("出库数量必须大于 0，你传的是 " + count);   // 400
Sku sku = getById(id);                                       // 不存在在里面抛 404，复用不重复判空
if (sku.getStock() < count) throw new BizRuleException("库存不足：「" + sku.getTitle() + "」现有 " + sku.getStock() + " 件，你想出库 " + count + " 件"); // 409
```
- **铁律**：日志里详细，返回给外面笼统；`log.error("系统异常", e)` 异常对象必须是**最后一个参数**（写成 String 就丢堆栈）；兜底别用 `Throwable.class`。

### 八、参数校验
> 分组校验：一套注解适配新增/更新，`@Validated(组)` 只在参数级（Day32）。
```java
@Null(message = "新增时不能自己指定 id（由服务器生成）", groups = OnCreate.class)
@NotNull(message = "更新时必须指定 id", groups = OnUpdate.class)
private Long id;

@NotNull(message = "价格不能为空", groups = OnCreate.class)
@Min(value = 0, message = "价格不能小于 0", groups = {OnCreate.class, OnUpdate.class})
private Integer price;

@PostMapping  public Result<Sku> add(@Validated(OnCreate.class) @RequestBody SkuForm form) { ... }
@PutMapping   public Result<Sku> update(@Validated(OnUpdate.class) @RequestBody SkuForm form) { ... }
```
> 自定义校验注解 + 校验器：四元注解 + 三件套缺一不可，空值放行（Day32）。
```java
@Target({ElementType.FIELD, ElementType.PARAMETER})
@Retention(RetentionPolicy.RUNTIME)                  // ⭐ 必须 RUNTIME，写 SOURCE 会静默失效
@Constraint(validatedBy = SkuCodeValidator.class)
public @interface SkuCode {
    String message() default "商品编码格式不对（正确格式：SKU-0001）";
    Class<?>[] groups() default {};                  // 少了它 → 分组校验时被静默跳过
    Class<? extends Payload>[] payload() default {}; // 必须写，几乎永远不用
}

public class SkuCodeValidator implements ConstraintValidator<SkuCode, String> {
    @Override public boolean isValid(String value, ConstraintValidatorContext ctx) {
        if (value == null || value.isBlank()) return true;   // ⭐ 铁律①：空值放行，"必填"归 @NotBlank
        return value.matches("SKU-\\d{4}");                  // ⭐ 铁律③：matches 整串匹配，find 会放过 xSKU-1234
    }
}
```
- **铁律**：① `null`/空白一律 `return true`；② 校验器是**单例**，字段只放只读配置；③ 用 `matches()` 不用 `find()`；④ 带参数的注解必须在 `initialize` 里 `this.max = annotation.max()` 读出来，忘了就完全不生效。

### Day 1 · 变量与 8 种基本类型

**核心知识点**

### Day 3 · 数组与 Scanner 输入

**核心知识点**

### Day 4 · 方法定义、重载与值传递

**核心知识点**
- 格式 `修饰符 返回值类型 方法名(参数列表) { 方法体; return 值; }`；不交回结果写 `void`
- 形参 = 定义时括号里的变量；实参 = 调用时传的具体值
- `return` 两件事：返回结果 + **立即结束方法**
- **重载**：同类中名相同、**参数列表不同**（个数或类型）；⚠️ 与返回值类型、参数名无关
- **值传递**：基本类型传副本 → 方法里改**不影响**外面；数组传地址 → 改元素**外面也变**

**⚠️ 最值得记的坑**
- 实测：`changeNum` 里改 `x=999` 后外面 `num 现在是：10`；`changeArr` 里 `a[0]=999` 后 `arr[0] 现在是：999`
- 非 void 忘写 `return`、类型不一致、`void` 里写 `return 值;` 都编译报错；**方法不能定义在方法里面**

**🔥 必背写法**
```java
public static boolean isPrime(int n) {
    if (n < 2) return false;                                  // 0、1 不是质数
    for (int i = 2; i <= n / 2; i++) if (n % i == 0) return false;
    return true;
}
```

### Day 5 · 类与对象及构造方法

**核心知识点**
- 类 = 图纸/模板；对象 = 造出的实物；**每次 `new` 都是独立对象**
- 类结构 `class 类名 { 数据类型 属性名; 返回值类型 方法名() { } }`，类名大驼峰
- **构造方法**：名字与类名**完全一样**、**无返回值类型**（连 void 都不写）、new 时自动执行填初值
- 不写构造方法 Java 默认送无参构造；自己写了有参构造后无参构造就没了
- **`this`** 指当前对象自己；参数名与属性名**同名时必须写** `this.name = name`
- 属性默认值：数字→0、boolean→false、引用类型→null；不 new 就用 → `NullPointerException`

**⚠️ 最值得记的坑**
- `public class` 类名必须和文件名一致；一个 `.java` 只能有一个 `public class`
- 漏写 `this` → `name = name` 是参数赋给自己，**属性永远 null / 0**；构造方法名写错、忘写 `new` → 编译报错

**🔥 必背写法**
```java
class Student {
    String name; int age;
    Student(String name, int age) { this.name = name; this.age = age; }  // 同名参数必须 this
}
```

### Day 6 · 封装：private + getter/setter

**核心知识点**
- 封装 = 属性 `private` + 公开 `getter/setter` 读写，**校验写在 setter 里**（唯一入口）
- 加 `private` 后 main 里 `s.age = 18` **直接编译报错**，这是第一道墙
- 命名：`getName()` / `setAge()`（`get`/`set` + 属性名首字母大写）；`boolean` 的 getter 用 `is`（`isVip()`）
- setter 校验样板：`if (age < 0 || age > 150) { 提示; return; } this.age = age;`
- 标准样板 = private 属性 + 构造方法 + getter/setter；只写 getter 不写 setter → 属性只读
- 四好处（面试常问）：安全、可控（改规则只改一处）、隐藏细节、继承/多态的基础

**⚠️ 最值得记的坑**
- 忘写 `private` → 封装等于没做
- setter 里 `name = name` → 自己给自己赋值，属性没变，必须 `this.name = name`

**🔥 必背写法**
```java
public int getAge() { return age; }
public void setAge(int age) {              // setter 是唯一入口，校验放这里
    if (age < 0 || age > 150) { System.out.println("年龄不合法：" + age); return; }
    this.age = age;
}
```

### Day 7 · 继承：extends / super / 重写

**核心知识点**
- `extends` 单继承（一个父类）；所有类都继承 `Object`
- 权限宽度 `public`>`protected`>默认>`private`；`protected` 专给继承用
- `private` 成员子类不能直接访问，只能经父类 public 方法用
- `super(参数)` 调父类构造，必须在子类构造**第一行**；不写则自动调无参 `super()`
- `super.方法()` 调父类方法；`@Override` 重写：名/参/返回值全同，只换实现
- 重写 Override（父子类间，参数相同）≠ 重载 Overload（同类中，参数不同）

**⚠️ 最值得记的坑**
- 父类无无参构造 + 子类第一行没写 `super(参数)` → 编译报错
- `super()` 必须第一行，与 `this()` 不能同用；名/参/返回值不同就不是重写

**🔥 必背写法**
```java
Student(String n, int id) { super(n); this.id = id; }   // 第一行必须调父类构造
```

### Day 8 · 多态：向上转型与动态绑定

**核心知识点**
- 多态 = 同一调用，不同对象不同表现
- 三要素缺一不可：继承 + 重写 + 父类引用指向子类对象（向上转型）
- 口诀 **编译看左边，运行看右边**：左边类型定能调什么，右边对象定执行谁的实现
- 属性与静态方法**不参与多态**，都看左边（`a.name` 取父类的值）
- 向下转型 `(Dog) a` 才能调子类独有方法，先 `instanceof` 判断
- 好处：多态参数 / 多态数组写一次通吃，加新子类不改老代码（开闭原则雏形）

**⚠️ 最值得记的坑**
- 向上转型后调子类独有方法（`a.bark()`）→ 编译报错，右边真是 Dog 也不行
- 跳过 `instanceof` 直接下转型且实际类型不符 → 运行时 `ClassCastException`

**🔥 必背写法**
```java
Dog d = (Dog) a;    // 向下转型，之前必须先 if (a instanceof Dog) 判断
```

### Day 9 · 抽象类与接口：多态的进阶形态

**核心知识点**
- `abstract void eat();` 只声明无方法体；含抽象方法的类必须 `abstract class`，且不能 new
- 抽象类可有属性、普通方法、构造方法；子类必须实现全部抽象方法
- 接口方法自动 `public abstract`，**实现必须写 `public`**；接口属性只能常量、无构造方法
- 只能 extends 一个父类，但可 implements 多个接口（弥补单继承）
- 抽象类管身份（is-a），接口管能力（can-do）；开发优先用接口
- 接口多态：`Flyable f = new Bird(...)`；照样编译看左边、运行看右边

**⚠️ 最值得记的坑**
- 实现接口漏写 `public` → 编译报错（不允许降级访问权限）
- `abstract void eat() {}`（带大括号）是错的；`new` 抽象类/接口都编译报错

**🔥 必背写法**
```java
class Bird extends Animal implements Flyable { }   // 身份用继承，能力用接口
```

### Day 10 · Object 类：toString / equals / hashCode

**核心知识点**
- `toString()` 默认 `类名@16进制`；重写后 `println(对象)` 自动调它，须 `public` 且返回 `String`
- `==` 比地址；`equals()` 默认也比地址，重写后才比内容
- 字面量共用常量池（`==` true）；`new String(...)` 地址不同（`==` false、`equals` true）
- 重写 equals 三件套：参数写 `Object` → `instanceof` 判类型 → 下转型逐项比内容
- equals 相等的两对象 hashCode **必须**相等（反之不要求）；项目用 `Objects.hash(...)`
- `getClass()` = 运行时真实类型；`instanceof` 沿继承链向上 true

**⚠️ 最值得记的坑**
- 参数写成 `equals(Student o)` 是**重载**，Java 不认
- 重写 equals 却不重写 hashCode → HashMap（Day 13）出诡异 bug
- 实测：`a==b` true、`a==c` false、`a.equals(c)` true

### Day 11 · String：不可变与常用方法

**核心知识点**

**核心知识点**

- 实体类必须 `@Override toString()`，否则打印 `Student@1b6d3586`；别当 SQL 参数
- `RowMapper.mapRow(rs)`：结果集一行 → 一个 `Student`，唯一出口只写一次
- 事务：`setAutoCommit(false)` → 业务 SQL → `commit()`；出错 `catch` 里 `rollback()`，`finally` 里 `setAutoCommit(true)` 恢复借来的 conn
- 注定失败的校验（余额不足/账户不存在）写在 `setAutoCommit(false)` 之前；失败三风格：抛 `SQLException`（最推荐）/ 字符串 / boolean
- 批量 `ps.addBatch()` 攒清单 → `int[] res = ps.executeBatch()` 打包一趟（1000 行逐条 = 1000 次往返）；列表查不到返空 List 不返 `null`
- ACID：原子性（全或无）、一致性、隔离性、持久性；`ensureAccount` 先查再插才幂等

**⚠️ 最值得记的坑**
- 忘 `commit()` → 数据一点没变（像"没执行"）；`catch` 不 `rollback()` → 连接挂未提交事务，别人看到脏数据
- **负数金额不校验** → `balance - (-50)` 变加钱、凭空造钱（对账 3000 → 3050，原文标注事故级 bug）
- `executeBatch()` 返 **`int[]`**（`return res.length` 是"几条结果"不是"插了几行"）；空 List 安全（返空数组累加 0）

**🔥 必背写法**
```java
conn.setAutoCommit(false);                // "要么全成"的操作前必写
try { update(conn, from, -amount); update(conn, to, amount); conn.commit(); }  // 才落库
catch (SQLException e) { conn.rollback(); throw e; }   // 出错全撤，钱"还"回来
finally { conn.setAutoCommit(true); }                  // 借来的 conn 恢复原样
```

### Day 28 · DAO 收口、隔离级别与连接池

**核心知识点**
- DAO 三规矩：只返回数据/影响行数不 `println`；查不到返回 `null`/空 `List` 不抛异常；`throws SQLException` 外抛
- `executeUpdate()` 返回值就是结果：`1` 改到一行、`0` 没改到（人不存在/条件不匹配）、`>1` 改多行；删失败靠 `if (deleteById(conn,id) == 0)`；新自增 id = 同连接 `SELECT LAST_INSERT_ID()`
- 聚合下推：`COUNT(*)`→`rs.getInt(1)`、`AVG`→`rs.getDouble(1)`、`MAX/MIN`、`ORDER BY ... LIMIT ?`；`getXxx(1)` 的 1 是**第几列（从 1 起）**，`AVG` 返回 DOUBLE
- 顺序只在 `List` 和 `LinkedHashMap` 里保住，`HashMap` 按哈希存键会打乱
- 隔离级别（值 1/2/4/8）：`READ UNCOMMITTED`(1) 全防不住；`READ COMMITTED`(2) 防脏读、Oracle/PG 默认；`REPEATABLE READ`(4) 防脏读+不可重复读、**MySQL 默认**；`SERIALIZABLE`(8) 全防最慢
- 三个读：脏读=读到别人**未提交**；不可重复读=同事务两次读**同一行**值变了；幻读=同事务两次查**一批行**行数变了
- `conn.getTransactionIsolation()` 看档、`setTransactionIsolation(Connection.TRANSACTION_READ_COMMITTED)` 改档；悲观锁 `SELECT ... FOR UPDATE`；乐观锁 = 带 `version` 条件的 UPDATE，返回 0 = 被抢先
- 连接池：`DriverManager.getConnection` 每次都要 TCP+握手+认证，1000 请求=1000 连接打爆 MySQL；池子固定 N 个循环用（HikariCP/Druid），配 `maximumPoolSize`/`minimumIdle`/`connectionTimeout`
- 池子的"壳"：`Proxy.newProxyInstance` 只拦 `close` 改成放回空闲列表，其余 `method.invoke(real, args)` 转发真连接——HikariCP/Druid 的核心把戏
- 分页 `LIMIT ? OFFSET ?`，`offset = (pageNo - 1) * pageSize`；必须带 `ORDER BY`，超范围返回空 List

**⚠️ 最值得记的坑**
- 中文不能当排序键：`ORDER BY COUNT(*) DESC, class_name` 实测 **一班=3、三班=2、二班=2**（中文按字符编码排，"三" < "二"）；改 `MIN(id)` 才对
- 包壳后 `c5 == c2`、`equals` **全是 false**（壳每次借时现做）；判复用看**池子还剩几个**（借 3→剩 0；还 1→剩 1）——**对象相等 ≠ 资源复用**
- 不包 `Proxy` 直接 `return real;`：`close()` 真关了连接、**池子数不增加**，再执行 SQL 报 **`No operations allowed after connection closed.`**；借第 4 个应得 `null`

**🔥 必背写法**
```java
// 连接池借壳：真连接留池里，close 被换成"还回去"
return (Connection) Proxy.newProxyInstance(Connection.class.getClassLoader(),
        new Class<?>[]{Connection.class}, (proxy, method, args) -> {
            if (method.getName().equals("close")) { idle.add(real); return null; }
            return method.invoke(real, args);
        });
```

- 四档隔离级别各防住哪种"读"？MySQL 默认哪一档、值多少？
- 为什么 `countByClass` 必须用 `LinkedHashMap`？怎么证明连接被复用了？

### Day 29 · Maven：坐标、生命周期与胖瘦 jar

### Day 31 · 全局异常处理 + 统一响应

**核心知识点**
- `@RestControllerAdvice` = `@ControllerAdvice`（给所有 Controller 加公共逻辑）+ `@ResponseBody`；错误处理全项目只写一处，取代每个接口的 try-catch（横切关注点抽离）
- `@ExceptionHandler(X.class)` 按异常**类型**分派；多个能匹配时选继承链上**最近的**（`ParamException` 优先于 `BaseException`，最后是 `Exception` 兜底），所以顺序「先具体、后兜底」
- handler 必须是 `public`；兜底用 `@ExceptionHandler(Exception.class)`，别用 `Throwable.class`（太宽，会吞掉 Spring 内部异常）
- 必须 `return ResponseEntity.status(e.getHttp()).body(Result.fail(...))` —— 直接 `return Result` 的话 HTTP 状态码恒为 200，等于退回 Day30 的坑
- 异常体系：`BaseException extends RuntimeException` 存 `code`（业务码）+ `http`（状态码），message 交给父类；子类只有一行 `super(...)`：`ApplicationException` 通用、`ParamException` 400、`ResourceNotFoundException` 404、`BizRuleException` 409
- 业务异常继承 `RuntimeException`（非受检）才能穿透多层调用直达 advice；受检 `Exception` 会导致整条调用链都要 `throws`/try-catch
- 统一信封 `Result<T>`：`{code,message,data,fieldErrors}`；`Result.ok()` / `Result.fail()` / `Result.failFields()`
- HTTP 状态码给浏览器/网关/监控看（粗粒度），业务码 `code` 给前端业务代码看（细粒度，如 40401 用户不存在 / 40402 订单不存在）——两者都要有
- 400 = 请求本身不合法（改请求就过）；404 = 东西不存在（改 ID 就过）；409 = 请求合法但违反业务规则（**重试没用**，得先改变现实）；500 = 我们的 bug
- `@Valid @RequestBody` + `@NotBlank/@NotNull/@Min` 失败抛 `MethodArgumentNotValidException`，用 `e.getBindingResult().getFieldErrors()` 取 `fe.getField()`/`fe.getDefaultMessage()` 收成 `fieldErrors`；SpringBoot 3 用 `jakarta.validation`（老教程 `javax.validation` 完全不生效且不报错）
- Service 才是 throw 的地方：Controller 不收业务规则、不 try-catch；`getById` 内部抛 404 供复用，主干只写成功路径
- 日志两档：业务异常（预期内）`log.warn("…code={}, http={}, message={}", …)` **不打堆栈**；系统异常 `log.error("系统异常", e)` 异常对象当**最后一个参数**自动带完整堆栈

**⚠️ 最值得记的坑**
- 改前的真机现象：`GET /tasks/999`（`orElse(null)` 写法）返回 **HTTP 200 + 响应体 0 字节**；前端 `r.ok` 为 true，`await r.json()` 直接崩，只能靠猜是哪一种错 —— 这就是必须 `throw ResourceNotFoundException` 的原因
- 默认错误响应会**泄露内部实现**：实测 `GET /sku/boom` → 500 + `Cannot invoke "com.xiaoming.day31.sku.Sku.getTitle()" because "sku" is null`，包名/类名/方法名全暴露；若是 SQL/反射异常还会泄露表名、字段名、SQL 语句（安全漏洞）。兜底 handler **绝不能**把 `e.getMessage()` 返回前端 → 「日志里详细，返回给外面笼统」
- 丢堆栈的两种隐蔽写法：`log.error("系统异常：" + e.getMessage())` 和 `log.error("系统异常", e.getMessage())` 都只传了 String，堆栈丢失，线上没法排查；必须是 `log.error("系统异常", e)`

**🔥 必背写法**
```java
// 兜底 handler：任何意料外异常都走这里（堆栈只进日志，外面只给笼统话）
@ExceptionHandler(Exception.class)
public ResponseEntity<Result<Void>> handleOther(Exception e) {
    log.error("系统异常", e);
    return ResponseEntity.status(500)
            .body(Result.fail(ResultCode.SYSTEM_ERROR, "服务器开小差了，请稍后重试"));
}
```

### Day 32 · 分组校验 + 自定义校验注解

**核心知识点**
- 分组校验 3 步：① 用**空接口**当组名（标记接口，`OnCreate`/`OnUpdate`；写 `OnCreate.class` 拼错编译期就红，比字符串安全）② 注解上 `groups = OnCreate.class`，一个约束管两场景写 `groups = {OnCreate.class, OnUpdate.class}`；**不写 `groups` 的注解属于默认组 `Default`** ③ Controller 上 `@Validated(OnCreate.class)` 指定这次跑哪组
- `@Valid`（`jakarta.validation.Valid`，Jakarta 标准，**没有 `groups` 属性**，写 `groups` 编译报错）vs `@Validated`（`org.springframework.validation.annotation.Validated`，Spring 增强：有 `value()` 指定组、能贴**类上**开启方法参数校验）
- 自定义注解四元注解：`@Target({FIELD, PARAMETER})`、`@Retention(RetentionPolicy.RUNTIME)`（⭐必须 RUNTIME，靠反射读）、`@Documented`、`@Constraint(validatedBy = SkuCodeValidator.class)`（把注解和干活的类绑起来）
- 「三件套」少一个都不行：`message()`（提示语，原样进 fieldErrors）、`groups() default {}`（缺了 → 分组校验时**被静默跳过**）、`payload() default {}`（必须写但几乎不用，规范留的扩展位）
- 带参数的注解：`int max() default 1000;` + `String message() default "库存不能超过 {max}"`，`{max}` 由 Bean Validation 框架自动取属性值替换（一句模板适配所有上限）
- `implements ConstraintValidator<注解, 字段类型>`（泛型别反）：`initialize(A annotation)` 启动只调一次，读注解参数存成字段；`isValid(T value, Context ctx)` 每个值调一次，`true` 通过、`false` 报 message
- 三条铁律：① `null`/空白一律 `return true`（「必填」是 `@NotNull`/`@NotBlank` 的职责，否则同一字段两条红字）② 校验器是**单例**，字段只放只读配置（`max`），放请求数据会串数据（Day18/19 的并发问题）③ 用 `matches()`（整串匹配）而非 `find()`（部分匹配，会放过 `xSKU-1234`）
- 两条校验路径：**请求体字段**由 SpringMVC 转 JSON 时校验，参数上 `@Valid`/`@Validated` 开启，抛 `MethodArgumentNotValidException`，`getBindingResult().getFieldErrors()`，字段名干净（`title`）；**方法参数**（`?limit=0`）由 Spring AOP `MethodValidationInterceptor` 拦，靠**类上 `@Validated`** 开启，抛 `ConstraintViolationException`，`getConstraintViolations()`，`getPropertyPath()` 形如 `search.limit`（要截断成 `limit`）
- 校验三层：① 注解（只看当前字段，400）② Service 手写 `if`/查库（编码重复、库存够不够，409）③ 数据库约束（唯一索引，走不到，有问题就是 500，Day35 讲）
- 「编码是否重复」写不成注解：注解**无状态**，只能拿到贴在自己身上的字段值，拿不到别的数据；要查数据 = 要有状态 = 只能 Service

**⚠️ 最值得记的坑**
- **分组静默失效（今天最大的坑，两个方向）**：
  - **组接口的声明位置**：曾把 `OnCreate`/`OnUpdate` 声明在 `SkuForm` **类内部**（`SkuForm.OnCreate`），而 Controller 上用的是 `valid.OnCreate`。组名的身份是 **Class 对象本身**，两个完全不同的 Class → Controller 指定的组谁也匹配不上 → **注解层全部静默失效**：实测接口照样返回 **200**，一条约束都没跑，**报错、警告、异常全都没有**，整天的题就死在这一行。组接口只该有**一份**，放 `valid` 包里统一 import。排查口诀：只要「该 400 的返回了 200」，先按住 Ctrl 点进 Controller 上的组和注解里的组，看跳的是不是同一个文件
  - **Controller 指定了组、注解忘了写 `groups`**：`Default` 组不再参与 → 没写 groups 的注解一条都不跑。实测：`POST /sku` 带 `id:99`（本该 400）→ **200 越权通过**（能覆盖别人数据）；`code:"abc"` → **200 脏数据入库**；`POST /sku {}` → 400 但 `message="书名不能为空"`、**fieldErrors=null**（注解层没跑，是 Service 手写校验兜住的，前端拿不到 fieldErrors 就标不了红字）；`PUT /sku {"price":99}` → **404「SKU 不存在：id=null」**（驴唇不对马嘴）
  - 反向也一样：注解加了 `groups`、Controller 没改 → 指定的组里没有这些约束，该拦的没拦。**要写就写全，写完必测反例**
- **注解参数不会自己生效**：交付版 `MaxStockValidator.initialize` 写成 `this.max = 1000`（写死）→ 实测 `stock:800` 返回 **200**（800 ≤ 1000 放过）；正确写 `this.max = annotation.max()`（=500）才 **400「库存不能超过 500」**，`stock:500` 边界因 `<=` 放过（写成 `<` 会把正好等于上限判错）。忘了读 → 编译不报错、启动不报错、校验「好像在工作」——又一个静默失效
- **`@RequestParam` 上的 `@Min` 失败返回 500**：实测 `GET /sku/search?limit=0` → **500「服务器开小差了，请稍后重试」**，日志真凶 `ConstraintViolationException: search.limit: limit 至少是 1`，栈里有 `MethodValidationInterceptor.invoke` 和 `SkuController$$SpringCGLIB$$0.search`（类上 `@Validated` 让 Spring 给 Controller 生成了代理）。Day31 只接了 `MethodArgumentNotValidException`，没接它就掉进兜底 → 补一个 handler 后变 **400** `fieldErrors:{limit:"limit 至少是 1"}`；`limit=99` → 400「limit 最多是 50」；`limit=50` 边界 200。规律：**凡是 ERROR+堆栈、但用户经常能触发的异常，都该有专属 handler**

### Day 33 · 拦截器与过滤器：顺序、注入与清理

**核心知识点**
- **Filter 三方法生命周期**：`init(FilterConfig)` 启动 1 次、`doFilter(ServletRequest,ServletResponse,FilterChain)` 每请求 1 次、`destroy()` 应用正常关闭 1 次（⚠️ `destroy()` 日志**未实测** —— 验证时是强制杀进程，只有 Ctrl+C 优雅关闭才打印）。
- **Filter 两条铁律**：① `chain.doFilter(request,response)` 是命根子，漏写 = 后面全不执行、**日志里一行错都没有**；② 签名只能用 `ServletRequest`（参数类型不允许变窄），要 URI / 请求头 / 状态码就 `(HttpServletRequest) request` 强转。
- **八步顺序**：Filter 前置 → DispatcherServlet 找 handler → `preHandle` → Controller(→Service) → `postHandle` → 视图渲染（REST 无）→ `afterCompletion` → Filter 后置。多拦截器 `preHandle` 正序、`postHandle`/`afterCompletion` 倒序；多过滤器按 `setOrder` 数字小→大进、反过来退（**先进后出，像穿衣服**）。
- **拦截器三方法分工**：`preHandle` 返回 boolean（false → 后面的拦截器 + Controller + `postHandle` 全不执行，但**已通过**的拦截器 `afterCompletion` 照样执行）；`postHandle` 能改 `ModelAndView`；`afterCompletion` 收尾。
- **`preHandle` 第三参 `handler` 实测类型**：`GET /sku` → `HandlerMethod`（能读 Controller 类 / 方法 / 方法上的注解，过滤器做不到）；`GET /abc` → `ResourceHttpRequestHandler`。
- **`FilterRegistrationBean` 注册**：`new FilterRegistrationBean<>(new OrderProbeFilter(recorder))` + `addUrlPatterns("/*")` + `setName(...)` + `setOrder(1)` —— **数字越小越靠外**；另一种 `@WebFilter` + 启动类 `@ServletComponentScan` 顺序不好控、常常注入不到依赖。
- **拦截器注册**：`WebMvcConfigurer.addInterceptors(InterceptorRegistry)` → `addInterceptor(bean).addPathPatterns("/**").excludePathPatterns("/login","/public/**","/trace/**")`。
- **路径通配符**：`/sku` 只匹配这一条（`/sku/1`、`/sku/search` **全都不拦**）；`/sku/*` 一层；`/sku/**` 所有层级；`/**` 全部（含静态资源、404）。白名单路径**回 Controller 抄**，别凭记忆写。
- **`@Autowired` 为 null 的根因**：拦截器是 `new` 出来的 → 不是 Spring Bean → 字段注入无效 → 用时 NPE。正法：`@Component` + 构造器注入 + `final` 字段（忘传**编译期就红**），注册处也构造器注入。
- **注册方式不对称**：Filter 类写了 `@Component` 会被**自动注册一遍**（再加 `FilterRegistrationBean` = 每请求跑两次）；拦截器写了 `@Component` **不会自动生效**，仍须 `registry.addInterceptor(...)`。
- **`ThreadLocal` 清理位置**：`CurrentUser`（`AuthInterceptor.preHandle` set）→ 清在 `AuthInterceptor.afterCompletion`；`TraceRecorder`（过滤器 + 拦截器都写）→ 清在 **order=1 最外层过滤器的最后一行**。`HOLDER.set/get/remove`，Tomcat 一个请求一个线程、线程池复用。
- **401 三件套**：`setStatus(401)` + `setContentType("application/json;charset=UTF-8")` + `objectMapper.writeValueAsString(Result.fail(ResultCode.UNAUTHORIZED,msg))`；实测响应体 83 字符 / 117 字节。
- **404 也走拦截器**：`/abc` 落到静态资源处理器 → `afterCompletion` 照样执行；不带 token 时实测 **401**（不是 404）→ `preHandle` 里用 `handler` 前必须 `instanceof HandlerMethod`。
- **拦截器抛的异常会被统一处理器接住**：`preHandle` 在 `DispatcherServlet.doDispatch()` 的 try 块里，`/trace/throw` → 409 + 统一 JSON（本机 spring-webmvc 6.1.14）。

**⚠️ 最值得记的坑**
- ⭐⭐ **`recorder.clear()` 写在 `afterCompletion` 里清不干净**：`afterCompletion` 不是最后一句代码 —— `CostFilter`/`OrderProbeFilter` 在 `chain.doFilter` 之后**还会记 3 行**（`耗时 95 ms → Filter② 退出 → Filter① 退出`），下一个同线程请求就带上这 3 行残留。交付版实测 `currentRequest` 行数 **3→9→16→21→27**、`lastCompleted.steps` **4→10→16→22→28**（每请求 +6 行）；**必须清在 order=1 最外层过滤器的最后一行**，改后 `currentRequest` 恒为 3 行。口诀：**谁最后动这份数据，谁负责清理**。
- **拦截器抛的异常确实会被 `@RestControllerAdvice` 接住**（反常识）：`/trace/throw` → **409** + 统一 JSON；老博客说"不会"是 Spring 3/4 的结论（当时 `applyPreHandle` 在 try 块外）。
- **`afterCompletion` 的第 4 参 `ex` 一直是 null**：异常已被 `GlobalExceptionHandler` 消化，`triggerAfterCompletion(request,response,null)`。实测 `/sku/boom`(500) 与 `/trace/throw`(409) 轨迹都写"异常：无"→ 复盘异常只能看日志（`handleOther` 里那句 `log.error` 是唯一堆栈出口）。
- **`new AuthInterceptor()` + `@Autowired`**：带**正确** token 访问 `GET /sku` 也 **500**，NPE 原文 `because "this.tokenStore" is null`；401 只 `setStatus` 不写响应体 → 客户端拿到 **0 字节**，前端 `res.json()` 直接崩。
- **`addPathPatterns("/sku")` 写窄 = 漏防一片**：`GET /sku/1` 无 token **200 越权**、`POST /sku/outbound?id=2&count=1` 无 token **200 且真把库存 3 改成 2**；反例 `PUT /sku` 无 token 恰好 401（路径**正好**等于 `/sku`）；改成 `/**` 后 `/favicon.ico` 也被拦成 **401**（真实项目要把静态资源加进白名单）。

```java
// ① 拦截器：@Component + 构造器注入（注册处注入，绝不 new）+ 401 的 JSON 信封
@Component
public class AuthInterceptor implements HandlerInterceptor {
    public static final String TOKEN_HEADER = "X-Token";
    private final TokenStore tokenStore;                    // final：漏传编译期就红
    public AuthInterceptor(TokenStore tokenStore) { this.tokenStore = tokenStore; }

    @Override
    public boolean preHandle(HttpServletRequest req, HttpServletResponse resp, Object handler) throws IOException {
        if (handler instanceof HandlerMethod) { /* 想读方法上的注解必须先判断：/abc 时它是 ResourceHttpRequestHandler */ }
        String token = req.getHeader(TOKEN_HEADER);
        if (token == null || token.isBlank()) {
            resp.setStatus(401);                                        // ① 状态码（401=你是谁，403=知道你是谁但不行）
            resp.setContentType("application/json;charset=UTF-8");      // ② charset 忘了 → 中文乱码
            Result<Void> body = Result.fail(ResultCode.UNAUTHORIZED, "未登录或登录已过期，请在请求头带上 X-Token");
            resp.getWriter().write(objectMapper.writeValueAsString(body));  // ③ 用 Jackson，别手拼字符串
            return false;                       // false = 中断：Controller 和 postHandle 都不执行
        }
        return true;                            // true = 放行
    }
    @Override public void postHandle(HttpServletRequest r, HttpServletResponse p, Object h, ModelAndView mv) { }
    // REST 里 modelAndView 恒为 null，但方法确实会执行
    @Override public void afterCompletion(HttpServletRequest r, HttpServletResponse p, Object h, Exception ex) {
        CurrentUser.clear();                    // 拦截器之后没人再动它 → 清在这里就够
    }
}

// ② Filter：FilterRegistrationBean 控顺序（Filter 类本身别写 @Component，否则每请求跑两次）
@Bean
public FilterRegistrationBean<OrderProbeFilter> orderProbeFilter(TraceRecorder recorder) {
    FilterRegistrationBean<OrderProbeFilter> reg = new FilterRegistrationBean<>(new OrderProbeFilter(recorder));
    reg.addUrlPatterns("/*");
    reg.setName("orderProbeFilter");
    reg.setOrder(1);                        // 数字越小越靠外，也越后退 → 它就是"最后动数据"的那一层
    return reg;
}
public void doFilter(ServletRequest request, ServletResponse response, FilterChain chain) throws IOException, ServletException {
    HttpServletRequest httpRequest = (HttpServletRequest) request;   // 签名不许变窄，只能强转
    chain.doFilter(request, response);                                // 命根子：不写 = 请求死在这（且不报错）
    recorder.record("[Filter① OrderProbe] 退出");
    recorder.clear();                       // ⭐⭐ 整个请求的最后一句代码（写进 afterCompletion 会残留 3 行）
}

// ③ 拦截器注册：从容器注入 Bean，先全拦再开白名单（路径回 Controller 抄）
@Override
public void addInterceptors(InterceptorRegistry registry) {
    registry.addInterceptor(authInterceptor)
            .addPathPatterns("/**")
            .excludePathPatterns("/login", "/public/**", "/trace/**");
    // 漏 /login → 登录接口自己被拦（死循环）；漏 /trace/** → 调试窗口被锁死
}
```

### Day 8 · 多态：向上转型与动态绑定
**🧷 补漏**
- **「重写 vs 重载」对比表**（知识点 §9 原文，`_p2` 只留了一行口诀）：

```java
static void handle(Socket s) {                // 一个连接的完整生命周期
    try {
```

### Python Day 4 · 字典 dict 与集合 set

**核心知识点**
- 建字典 `{"apple": "苹果"}`；查：`d[k]`（键不存在**报 KeyError**）vs `d.get(k)` / `d.get(k, "默认值")`（不崩）

- 遍历：`for k in d` / `d.keys()` / `d.values()` / `d.items()`（★ 同时拿键和值）
- 词频套路：`d[w] = d.get(w, 0) + 1`；字典是**哈希表**，查是 O(1)，`x in list` 是 O(n)
- set：`set([1,2,2,3])` 自动去重；`add` / `remove`（不存在报错）/ `discard`（不报错）
- 集合运算 `|` 并、`&` 交、`-` 差、`^` 对称差；`x in s` 是 O(1)

```python
# 词频统计（一行计数，首次出现自动从 0 起算）
```

### Python Day 6 · 二维列表与矩阵操作

**核心知识点**
- 二维列表 = 列表的列表，`m[行][列]`（**先行后列**）
- 读矩阵标准姿势：`n, m = map(int, input().split())` 后循环 `matrix.append(list(map(int, input().split())))`
- 一行版：`matrix = [list(map(int, input().split())) for _ in range(n)]`
- 遍历三姿势：`for row in matrix: for x in row`；要下标用 `range(n)` / `range(m)`；只取某列要固定列号扫所有行

### Python Day 7 · 排序与自定义 key 排序

**核心知识点**
- `a.sort()` 原地改自己、**返回 None**；`sorted(a)` 返回新列表、原数据不动
- 默认排序规则：数字按大小；字符串按 **Unicode 码点**（`A < Z < a < z`，中文**不是拼音**）；元组/列表逐项比
- `key=`：排序时按 `key(元素)` 的结果比大小，元素本身不动（`key=len` / `key=str.lower` / `key=abs`）
- `lambda 参数: 返回值` = 一行版临时函数，专门喂给 `key`
- ⭐ 多关键字：key 返回元组，先比第 1 项、相同再比第 2 项；**混合方向用负号**：`key=lambda x: (-x[1], x[0])`
- 稳定排序：比不出大小的保持原顺序，可"先按次要关键字排、再按主要关键字排"
- 取前 k 名：`sorted(数据, key=..., reverse=True)[:k]`

**⚠️ 最值得记的坑**
- `a = a.sort()` → `a` 变成 `None`（要赋值就用 `sorted`）
- `input()` 忘 `map(int)` → 字符串排序，`'10'` 排在 `'9'` 前面
- `reverse=True` 是**全局开关**，会把所有 key 一起反过来；字符串不能取负
- 字典列表排序要写字段名：`key=lambda d: d["score"]`（字典不能用 `x[1]`）

**🔥 必背写法**
```python
# 分数从高到低、同分姓名从小到大（蓝桥"成绩排名"标准 key）
rows.sort(key=lambda x: (-x[1], x[0]))    # x 是 (姓名, 分数) 元组，负号实现降序
```

- 为什么不能写成 `key=lambda x: (x[1], x[0])` 再配 `reverse=True`？

### Python Day 8 · 常用库与内置函数（math / Counter / itertools / bisect）

**核心知识点**
- import 两种写法：`import math` → `math.gcd(a, b)`；`from math import gcd` → `gcd(a, b)`
- `math`：`gcd` / `lcm`(3.9+) / `isqrt`（整数平方根）/ `factorial` / `ceil` / `floor` / `sqrt`（返回**浮点**），`abs` 是内置不用 import
- 判平方数用 `isqrt(n)**2 == n`（`sqrt` 大数有浮点误差）
- `Counter`：一行计数；`c[不存在的键]` 返回 **0**（不再 KeyError）；`most_common(1)[0]` 拿 `(元素, 次数)`；`elements()` 按次数展开；`sum(c.values())` 是总数
- Counter 运算：`a - b` 只在 a 多的、`a & b` 两边都有、`a | b` 取大次数
- `deque`：`append / appendleft / pop / popleft`，`popleft` 是 O(1)（`list.pop(0)` 是 O(n)，队列 BFS 用 deque）
- `itertools`：`permutations / combinations / product / accumulate`——结果是**迭代器，必须套 `list()`**；数据大就爆
- `bisect`：表**必须先排序**；`bisect_left / bisect_right` 返回**下标**；`insort` 插入保持有序
- 内置：`sum / max(可带 key) / min / round / divmod(商和余) / sorted / any / all`
- 输出小数用 `f"{x:.2f}"`（比 `round` 再打印稳）

**⚠️ 最值得记的坑**
- **本机 Python 3.9.13**：`Counter.total()`（3.10+）会 AttributeError → 用 `sum(c.values())`；`math.lcm` 能用
- `round(2.675, 2)` 得 `2.67`（浮点存储）；`permutations` 忘 `list()` 打印出对象；`bisect` 用在没排序的表上结果全错

**🔥 必背写法**
```python
# 计数 + 找出现最多 + 总数（Day8 最值钱的三行）
from collections import Counter
c = Counter("hello")
print(c.most_common(1)[0])     # ('l', 2) —— 元素和次数一起拿
print(sum(c.values()))         # 5 —— 总数，别用 c.total()（需 3.10+）
```

### Python Day 9 · 字符串进阶（切片 / join / ord）

**核心知识点**
- 字符串**不可变**：`s[0] = "H"` 报 TypeError；`replace/upper/strip` 都返回**新串**，必须接住 `s = s.replace(...)`
- 切片 `s[起点:终点:步长]` **左闭右开**；`s[-1]` 倒数第一；`s[::-1]` 反转；`s[::2]` 隔一取一；`s[-2:]` 最后两个
- **切片不报越界**（`s[100:]`→`''`），索引越界才 `IndexError` → 能切片就别索引
- `join`：`''.join(sorted("cba"))`、`" ".join(map(str, nums))`；循环里只 `append`、最后 `join` 一次（循环里 `+` 拼串大数据会超时）
- 方法表：`find` 找不到返 **-1**、`index` 报 ValueError、`rfind`、`count`（**不重叠**）、`replace(a,b,2)`、`startswith/endswith`、`split`、`strip`（`lstrip/rstrip`）、`upper/lower/swapcase`、`isdigit/isalpha/isalnum`
- `ord` / `chr`：背 `'0'=48`、`'A'=65`、`'a'=97`；连续比较 `'a' <= ch <= 'z'`；字母序号 `ord(ch) - ord('a') + 1`
- 回文：`s == s[::-1]`（双指针版先见个面）；升级版先**清洗**再判
- `a + a` 环形技巧：`b in a + a` 判循环移位，**必须先判长度相等**

**⚠️ 最值得记的坑**
- 忘了接返回值（`s.replace(...)` 后 s 没变）；`"aaa".count("aa") == 1` 是不重叠计数
- 清洗（`isalnum` + `lower`）后可能得到**空串**，`'' == ''[::-1]` 是 True → 约定：**空串算回文**
- 旋转匹配不先判长度：`a="ab"`、`b="abab"` 会被 `b in a+a` 误判成 YES

**🔥 必背写法**
```python
# 回文判断（清洗版）：只留字母数字 + 统一小写，再整体反转比较
t = ''.join(ch.lower() for ch in s if ch.isalnum())
print("YES" if t == t[::-1] else "NO")    # 清洗后为空串也输出 YES
```

- `s[10]` 和 `s[10:]` 哪个会报错？

### Python Day 10 · 前缀和与差分（未开始）

> ⚠️ **状态：未开始**——10 个 `.py` 模板（Ex1~Ex6 / Review / 3 道真题）**全部只有注释、没有一行代码**；《练习题》末尾的「观察记录」「复杂度小结」也全部留白。以下知识点来自当日《知识点.md》（已生成），**尚未练习验证**。

**核心知识点**
- 前缀和：`pre[i]` = 前 i 个元素之和，`pre[0] = 0`；区间和 `a[l..r] = pre[r] - pre[l-1]`，单次 **O(1)**
- 为什么要 `pre[0]=0`：`l=1` 时公式就是 `pre[r] - pre[0]`，**多开一个位置换掉一个 if**
- Python 对齐：`pre = [0] + list(accumulate(a))`（手写 `pre[i] = pre[i-1] + a[i-1]` 极易错位）
- 差分：`d[i] = a[i] - a[i-1]`，`a` 是 `d` 的前缀和；区间加 `d[L] += v; d[R+1] -= v`（每次 O(1)），**d 开 `n+2` 格**防越界
- 差分的"覆盖次数"用法：`d[L] += 1; d[R+1] -= 1` 复原后就是"每个位置被几个区间覆盖"
- 二维前缀和：`pre[i][j] = pre[i-1][j] + pre[i][j-1] - pre[i-1][j-1] + mat[i][j]`（补哨兵行/列，下标统一从 1 起）
- 子矩阵和四项容斥：`pre[x2][y2] - pre[x1-1][y2] - pre[x2][y1-1] + pre[x1-1][y1-1]`
- 变种：前缀积 / 前缀最大 / 前缀异或、后缀和（左右两边和）；`pre_max` **不能**相减求区间最值
- 复杂度对比：暴力 10^5×10^5 → 10^10 超时；预处理 O(n) + 每次 O(1) → 秒过
- 选工具口诀：**"查"用前缀和，"改"用差分**；两样都要 → 树状数组/线段树（以后学）
- `sys.stdin.read()` 一次性读入（大数据比逐行 `input()` 快）；别用 `a.insert(0, 0)` 补哨兵（O(n)）

**⚠️ 最值得记的坑**
- `pre` 与 `a` **差一个下标**（`a[i-1]`），写错整体错位；`pre[0] = 0` 忘了，`l = 1` 时结果离谱
- 差分数组没多开格 → `R = n` 时 `d[n+1]` IndexError；二维 `pre` 用 `[[0]*m]*n` 是浅拷贝（Day6 踩过）

**🔥 必背写法**
```python
# 前缀和 + 区间和（第 l 到第 r 个数，O(1)）
from itertools import accumulate
pre = [0] + list(accumulate(a))     # pre[0]=0，pre[i] = 前 i 个之和，不会错位
print(pre[r] - pre[l - 1])

# 差分区间加：只改两个位置，最后前缀和复原
d = [0] * (n + 2)                  # 多开格，R = n 时 d[R+1] 不越界
d[L] += v
d[R + 1] -= v
```

- `pre[0] = 0` 为什么不是装饰，而是公式的一部分？
- 差分数组为什么要开 `n + 2` 格？不开会怎样？
- 题目说"多次查询区间和"和"多次把 L 到 R 加上 v"，分别用哪个工具？
